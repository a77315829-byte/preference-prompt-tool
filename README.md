## 본인 기여

선택 기반 프롬프트 생성 도구를 기획하고, 선호를 반영하는 구조와 평가 방식 개선을 맡았습니다. 기능 구현과 품질 개선 실험을 구분해 기록했습니다.

## 기술 구조

| 구성 | 구현 내용 |
|---|---|
| 쌍대 비교 기반 추정 | 한 번에 한 속성만 다른 후보를 비교하고 Bradley-Terry 방식으로 효용을 갱신합니다. 무승부와 선호가 정해지지 않은 축도 구분하며, 내부 확신도는 사용자 선호의 확률로 표시하지 않습니다. |
| 비교 흐름과 확장 구조 | 불확실한 축을 우선 비교하고 사람용 화면에서는 중복 질문을 피합니다. 최대 8회 이내로 프롬프트를 조립하며 도메인 속성·검사 함수와 공통 엔진을 분리했습니다. |
| 평가 피드백과 GEPA | 속성별 검사 점수와 자연어 위반 피드백을 평가 함수로 만듭니다. GEPA 최적화는 선택 단계이며, 기본 프롬프트 조립 실험의 성과와 섞어 해석하지 않습니다. |
| 측정과 비교군 개선 | 표현 겹침만으로 요약을 판단하지 않고 길이·추출성을 함께 점검했습니다. 선호를 배운 문서와 평가 문서를 나누고 일반 지침 및 정답 선호를 아는 강한 비교군과 비교했습니다. |

## 구현 결과와 확인 범위

프롬프트 생성·재사용 흐름과 React UI를 구현했습니다. Qwen의 30개 페르소나 비교에서 강한 비교군 대비 ROUGE-L 평균차 +0.0047, p=0.3616으로 유의한 우위는 확인하지 못했습니다.

언어모델 자체를 학습하는 프로젝트가 아닙니다. 페르소나 기반 실험이며 실제 사용자 만족도 향상이나 비교군과의 동등성을 입증한 결과로 해석하지 않습니다.

### 코딩 프롬프트 검증 (사전등록 3회)

결과를 보기 전에 기준을 커밋하고 새 보류 과제에서 판정했습니다. 한 번에 프로필 4개 × 과제 5개 × 3회 = 60단위이며, 괄호는 95% 부트스트랩 구간입니다. 기능 통과율은 타입 검사·빌드·과제별 고정 시나리오를 모두 통과한 비율입니다.

| 질문 | 결과 | 판정 |
|---|---|---|
| 선택으로 조립한 프롬프트가 목표 선호를 따르게 하는가 | 축 검사 통과율 +0.2889 [0.2222, 0.3611] · +0.2778 [0.2222, 0.3333] · +0.2333 [0.1667, 0.3] (1·2·3차, 프롬프트 없음 대비) | 작동 |
| AI가 근거 있는 선호 줄을 다시 쓰면 더 따르는가 | 축 검사 통과율 -0.0389 [-0.0944, 0.0167] · +0.0167 [-0.0444, 0.0722] (1·2차, 기본 조립본 대비) | 기준 미충족, 기능은 꺼 둠 |
| 요청 대조 규칙 한 줄이 기능 통과율을 높이는가 | -0.0167 [-0.1, 0.0667] (3차, 기본 조립본 대비) | 기준 미충족 |

판정 밖에서, 기본 조립본은 프롬프트 없음보다 기능 통과율이 낮았습니다: -0.1667 [-0.3, -0.0333] (2차, 실행 검사 수정 후 재채점) · -0.0667 [-0.1333, -0.0167] (3차). 1차 과제에서는 -0.0167 [-0.1333, 0.1]로 확인되지 않았습니다. 선호를 반영하는 대가로 요청 동작을 덜 지킬 수 있다는 뜻이며, 원인은 아직 가리지 못했습니다. 가상 사용자와 정적 검사·고정 시나리오 기준이라 사용자 만족이나 임의 입력의 기능 동일성을 입증하지 않습니다. 기록: [1차](docs/personalized_prompt_preregistration.md) · [2차](docs/personalized_prompt_preregistration_v2.md) · [3차](docs/rule_based_function_preregistration.md)
