# 현재 TypeScript/React 지침의 세 조건 비교

2026-11-12, `microstone`. 현재 제품의 **AI 답변 방식 설정**이 실제로 내보내는 네 항목 지침을 대상으로 한다. 별도 `coding_contract_v1` 프로토타입이나 **React 코드 스타일 비교**의 세 축을 대신 검증한 결과가 아니다. 유료 모델 API·GEPA·새 패키지 설치 없이 독립 Codex 보조 에이전트로 수행했다. Codex 사용량은 소비됐다.

## 고정한 비교

| 조건 | 전달한 내용 |
|---|---|
| 일반 요청 | 실제 `general_prompt`의 환경·공통 규칙과 완전한 기능 요구. 작성 선호만 제외 |
| 강한 수동 지침 | 같은 환경·공통 규칙·기능 요구에 제품의 선호 의무를 같은 의미로 직접 작성 |
| 제품 지침 | 현재 `build_coding_instructions`의 반환문을 수정 없이 사용하고 같은 작업 요청 추가 |

사용자가 선택했다고 가정한 설정 두 묶음을 각각 버그 2개·기능 2개에 배정했다. 실제 사용자의 숨은 취향이나 선택 UI의 효과를 측정하지 않는다.

| 설정 | 설명 | 주석 | 구성 | 출력 |
|---|---|---|---|---|
| P1 | 코드 먼저, 간결한 이유·사용법 | 필요한 의도·주의점 | 규모에 맞는 역할 분리 | 기존 코드 변경 중심, 새 구현은 전체 |
| P2 | 단계·이유·사용법 | 핵심 로직·주의점 설명 | 간결한 구성 | 필요한 파일의 전체 코드 |

이는 16개 설정 조합 전체 검사나 개별 항목의 인과 효과 비교가 아니다. ‘역할 분리’에 파일 개수, ‘자세한 주석’에 주석 개수를 성공 기준으로 넣지 않았다.

## 새 과제와 검사기 대조

과제는 이번에 작성한 합성 미니 컴포넌트다. 실제 저장소에서 새로 발견한 운영 버그·공개 벤치마크 성능으로 표현하지 않는다. 이전에 두 번 사용한 외부 작업/초안 동기화 버그를 재사용하지 않았다.

| 과제 | 종류 | 핵심 동작 | 검사 수 |
|---|---|---|---:|
| `roster_selection` | 버그 수정 | 검색·순서 변경 후 ID 선택 유지, 보이는 항목 일괄 선택 | 9 |
| `reservation_validation` | 기능 추가 | 날짜 간 순서, 최신 정원, 필드 오류와 제출 | 9 |
| `optimistic_favorite` | 기능 추가 | 즉시 표시, 대기 중 중복 방지, 실패 복구·재시도 | 8 |
| `accordion_keyboard` | 기능 추가 | 비활성 제목 건너뛰기, 순환·Home/End 포커스, 고유 ARIA 연결 | 10 |
| `queue_pagination` | 버그 수정 | 데이터 축소·페이지 크기 변경 후 보정된 페이지 유지 | 8 |
| `undo_removal` | 버그 수정 | 마지막 삭제를 원래 순서로 한 번 복원 | 8 |
| `resource_union` | 기능 추가 | 상태 유니언 렌더링, 인자 없는 재시도, 안전한 텍스트 표시 | 8 |
| `draft_filters` | 버그 수정 | 임시값과 적용값 분리, Apply·Reset·새 목록 처리 | 9 |

총 69개 실행 검사는 서로 다른 사용자 69명이나 독립 과제 69개가 아니다. 생성 전에 정답 구현 8개가 타입·69개 동작 검사를 통과하고, 타입이 맞지만 동작이 틀린 변형 8개를 모두 감지했다. 개발용 검사기 사례도 타입 실패/동작 성공, 타입 성공/동작 실패를 분리했다.

첫 대조 실행은 잘못된 포커스의 DOM 객체를 오류 메시지로 비교하다 60초를 넘겨 중단됐다. 합격 조건은 유지하고 객체 참조 비교를 간결한 참·거짓 오류 표시로 바꿨다. 두 번째 대조에서 모든 정답·오답 검사가 완료됐다. 첫 실행 기록은 보존했으며, 이 수정은 후보 생성 전에 끝냈다.

## 생성·적용·평가 경계

- 환경: React/ReactDOM 19.3.0, TypeScript 5.9.3, 실제 React 타입, JSDOM 20.0.3. 설치된 버전을 사용했다.
- 과제·코드·프롬프트·채점 기준·집계 코드를 먼저 해시로 고정했다. 조건별 새 에이전트 3개가 첫 응답 8개씩 만들었다. 시작 과제 위치는 고정된 순환 순서로 다르게 했다. 한 에이전트 안의 8응답은 상관될 수 있으며, 정확한 런타임 모델·디코딩 설정은 별도 API 메타데이터로 노출되지 않았다.
- 원문 답변을 먼저 보존한다. 코드 적용은 명시한 파일·위치에 완전한 코드 블록/함수/구간/패치를 문자 그대로 적용한다. 누락된 import·함수·타입을 만들어 보완하지 않는다. 모호하면 전달 미확인으로 남긴다.
- 코드를 검토하고 해시를 고정한 뒤 답변마다 별도 Node 프로세스에서 실행한다. 외부 모듈·네트워크·파일 접근을 제한한 로더와 비밀 환경변수를 제외한 실행 환경을 사용한다. 완전한 OS 보안 샌드박스라고 주장하지 않는다.
- **타입:** 실제 strict TypeScript 컴파일과 공개 `Component`·`Props` 호환성을 검사한다. 컴파일 통과와 `any`·억제문 금지까지 포함한 통과를 구분한다. 외부 라이브러리 선언은 `skipLibCheck`, 후보의 별도 `.d.ts`는 공통 요청에서 제외했다.
- **동작:** 실제 ReactDOM 렌더링·상태·props 변경·클릭/입력/키보드·Promise 완료를 JSDOM에서 실행한다. 타입 실패가 있어도 실행 가능한 답변은 동작을 별도로 검사한다. 실제 브라우저 레이아웃·스크린리더·서버·보안 검증은 아니다.
- **조건:** 두 독립 검토자가 방식 이름·프롬프트·실행 점수·서로의 검토를 보지 않고 네 목표 조건을 확인한다. 정확한 답변 인용을 남긴다. 일반 요청에 주지 않은 선호를 따르지 않았다고 ‘지시 위반’이라 부르지 않고 목표와의 일치로 비교한다. AI 검토는 사람의 만족도 평가가 아니다.
- 평가 오류·미실행·전달 미확인을 성공이나 기능 실패로 바꾸지 않는다. 결과가 좋을 때까지 재생성하거나 현재 제품 지침을 수정하지 않는다.

## 결과와 해석

첫 응답 24개를 모두 적용·실행했다. 전체 파일 16개와 정확한 구간 교체 8개를 답변 지시대로 적용했으며 코드 보완·재생성은 없었다. 전달 미확인, 타입 오류, 동작 실패, 평가 중단은 0건이었다.

| 지표 | 일반 요청 | 수동 지침 | 제품 지침 |
|---|---:|---:|---:|
| strict TypeScript 컴파일 | 8/8 | 8/8 | 8/8 |
| 컴파일 + 명시적 any·억제문 없음 | 8/8 | 8/8 | 8/8 |
| 과제의 모든 동작 검사 통과 | 8/8 | 8/8 | 8/8 |
| 개별 동작 검사 | 69/69 | 69/69 | 69/69 |
| 선택한 네 답변 조건 모두 일치 | 0/8 | 8/8 | 8/8 |
| 타입·동작·네 조건 동시에 충족 | 0/8 | 8/8 | 8/8 |

두 블라인드 검토자는 **24답변 × 4항목의 판정 96개 모두 일치**했다. 과제별 같은 목표를 사용했으며 일반 요청에는 작성 선호를 전달하지 않았다. 따라서 일반 요청의 수치는 지정하지 않은 목표에 자발적으로 맞았는지를 뜻한다. 일반 요청도 기능 요구와 실행 검사를 모두 충족했다.

| 목표 항목 일치 | 일반 요청 | 수동 지침 | 제품 지침 |
|---|---:|---:|---:|
| 설명 방식 | 4/8 | 8/8 | 8/8 |
| 주석 방식 | 4/8 | 8/8 | 8/8 |
| 코드 구성 | 8/8 | 8/8 | 8/8 |
| 출력 범위 | 6/8 | 8/8 | 8/8 |

일반 요청의 차이는 코드 앞 설명 4건, 자세한 코드 주석 부재 4건, 전체 파일 대신 변경 조각을 준 경우 2건이었다. 항목은 겹치므로 실패 과제 10개로 합산하지 않는다. 구성은 세 방식 모두 목표와 일치했다. 의미 있는 단계 설명에는 번호 목록을 강제하지 않았고, 역할 분리에는 별도 파일을 강제하지 않았다.

**추가 관찰:** 수동 지침의 예약 폼(`R004`)과 제품 지침의 아코디언(`R008`)에 일본어 주석이 한 문장씩 있었다. 한국어 본문 설명과 별도로 기록한다. 사전 고정한 네 항목 평가는 주석의 의도를 보며 주석 언어를 별도 점수화하지 않았다. 원점수를 바꾸지 않았으며 네 항목 성공을 ‘모든 언어·품질 조건이 완벽함’으로 확대하지 않는다. 실행했다고 허위 주장한 답변은 발견하지 못했다.

이 결과가 뒷받침하는 것은 **이번 작은 과제들에서 제품 지침이 선택한 답변 조건을 전달했고, 관찰한 타입·동작 퇴행이 없었다는 점**이다. 조건을 잘 적은 수동 지침과 결과가 같았으므로 수동 작성보다 우수하다는 근거는 확보하지 못했다. 기능 검사는 세 방식 모두 최고점이어서 정확도 차이를 가려내지 못했다. 8개 과제의 동률은 통계적 동등성 입증도 아니다.

제품 생성기는 유지했다. 코딩 기능 전체, React 코드 스타일 비교, 사람의 선호 추정·편의성·수정 시간·팀 채택은 여전히 별도 검증 대상이다. 이후 확장은 새로운 저장소 통합 과제와 설정 조합을 먼저 고정한 뒤 진행한다. 이 8개 과제는 이제 관찰한 자료이므로 개선 후 독립 최종 평가에 재사용하지 않는다.
