# 요약 평가 오류·조건 충돌 수정 후 비교

2026-11-10, `microstone`. **새 영어 원문 9개에서 강한 수동 프롬프트·현재본·수정본의 결과가 동률이었다.** 수정본의 내용 보존 우위는 확인하지 못했다. 기본 지침을 교체하지 않고, 문장 구분 수정과 사용자가 명시적으로 조건 충돌을 해결하는 작업용 지침 경로를 추가했다. 유료 모델 API 호출·GEPA 실행·새 의존성 추가는 없었다.

## 제품에서 바뀐 동작

- `checks/summarization_grounded_v3.py`와 EN/KO v3 도메인: `Gov.`, `Rep.`, 방송사 `E!`를 문장 끝으로 잘못 세던 경우를 문맥에 따라 구분한다. 기본 지침은 v2와 같다. 과거 검사 파일·결과·점수는 소급 변경하지 않았다.
- API·Streamlit 기본 요약에 v3 검사를 연결했다. 영어·한국어 무료 데모도 같은 문장 구분 함수를 사용한다. `Gov. Han ...`을 `Gov.`와 나머지로 갈라 보여 주던 UI 문제를 고쳤다.
- React 요약 비교 완료 화면의 **이번 원문의 조건 충돌 확인**에서 분량·표현 방식·남길 원문 문장을 확인한다. 새 `/api/summary-contract`는 모델 호출·자동 저장 없이 지침을 조립한다.
- 예를 들어 ‘최대 2문장·완전 발췌’와 ‘서로 다른 원문 3문장 모두 보존’은 충돌한다. 처리 선택 전에는 새 작업용 지침을 반환하지 않는다. 사용자가 **분량 확대 / 재서술 허용 / 일부 생략 허용** 중 고른 부분만 바꾸며 변경 전후를 표시한다.
- 입력 변경은 이전 결과를 무효화하고 원문 변경은 문장 선택을 지운다. 늦게 도착한 응답은 무시한다. 12,000자 초과 원문을 조용히 자르지 않는다. 재사용 지침에는 원문을 넣지 않고, 작업용 함께 복사에만 원문·선택 문장을 넣는다.

이 기능은 **선택된 완전 발췌 문장 수와 분량의 구조적 충돌**을 다룬다. 의미상 압축 가능성·모든 중요 내용·인용의 충분한 맥락을 자동 판별하거나 보존을 보장하지 않는다. 최대 8개 문장 선택은 입력 상한이며 선호 비교 횟수나 통계적 충분성 근거가 아니다.

## 비교를 고정한 방법

1. 이전 실험에서 관찰한 원문 63개를 제외했다. 기존 MACSum 원본 `test`에서 기준에 맞고 미사용인 원문이 1개만 남아, 원본 **`val`의 미사용 자료**를 사용했다. 공식 test 성능으로 보고하지 않는다.
2. 250~800단어, 원문 단위 8개 이상, 초점 없는 참조 요약이 있는 원문을 고정 seed `20261115`로 섞었다. 최초 C03은 과거 T17과 단어 5-gram Jaccard 0.1822로 겹쳐 **생성 전에** 다음 적격 원문(val 67)으로 교체했다. 최초 자료는 별도 보존하고 최종 입력은 `evaluation_*` 파일로 구분했다. 교체 후 과거·표본 내부 603쌍의 최대 겹침은 0.0260(<0.1)이었다.
3. 프롬프트·출력을 보지 않은 원문 검토에서 각 원문당 선택 문장 3개와 비공개 핵심 명제 3개를 정했다. 선택 문장은 실제 사람의 응답이 아닌 가정이며 **세 생성 조건 모두에 제공**했다. 명제와 선택 문장의 내용이 겹치므로 ‘명시한 우선 내용 준수’ 검사이지 자발적 핵심 발견·선호 추정 검사가 아니다.
4. 충돌 6개는 동일한 짧은 완전 발췌 조건에서 확대·재서술·생략 허용을 각각 2개씩 적용했다. 비충돌 3개를 더했다. 모든 생성 조건에 동일한 원문·선택 문장·이미 해결한 최종 조건을 제공했다. 충돌을 해결한 이득을 수정본만의 모델 성능으로 계산하지 않는다.
5. 수동본은 조건·사실 보존을 분명히 적은 강한 기준이다. 현재본은 실제 v2 내보내기 지침이다. 수정본은 새 제품의 `task_requests.en`과 정확히 일치한다. 데이터·프롬프트·평가 기준·코드를 먼저 SHA-256으로 고정했다.
6. 조건별 독립 보조 에이전트 3개가 첫 응답 9개씩 저장했다. 두 독립 검토자가 방식 이름·프롬프트·다른 검토·자동 점수·참조 요약 없이 27개씩 평가했다. 점수에 따른 재생성·재채점은 없었다. 27응답 중 서로 다른 문자열은 17개이며, 동일 출력은 일관되게 채점했다.

## 관측 결과

두 익명 검토자의 아래 집계가 같았다. 의미 판정은 AI 보조 검토이며 인간 정답이 아니다.

| 지표 | 강한 수동본 | 현재본 | 수정본 |
|---|---:|---:|---:|
| 길이 조건 통과 | 9/9 | 9/9 | 9/9 |
| 표현 방식 조건 통과 | 9/9 | 9/9 | 9/9 |
| 두 형식 조건 동시 통과 | 9/9 | 9/9 | 9/9 |
| 핵심 명제 보존 | 25/27 | 25/27 | 25/27 |
| 선택 문장 속 주요 정보 보존 | 25/27 | 25/27 | 25/27 |
| 원문과의 사실 문제 표시 응답 | 0/9 | 0/9 | 0/9 |
| 요약 대신 확인 질문 등 반환 | 0/9 | 0/9 | 0/9 |

형식 조건 통과가 내용 전부 보존을 뜻하지 않는다. 모든 우선 내용을 요구한 7원문은 각 방식이 21/21, 생략을 허용한 2원문은 4/6이었다. 생략 허용 사례의 두 누락은 내용 보존 수에 그대로 남겼으며 사실을 지어낸 것으로 세지 않았다. 본문 전체를 원문과 대조했지만 사실 문제 표시 0건은 환각이 불가능하다는 보장이 아니다.

자동 v3 문장 수는 27응답 모두 두 검토자의 수와 같았다. 다만 수정본 2응답은 단어 겹침 휴리스틱에서 약 51~52%로 재서술 참고 기준을 넘었고, 두 의미 검토자는 재서술로 인정했다. **겹침 점수는 의미 판정이 아니다.** 해당 점수·임계값·출력은 결과를 보고 변경하지 않았다. 이 자동 검사 한계는 남아 있다.

독립 참고 지표인 원문별 최대 참조 요약 단어 LCS F1 평균은 수동 0.2012, 현재 0.1872, 수정 0.2034였다. 공식 ROUGE나 사실성 점수가 아니며 우위·후보 채택에 사용하지 않는다. 평균 분량은 각각 77.67·75.44·76.11단어다.

## 적용 결정과 남은 범위

**확인된 변경은 잘못된 문장 구분 수정과 명시적 조건 충돌 처리다.** 수정본의 일반적인 요약 품질 상승·수동본과의 통계적 동등성·사람의 편의성은 확보하지 못했다. 따라서 기본 지침과 선택적 GEPA를 유지한다. 이 비교를 GEPA 필수화의 근거로 쓰지 않는다. 영어 9원문에 대한 결론을 한국어 의미 품질로 옮기지 않는다.

이번에 사용한 9개는 이제 관찰 자료다. 다음 개선에 참고할 수 있지만 다음 ‘새 최종 평가’에는 다시 넣지 않는다. 후속 요약 평가는 여러 중요 정보가 한 문장에 있거나 추가 지시 대상·인용 맥락이 필요한 자료를 사전에 정하고, 이번처럼 같은 명시적 정보 단위를 보존하는 것 이상의 난도를 별도 확인해야 한다. 이 결과를 보고 같은 원문을 다시 풀어 점수를 올리지 않는다.

**코딩 검증은 별도로 남아 있다.** 현재 코딩 화면 회귀 검사는 생성 코드의 기능 검사가 아니다. 기존 실제 React 비교는 같은 JavaScript 버그 하나에 대한 결과이며, Luna 100응답은 Python 함수 과제다. 현재 TypeScript/React 제품 지침은 새 독립 과제에서 타입·실제 렌더링/이벤트·조건 준수를 따로 확인해야 한다. [코딩 증거 재점검과 다음 절차](../../docs/history/coding-validation-audit-2026-11-10.md)에 완료·미완료 범위를 구분했다.

## 검증과 재현

관련 검사 통과 기록은 [validation.json](results/2026-11-10/validation.json)에 있다. 프론트 빌드와 로컬 브라우저에서 충돌 표시·미선택 차단·확대 전후 표시·복사 범위를 확인했다. 서버는 무료 데모 모드로 실행했다. 별도 유료 모델 API는 0회이며 Codex 사용량은 소비됐다.

```powershell
.venv/Scripts/python.exe -X utf8 -m benchmarks.summary_contract_revision.run verify
.venv/Scripts/python.exe -X utf8 -m pytest -q benchmarks/summary_contract_revision/test_run.py
```

`freeze`, `blind`, `score`, `diagnostics`는 출력 파일이 없을 때 한 번만 쓰는 단계다. 보존된 실행에 다시 실행하면 덮어쓰기를 거절한다. 재집계는 저장된 JSON을 읽되 원자료를 바꾸지 않는다. `completion_seal.json`은 이 실행의 최종 파일 무결성을 확인하는 해시 목록이다.
