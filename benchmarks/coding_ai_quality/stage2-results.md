# 코딩 AI 품질 비교: 2단계 파일럿

## 목적과 조건

현재 코딩 기능의 기본 모델 `openai/gpt-4o-mini`와 코딩 작업용 후보 `openai/gpt-5.4-mini`가, 사용자가 요청한 **같은 기능**을 서로 다른 코딩 스타일의 A/B 코드로 얼마나 안정적으로 생성하는지 비교했습니다. 후보는 코딩 작업에 맞는 소형 모델로 검토했지만, 이름이나 사전 기대가 아니라 실제 결과로 채택 여부를 판단합니다.

- 고정 과제: [v1.json](v1.json)의 `calibration` 4개. `holdout` 2개는 미사용.
- 동일 조건: 기능 요청, 비교 축과 나머지 두 축의 스타일 값, 서비스의 실제 `_generate_pair` 경로, 모델별 과제당 1회.
- 실행 상한: 최대 32회의 애플리케이션 수준 API 호출 시도. 실제 완료 실행은 21회였습니다. API 공급자의 실제 청구 횟수·토큰·금액을 뜻하지는 않습니다.
- 원문: Git에서 제외된 로컬 `data/coding_ai_quality_trial.json`에 저장. API 키는 결과 파일이나 이 문서에 포함하지 않았습니다.
- `generated`는 서비스의 현행 스타일 검사를 통과해 A/B 텍스트가 반환됐다는 뜻입니다. 컴파일 성공, 기능 정확성, A/B 기능 동일성을 뜻하지 않습니다.

## 관찰 결과

| 과제 | 비교 축 | GPT-4o-mini | GPT-5.4-mini |
| --- | --- | --- | --- |
| 카운터 초기화 | 코드 구조 | 생성, 4회 시도, 29.54초 | 생성, 3회 시도, 7.71초 |
| 상품 검색 | 스타일 관리 | 생성, 3회 시도, 23.44초 | 생성, 3회 시도, 9.20초 |
| 가입 입력 검증 | 타입 작성 | 스타일 검사 실패, 2회 시도, 18.60초 | 스타일 검사 실패, 2회 시도, 14.71초 |
| 할 일 완료 전환 | 코드 구조 | 스타일 검사 실패, 2회 시도, 14.25초 | 스타일 검사 실패, 2회 시도, 8.16초 |

두 모델 모두 4개 과제 중 **2개는 텍스트 쌍이 생성되고 2개는 현행 스타일 검사에서 실패**했습니다. 이 수치는 기능 합격률이 아닙니다. 완료 실행에서 기준선은 11회 시도·총 85.83초, 후보는 10회 시도·총 39.78초였습니다. 순차 실행한 과제별 단일 표본이므로 응답 속도 차이를 일반화할 수 없습니다.

생성 원문을 표본으로 확인했을 때 기준선의 카운터 분리형 답변은 파일 구조 안내에 `CounterStyles.ts`라고 쓰면서 실제 코드는 `CounterStyles.css`로 제시해 이름이 일치하지 않았습니다. 후보의 카운터 답변에는 `JSX.Element` 반환형과 빈 Props 타입이 등장했습니다. 현재 프로젝트의 React 타입 환경에서 이것이 컴파일되는지는 확인하지 않았습니다. 두 사례 모두 현행 검사만으로는 결과 품질을 충분히 보증하지 못한다는 신호입니다.

## 결론과 다음 검증

**지금은 모델 교체를 결정하지 않습니다.** 현행 스타일 검사 통과율은 같고, 생성된 쌍의 실제 기능·빌드·동일성이 미검증입니다. 비용도 측정하지 못했습니다. 다음에는 기능 요구사항을 A와 B에 공통으로 고정하고 실패 이유를 구체적으로 기록하도록 생성·검사 경로를 개선합니다. 이후 두 모델의 결과를 타입 검사와 기능별 수용 조건으로 다시 평가하고, 마지막에 보류용 과제와 사용자 평가로 교체 여부를 결정합니다.
