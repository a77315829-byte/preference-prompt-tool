# 5단계: React 19 호환성 보완 후 재측정

코딩 후보에서 전역 `JSX.Element`를 반환 타입으로 사용하면 현재 React 19·TypeScript 5 환경에서 타입 검사가 실패할 수 있었습니다. 생성 지시에 `React.JSX.Element` 또는 반환 타입 추론을 사용하도록 명시하고, 정적 품질 검사에서 전역 `JSX.*` 사용을 거절하도록 했습니다. 이 규칙은 기능 정확성을 보증하지 않으므로, 실제 생성 코드의 타입 검사·빌드·동작을 별도로 확인했습니다.

## 실행 범위와 결과

- 사전 고정된 보정 과제 `counter_reset` 하나, 비교 축은 `code_structure`입니다. A/B는 모두 초기값 0, 증가, 초기화, 현재 값 표시를 구현해야 합니다. 보류용 과제는 사용하지 않았습니다.
- 서비스의 실제 A/B 생성 경로에서 `openai/gpt-4o-mini`와 `openai/gpt-5.4-mini`를 각각 한 쌍씩 생성했습니다. 모델당 생성·수정 시도는 3회, 전체 API 시도는 7회였습니다. 이 중 첫 1회는 실행 환경의 연결 오류로 실패했고, 이어서 생성된 두 쌍을 평가했습니다. API 시도 횟수는 토큰 사용량이나 청구 비용이 아닙니다.
- 생성된 네 후보 모두 TypeScript 타입 검사와 번들 빌드를 통과했습니다. 두 모델의 A/B 각각이 카운터의 준비된 조작 시나리오를 통과해, 이 과제의 검증 범위에서 기능 동일성이 확인됐습니다.
- A는 한 파일, B는 파일 분리 구조로 생성됐습니다. `gpt-4o-mini`의 B는 컴포넌트와 CSS, `gpt-5.4-mini`의 B는 컴포넌트와 보기 컴포넌트로 분리됐습니다. 두 모델 모두 React 19 비호환 전역 `JSX.Element` 대신 타입 추론 또는 `React.JSX.Element`를 사용했습니다.

원문과 기계 평가 결과는 Git에서 제외된 로컬 `data/coding_ai_quality_stage5_trial.json`, `data/coding_ai_quality_stage5_eval.json`에 있습니다. 평가기는 생성 코드의 코드 블록 바로 앞 제목에서 파일명을 읽도록 보완했습니다. 파일 구조를 설명한 문장의 파일명을 코드 파일명으로 오인하던 회귀 사례도 테스트에 추가했습니다.

## 해석과 남은 검증

이번 결과는 **카운터 한 과제의 한 번씩 생성한 A/B**에만 해당합니다. 두 모델 간 우열이나 모델 변경을 결정할 표본이 아닙니다. 타입·빌드·정해진 조작 시나리오가 모두 통과했다는 뜻이지 임의 기능의 완전한 동일성을 증명하지는 않습니다. 다른 보정 과제와 보류용 과제, 실제 사용자 평가, 비용 확인은 남아 있습니다. 보류용 과제는 규칙 조정에 사용하지 않아야 합니다.
