# 6단계: 상품 검색 A/B 교차 검증

고정 평가 과제 `product_search`만 선택해 기존 기준 모델 `openai/gpt-4o-mini`와
후보 `openai/gpt-5.4-mini`의 A/B를 각각 한 쌍씩 생성했습니다. A/B는 같은
React·TypeScript 상품 검색 기능을 요청하고, 스타일 관리 방식만
`theme` 대 `direct`로 달리했습니다. 홀드아웃 과제는 사용하지 않았습니다.

| 모델 | 생성 | A/B 타입 검사 | A/B 빌드 | 고정 동작 시나리오 | 관찰 |
| --- | --- | --- | --- | --- | --- |
| `openai/gpt-4o-mini` | 성공 | 모두 통과 | 모두 통과 | 양쪽 모두 3/3 | 테마 객체 대 직접 값 작성 구분 |
| `openai/gpt-5.4-mini` | 성공 | 모두 통과 | 모두 통과 | 양쪽 모두 3/3 | A에만 포커스 테두리 변화가 있어 비교 축 외 차이 존재 |

첫 API 시도는 로컬 네트워크 제한으로 실패했고, 허용된 환경에서 재개했습니다.
전체 API 시도는 실패 1회를 포함해 7회로, 설정한 상한 8회 이내였습니다.
동작 검사는 초기 상품 3개 표시, 입력 필터링, 검색 결과 없음 표시의 고정
시나리오만 확인합니다. 두 구현의 모든 상태가 동일하다는 증거는 아닙니다.

수동 검토에서 후보 모델 A에만 입력창 포커스 시 테두리 색을 바꾸는 동작이
있었습니다. 그러므로 기능·시각 동등성을 완전히 확인했다고 판단하지
않습니다. 이를 반영해 생성 지시에 스타일 값, 포커스/호버 상태 및 접근성
속성도 같게 유지하도록 명시했습니다. 이 변경 뒤의 실제 AI 출력은 아직
재측정하지 않았습니다.

원문과 평가 JSON은 Git에서 제외된 로컬 `data/coding_ai_quality_stage6_trial.json`,
`data/coding_ai_quality_stage6_eval.json`에 보관합니다. 사용자 선호 평가는 아직
진행하지 않았고, 위 결과만으로 모델 우위를 결론 내리지 않습니다.
