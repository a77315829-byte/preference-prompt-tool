# 실제 GEPA 엔진을 사용하는 유료 API 없는 요약 비교

설치된 `gepa==0.1.4`의 `gepa.optimize()`가 부모 후보 선택, 성찰 프롬프트 구성·응답 추출,
소규모 학습 묶음의 후보 수용, 전체 검증 점수와 최종 후보 선택을 수행한다.
모델 응답을 받는 부분만 파일 요청과 독립 Codex 보조 에이전트로 연결했다.
이전 `summary_reflection`의 한 번의 수동 성찰 절차와 달리 **실제 GEPA 탐색 루프를 실행한다.**

외부 유료 모델 API는 사용하지 않는다. Codex 사용량은 소비되며 실제 모델 이름·디코딩 설정·토큰 사용량은
이 도구에서 노출되지 않았다. 개발 중의 조정자가 파일 요청을 에이전트에게 전달하는 방식이며,
웹 서비스에서 GEPA를 무료로 자동 제공할 수 있다는 뜻은 아니다. 운영 서버에는 별도 모델 실행 경로가 필요하다.

## 범위와 분리

이전 세 요약 실험의 42개 원문을 모두 제외하고 MACSum macdoc에서 새 원문 21개를 선택한다.

| 용도 | 개수 | 원래 데이터 분할 | 쓰임 |
|---|---:|---|---|
| 개선 | 6 | train | GEPA가 선택한 사례의 출력·실패 피드백으로 지침 제안 |
| 후보 선택 | 6 | val | 후보 선택용 점수; 최종 성능이라고 보고하지 않음 |
| 최종 평가 | 9 | test | 탐색 종료 후 현재 지침·GEPA 결과 비교 |

문서 길이는 250–800 공백 구분 단어, 원문 단위 8개 이상, 주제 제한 없는 참조 요약이 있는 문서다.
모든 분할은 원문 SHA-256로 서로 겹치지 않으며 데이터셋·표본·코드·지침·평가 기준을 생성 전에 고정했다.
최종 평가에는 길이 3 × 표현 3 조건을 한 번씩 배정한다. 모델 사전학습 미포함을 보장하지 않는다.

원문마다 핵심 명제 3개를 출력 생성 전에 작성했다. 최종 평가 명제는 별도 원문 검토를 거쳤고,
불필요한 세부 시간 조건 세 곳을 생성 전에 단순화했다. [주석 한계](results/2026-11-10/annotation_limits.json),
[사전 원문 검토](results/2026-11-10/anchor_audit.json). 이는 사람이 작성한 정답이나 전체 내용 목록은 아니다.
짧은 완전 발췌에서는 세 핵심 명제가 서로 다른 원문 문장에 있어 모두 담을 수 없는 경우가 있다.

## 실제 탐색과 채점

현재 제품의 `summarization_grounded_v2.yaml`에서 내보낸 지침은 고정하고, 뒤에 붙는 **220단어 이하 보충 지침만**
탐색한다. 성찰은 최대 2회, 새 `(원문, 선택 조건, 전체 지침)` 평가는 최대 30개다. 결합 탐색은 사용하지 않는다.
변경 지침이 기존 지침을 실제로 따르는지는 평가해야 하며, 문자열 보존만으로 준수를 보장하지 않는다.

설치된 GEPA가 제공하는 Pareto 부모 선택과 동점 허용 학습 수용을 사용한다. 후보 선택용 전체 점수를 비교하고,
현재 지침과 최고 점수가 같으면 현재 지침을 유지한다. 유효하지 않은 후보는 유효한 점수보다 낮은 -1을 받고
최종 비교 후보에서도 제외한다. 원문과 겹치는 5단어 연속 구문 검사는 보수적인 누출 방지이며 완벽한 판별기는 아니다.

기본 성찰 템플릿의 사례 사실을 지침에 담으라는 요청을 사용하지 않고, 사례를 외우지 않는 일반 규칙만 제안하도록
GEPA의 공식 `reflection_prompt_template` 확장 지점을 사용한다. GEPA 알고리즘·설치 패키지는 변경하지 않는다.

탐색 점수는 핵심 명제 보존 수/3이다. 자동·익명 검토의 길이/표현 조건에 실패하거나 사실 문제 표시가 있으면 0이다.
최적화 중 의미 평가는 생성자와 다른 새 맥락의 에이전트 하나가 수행한다. 동일 입력·전체 지침은 첫 응답과 평가를 캐시한다.
**운영 `service.optimize()`의 형식 위주 점수와 다른 연구용 평가 설정**이다. 기존 서비스 점수가 내용 품질을 보장한다는 근거로 쓰지 않는다.

최종 결과는 서로 다른 두 익명 검토자가 조건 준수·핵심 내용·전체 요약의 사실 문제를 따로 평가한다.
후보 선택 점수로 합쳐 보고하지 않는다. 추가로 GEPA에 제공하지 않은 사람 참조 요약과의 단어 순서 겹침(LCS F1),
출력 단어 수를 계산한다. 참조는 주제 제한이 없고 요청 길이가 같은 것을 우선하며, 없으면 주제 제한 없는 것을 사용한다.
이 겹침 점수는 공식 ROUGE 구현이나 사실성 점수가 아니며 충실한 다른 표현에도 낮을 수 있다.

GEPA가 원본을 선택하면 이를 그대로 보고한다. 후보 선택용 평가를 받은 비원본 후보가 있다면 그 점수가 가장 높은 후보를
별도의 **탐색 참고 조건**으로만 추가한다(동점은 먼저 나온 후보). 이것을 GEPA가 채택한 결과로 바꾸어 보고하지 않는다.
최종 입력을 만들기 전에 이 정책으로 후보를 고정한다. 동일 지침은 첫 요약을 재사용하고 독립 표본인 것처럼 세지 않는다.
최종 결과를 보고 후보를 다시 선택·수정·재생성하지 않는다.

## 무결성과 재현

`queue/NNNN_kind/request.json`은 GEPA가 생성한 실제 요청이고, `response.json`은 요청 파일 SHA-256에 묶인다.
생성·검토·성찰 담당은 각각 다른 새 맥락이며 허용된 요청만 읽는다. 코드에서 모델 API 클라이언트·모델 문자열·
자격증명·외부 프로세스를 사용하지 않고 최적화 프로세스의 소켓 연결을 차단한다. 이는 완전한 OS 샌드박스는 아니다.

GEPA의 리스트 학습/검증 로더가 모두 정수 0부터 식별자를 부여하므로 공유 평가 캐시를 켜면 학습 결과가
검증에 재사용될 수 있다. 이 실행에서는 GEPA 내부 캐시를 끄고, 원문·프로필·전체 지침을 포함한 별도 캐시를 쓴다.
학습에서만 좋아지는 가짜 응답으로 실제 GEPA를 실행해 이 교차 오염을 방지하는 회귀 검사를 통과했다.

`events.jsonl`·`engine/`·`gepa_result.json`에는 실제 탐색과 요청·응답·캐시 사용을 남긴다.
대기 시간에는 조정자가 에이전트 작업을 배정하는 시간이 포함되어 제품 지연이나 사람의 수정 시간으로 해석하지 않는다.
원문 해시 확인은 최종 파일 바이트도 읽지만 그 원문은 최적화 데이터나 모델 요청에 제공하지 않는다.

```powershell
# 기록된 실행은 덮어쓰지 않는다. 아래는 새 실행의 준비·배정 절차다.
.venv/Scripts/python.exe -X utf8 -m benchmarks.summary_gepa_offline.run sample
.venv/Scripts/python.exe -X utf8 -m benchmarks.summary_gepa_offline.diagnostics prepare
# 세 분할의 facts.json과 사전 검토를 완성한 후
.venv/Scripts/python.exe -X utf8 -m benchmarks.summary_gepa_offline.run freeze
.venv/Scripts/python.exe -X utf8 -u -m benchmarks.summary_gepa_offline.driver
# 출력되는 PENDING 요청을 독립 에이전트에 배정해 같은 폴더 response.json으로 응답한다.
# 실제 GEPA가 종료된 뒤에만:
.venv/Scripts/python.exe -X utf8 -m benchmarks.summary_gepa_offline.run prepare_final
# 서로 다른 최종 입력의 첫 출력을 받은 후
.venv/Scripts/python.exe -X utf8 -m benchmarks.summary_gepa_offline.run blind
# 익명 검토 두 개를 받은 후
.venv/Scripts/python.exe -X utf8 -m benchmarks.summary_gepa_offline.run score
.venv/Scripts/python.exe -X utf8 -m benchmarks.summary_gepa_offline.diagnostics measure
.venv/Scripts/python.exe -X utf8 -m benchmarks.summary_gepa_offline.run verify
```

외부 모델 API 없이 소수의 영어 뉴스와 같은 계열 AI로 수행하는 제한된 실험이다. 유의한 일반 우위,
사람의 선호·만족도·시간 절감, 한국어 품질, 모든 GEPA 설정의 효과를 검증하지 않는다.
이 결과로 제품 기본값을 자동 교체하거나 GEPA를 필수 실행으로 바꾸지 않는다.
[GEPA 공식 구현](https://github.com/gepa-ai/gepa), [논문](https://arxiv.org/abs/2507.19457).

## 새 원문 9개 최종 비교

탐색 종료 후 고정한 현재본과 첫 GEPA 후보로 각각 9개씩, 총 18개 첫 요약을 생성했다.
독립된 두 검토자는 같은 원문·목표·고정 핵심 명제를 받고 조건 이름과 프롬프트를 보지 않은 채 평가했다.
두 검토자의 문장 수·표현 조건·명제 보존·사실 문제 유무 판정은 모두 일치했다.

| 조건 | 길이·표현 동시 통과(A/B) | 핵심 명제 보존(A/B) | 사실 문제 표시 요약(A/B) |
|---|---:|---:|---:|
| 현재 수정본 | 9/9 · 9/9 | 22/27 · 22/27 | 1/9 · 1/9 |
| 첫 GEPA 후보 — 비채택 탐색 참고 | 9/9 · 9/9 | 20/27 · 20/27 | 0/9 · 0/9 |

**GEPA가 최종 반환한 지침은 현재 수정본 그대로다.** 따라서 GEPA 최종 선택본의 별도 표본은 없으며
현재본과 같은 출력을 재사용한다. 표의 두 번째 행은 GEPA가 만든 후보지만 최종 선택한 결과가 아니다.
최종 평가 결과를 보고 이 후보를 다른 것으로 바꾸거나 다시 생성하지 않았다.

현재본의 사실 문제 1건은 원문의 ‘많은 자녀가 지지하는 것으로 보인다’를 ‘여러 자녀가 지지를 표명했다’로
강하게 바꾼 부분이다. 이는 원문 근거보다 단정적인 표현이라는 표시이며 현실에서 거짓임을 입증한 것은 아니다.
후보의 표시가 0건이라는 사실도 오류가 전혀 없음을 보장하지 않는다. 현재본은 고정 핵심 명제를 2개 더 보존했고,
후보에는 이 사실성 표시가 없었다. **내용 보존 개선이나 전반적인 우위는 확인하지 못했다.**

핵심 명제 27개는 출력 전에 작성한 AI 주석이다. 누락된 항목에는 한정·맥락이 포함되며 모든 누락이 허위 사실은 아니다.
특히 짧은 완전 발췌 H05는 두 문장 안에 세 명제를 모두 담을 수 없다는 한계를 생성 전에 기록했다.
원래 27개 분모를 유지하고 이 제약을 명시한다. 실제 사용자의 핵심 정보 판단이나 만족도와 동일시하지 않는다.

자동 조건 검사는 현재본 9/9·후보 8/9였지만, 후보 한 건의 `Gov.`를 문장 끝으로 오인해 2문장을 3문장으로 센
실패가 포함됐다. 두 독립 검토자는 모두 2문장으로 판정했다. `E!`·`Rep.`에서도 문장 수 차이가 있었지만
길이 조건의 통과 여부는 달라지지 않았다. 위 표는 사전 계획대로 독립 검토자의 조건 판정을 쓰며,
[자동 검사와의 차이](results/2026-11-10/final/integrity.json)와
[원문 대조 검토](results/2026-11-10/final/adjudication.json)를 별도로 보존한다.
