# 요약 조건 준수·내용 보존: Codex 보조 에이전트 파일럿

2026-11-10. MACSum 영어 뉴스 원문 9개 × 일반 요청·수동 지침·서비스 조립 지침 = 27개 요약.
별도 유료 모델 API를 호출하지 않는다. Codex 사용량은 소비되며 계정의 실제 사용량·요금은 측정하지 않는다.
코딩 기능과 기존 연구 엔진은 변경하지 않는 별도 실험이다.

## 결과

**이 표본에서 조건을 명시한 두 방식은 길이를 잘 제어했지만, 우리 조립본이 잘 쓴 수동 프롬프트보다
내용을 더 보존한다는 우위는 확인되지 않았다.** 일반 요청은 목표 조건을 전달받지 않았으므로
조건 준수 수치를 일반적인 요약 품질의 우열로 해석하지 않는다.

| 조건 | 길이 조건 | 표현 조건 | 두 조건 모두 | 고정 핵심 사실 보존 | 사실 문제를 표시한 출력 |
|---|---:|---:|---:|---:|---:|
| 일반 요청 | 2/9 | 4/9 | 0/9 | 21/27 | 1/9 |
| 수동 프롬프트 | 9/9 | 8/9 | 8/9 | 21–22/27 | 0/9 |
| 우리 프롬프트 | 9/9 | 8/9 | 8/9 | 21/27 | 0/9 |

문장 수와 표현 조건은 두 검토자의 판정이 27/27 일치했다. 핵심 명제는 81개 판정 중 80개가
일치했다. 수동 S03의 반복 개봉 연기를 시간 순서에서 추론할 수 있는지에 따라 1개가 갈려
원문을 다시 검토한 뒤에도 범위로 남겼다. 두 에이전트는 같은 모델 계열이므로 높은 일치도를
독립적인 사람 검증으로 해석하지 않는다. 명제는 여러 세부 내용을 묶기도 하므로 21/27을
“문서 의미의 77.8% 보존”이라고 표현하지 않는다.

- **공통 표현 실패:** 수동·조립 S03은 문장 앞의 `(The Hollywood Reporter)`를 제거했다.
  나머지는 발췌였지만 사전 고정한 엄격한 원문 일치 기준에서 실패했다. 의미 왜곡 사례는 아니다.
- **누락 사례:** 두 방식의 S07은 같은 두 문장을 발췌했다. $29라는 전체 예산과 인식 제고 목적이
  빠졌고, Paltrow의 참여와 캠페인의 연결도 명시적이지 않아 엄격한 3개 명제를 충족하지 못했다.
  내용이 모두 무의미하다는 뜻은 아니다. 짧은 발췌의 정보 손실을 보여 주는 사례다.
- **방식 간 차이:** S02에서 수동본은 경찰 정차의 결과가 공개되지 않았다는 사실을 담았고
  조립본은 생략했다. S03에서는 조립본이 개봉 연기 경위를 더 명시적으로 남겼다.
  개별 사례를 방식 전체의 우위로 일반화하지 않는다.
- **사실 문제:** 일반 요청 S04의 `former participants`에서 `former`라는 지위 설명은 제공된
  원문에 없다. 두 검토자와 원문 재검토가 같은 문제를 지적했다. 다른 출력에서 문제가 발견되지
  않았다는 결과가 무오류 보장은 아니다.
- **자동 지표의 함정:** 기존 bigram 점수 통과는 일반 3/9, 수동 5/9, 조립 7/9다.
  실제 표현 지시 검토에서는 수동과 조립이 모두 8/9였다. `high`의 75% 상한과 자연어 지시의
  불일치 때문에 자동 점수 차이를 곧바로 조립본의 우위로 쓰면 안 된다.
- S01·S07은 수동/조립 출력이 완전히 같았다. 두 검토자 모두 이 중복 쌍을 일관되게 판정했다.

[실행 기록](results/2026-11-10/execution.json). 새 평가 검사와 기존 프롬프트 내보내기 검사 **24개 통과**.
처음 검사에서는 샌드박스 임시 폴더 생성 오류 4개가 발생했고, 저장소 안의 새 임시 경로로
동일 검사를 실행해 24개 모두 통과했다. 앱 코드 오류나 결과 재생성으로 처리하지 않았다.

## 이 결과에 따른 개발 우선순위

1. 선택한 조건과 생성된 지침의 대응을 명확히 보여 주고, 사실·불확실성 보존을 길이와 별도로 점검한다.
2. 짧게/그대로 발췌의 조합에서 핵심 내용이 빠질 수 있음을 확인할 방법을 마련한다.
   선호 추정 성공률을 높였다고 주장하거나 비교 횟수를 늘리는 것으로 해결하지 않는다.
3. 자연어 지시와 자동 검사의 불일치를 정리한다. 과거 실험 점수는 덮어쓰지 않고 새 버전에서 검증한다.
4. 후속 변경은 다른 원문에서 다시 비교한다. 이번 9개에 맞춘 수정 후 같은 자료에서 좋아진 수치를
   독립 검증으로 보고하지 않는다. 본 실행에서는 앱 생성기·선택 횟수·코딩 기능을 바꾸지 않았다.

## 목적과 비교 조건

명시한 결과 조건을 지침으로 전달했을 때 새 원문의 답변에서 조건과 내용을 얼마나 유지하는지 확인한다.
사람의 취향 발견, 선택 횟수의 적정성, 사용성·시간 절감·서비스 채택을 평가하지 않는다.

| 조건 | 지침 |
|---|---|
| 일반 요청 | 영어로 요약하고 요약문만 출력 |
| 수동 프롬프트 | 실험자가 직접 적은 길이·표현 조건과 사실·숫자·불확실성 보존 지침 |
| 우리 프롬프트 | 같은 목표 설정을 현재 `engine.generator.build_final_prompt`의 영어 내보내기에 전달 |

수동과 조립본은 같은 목표 정보를 받는다. 일반 요청에는 목표 조건을 알려주지 않으므로,
그 조건의 준수 차이는 정보 제공 효과를 포함한다. 주 비교는 수동 대 조립본이다.
두 지침의 길이·표현 목표는 같지만 전체 규칙의 표현과 우선순위는 다르다.
수동본은 주장 주체·혐의·계획을 명시하고, 현재 조립본은 선호를 먼저 지키라는 문구를 포함한다.
따라서 **실제로 사용 가능한 두 프롬프트 전체의 비교**이며, 동일한 규칙의 조립 경로만 분리한 실험은 아니다.
고정 프로토콜의 `same ... fidelity rules`는 같은 사실 보존 목적이라는 뜻으로 한정한다.
수동 지침은 실제 참가자가 쓴 것이 아니며, 조립본도 사람의 비교 선택을 거치지 않았다.
조립본에 포함된 “비교에서 추정한 선호”라는 기존 안내 문구는 실제 실험의 출처를 설명하지 않는다.
이번에는 확정 설정을 주입해 현재 내보내기를 그대로 검사했으며 이 문구를 결과의 근거로 삼지 않는다.
GEPA·프롬프트 재작성·출력 후 재생성은 하지 않는다.

## 생성 전에 고정한 사항

- 로컬 `data/macsum/dataset/macdoc/test.json`에서 250–800단어, 원문 단위 8개 이상,
  주제 제한 없는 참고 요약을 가진 52개 후보를 seed 20261110으로 섞어 첫 9개 선택.
- 짧음/보통/김 × 바꿔쓰기/원문 표현 활용/그대로 발췌의 9조합을 별도 seed로 배정.
  한 조합당 문서 1개라 조합별 성능을 일반화할 수 없다. 주제 조건은 사용하지 않는다.
- 첫 후보 생성 전에 별도 에이전트가 원문 근거가 있는 핵심 명제 3개씩 주석하고,
  실제 부분문자열 인용을 코드로 검증했다. 이 명제는 MACSum의 사람 정답 라벨이 아닌 AI 주석이다.
- 평가 기준·원문·실제 프롬프트·주석을 SHA-256으로 고정했다.
- 대화 이력을 물려받지 않은 생성 에이전트 3개가 동일한 상속 모델/추론 설정으로 조건 하나씩 처리했다.
  각 조건 내 9개는 같은 대화 안에서 처리한다. OS 격리나 27개 독립 모델 실험은 아니다.
  저장소 운영 지침은 모두 동일하게 읽고, 다른 조건·평가 답안은 읽지 않도록 지시했다.

## 평가

**조건 준수와 내용 보존을 합산하지 않는다.**

1. 문장 수: 짧음 1–2, 보통 3–4, 김 5문장 이상. 앱의 단순 문장 분리 결과와
   약어·인용부호를 고려한 검토자 문장 수를 구분한다.
2. 표현 방식: 익명화한 출력에서 별도 검토자 두 명이 고정 rubric으로 확인한다.
   기존 bigram 겹침은 별도 진단이다. 특히 `high`의 자연어 지시는 가능한 많이 재사용하라는
   뜻인데 자동 검사에는 75% 상한이 있으므로, 그 점수를 곧바로 지시 위반으로 해석하지 않는다.
3. 핵심 사실 보존: 원문별 고정 명제 3개가 요약에 보존되는지와 근거 구절을 기록한다.
   중요한 한정·주장 주체가 빠지면 부분 보존으로 간주해 통과시키지 않는다.
   짧은 발췌에서 3개를 모두 담기 어려울 수 있다. 이는 내용 포함량의 비교이며
   모든 출력에 100% 보존을 요구하는 합격 시험이 아니다. 누락과 사실 오류를 구분한다.
4. 사실 문제: 요약 전체에서 추가·왜곡·잘못된 수치·불확실성을 확정으로 바꾼 표현을
   별도로 찾는다. 보존한 핵심 사실이 많아도 새로운 오류가 있으면 기록한다.

두 검토자는 생성에 참여하지 않은 독립 Codex 에이전트다. 원문·목표 조건·고정 명제·익명 출력만
읽으며 조건명·생성 지침·다른 평가를 읽지 않는다. 출력 형식으로 조건을 추측할 가능성은 남는다.
의미·사실 관계는 문자열 검사만으로 판정할 수 없어 AI 검토를 사용한다. 인용은 코드로 대조하고
평가 불일치와 근거를 보존한다. 사람의 사실성 평가나 사용자 선호 점수로 표현하지 않는다.

## 원자료와 재현

- [프로토콜](results/2026-11-10/protocol.json), [고정 해시](results/2026-11-10/frozen.json)
- [원문·설정·프롬프트](results/2026-11-10/cases.json), [사전 핵심 명제](results/2026-11-10/facts.json)
- `inputs/`: 조건별 생성 입력. `outputs/`: 첫 제출 원문.
- `blind_packet.json`: 익명 평가 입력. `blind_mapping.json`: 조건 대조표(검토자에게 숨김).
- `automatic.json`: 자동 측정, `review_a.json`·`review_b.json`: 독립 의미 검토, `scores.json`: 집계.

```powershell
.venv/Scripts/python.exe -X utf8 -m pytest benchmarks/summary_agent_pilot/test_evaluate.py -q
# 아래 명령은 기존 파일을 덮어쓰지 않는다. 새 실행은 별도 RUN 식별자를 사용한다.
.venv/Scripts/python.exe -X utf8 -m benchmarks.summary_agent_pilot.prepare
# 원문 근거를 검토해 facts.json 작성 후:
.venv/Scripts/python.exe -X utf8 -m benchmarks.summary_agent_pilot.evaluate freeze
# 독립 에이전트의 첫 출력 세 파일을 받은 후:
.venv/Scripts/python.exe -X utf8 -m benchmarks.summary_agent_pilot.evaluate blind
.venv/Scripts/python.exe -X utf8 -m benchmarks.summary_agent_pilot.integrity seal
# 독립 검토 두 파일을 받은 후:
.venv/Scripts/python.exe -X utf8 -m benchmarks.summary_agent_pilot.integrity verify
.venv/Scripts/python.exe -X utf8 -m benchmarks.summary_agent_pilot.evaluate score
```

스크립트는 모델을 호출하지 않는다. 기존 라이브러리만 사용한다.
MACSum 원자료와 그 사용 조건은 로컬 `data/macsum`을 따른다.
독립 방법 검토에 따라 사전 고정 파일은 그대로 두고 생성 이후 무결성 검사·해시를 추가했다.
사실 오류는 유무의 일치만으로 같은 판단이라고 하지 않으며, 어느 검토자든 오류를 표시한 모든 출력의 근거를 추가 확인한다.

## 해석 범위

9개 공개 영어 뉴스, 조건당 1회인 탐색 파일럿이다. 원문이 모델 사전학습에 들어갔는지는 알 수 없고,
이 저장소에서 해당 test 분할을 과거에 확인한 이력이 있다. 완전히 처음 보는 비공개 시험이라고 하지 않는다.
문장 수 설정은 현재 앱의 설정이며 MACSum의 원래 길이 라벨과 동일하지 않다.
한국어·회의록·팀 업무·실제 사람의 선호로 일반화하지 않는다. 통계적 우위·동등성을 주장하지 않는다.
에이전트 실행 시간은 사람의 작성·수정 시간으로 해석하지 않는다.

MACSum: https://aclanthology.org/2023.tacl-1.46/ — 조건부 요약의 외부 자료이며 이 도구의 채택 효과를 입증하는 연구가 아니다.
