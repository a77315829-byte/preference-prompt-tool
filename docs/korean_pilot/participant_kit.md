# 한국어 요약 파일럿 — 참여자 안내 묶음

`README.md`의 절차를 실제 사람과 진행할 때 쓰는 문서다. 모집 문구, 동의 안내,
진행 체크리스트, 기록표를 담았다. `[ ]` 칸은 팀이 정해서 채운다.

> 학교·기관에 연구윤리(IRB) 규정이 있으면 이 파일럿이 심의 대상인지 먼저 확인한다.
> 아래 동의 안내는 출발점이며 법률 검토를 거친 문서가 아니다.

## 1. 모집 문구 (메신저·게시판용)

> **AI 요약 방식 비교 실험 참여자 모집 (약 30분)**
>
> AI에게 원하는 요약 방식을 알려 주는 두 가지 방법을 비교합니다.
> ① 지침을 직접 써 보기 ② 두 요약 중 마음에 드는 쪽을 몇 번 고르기.
> 그다음 새 글 3개의 요약을 보고 어느 쪽이 나은지 골라 주시면 됩니다.
>
> - 대상: AI로 글을 요약해 본 적이 있는 분 [대상 범위]
> - 시간: 약 30분, [대면/온라인]
> - 사례: [있음/없음 - 내용]
> - 이름 대신 번호(P001 등)로만 기록합니다.
> - 문의: [담당자 연락처]

## 2. 동의 안내 (시작 전에 읽어 드리고 확인받기)

1. **목적:** AI 요약 지침을 만드는 두 방법(직접 작성, 비교 선택)의 소요 시간과 결과 선호를 비교합니다.
2. **하는 일:** 지침 직접 작성, 두 요약 중 고르기(최대 8회), 새 글 3개의 요약 평가. 약 30분.
3. **기록하는 것:** 참여자 번호, 작성한 지침, 걸린 시간, 지침을 고친 횟수, 평가 응답.
   이름과 연락처는 연구 기록에 넣지 않습니다.
4. **외부로 보내는 것:** 요약할 글과 지침은 요약을 만들기 위해 AI 서비스(OpenAI API)로 전송됩니다.
   **개인 정보나 민감한 내용이 든 글은 쓰지 마세요.** 실험에 쓰는 글은 연구팀이 준비합니다.
5. **보관과 삭제:** 기록은 [보관 위치]에 [기간]까지 보관하고 그 뒤 삭제합니다.
6. **자발적 참여:** 언제든 그만둘 수 있고, 그만두면 그때까지의 기록은 [삭제/요청 시 삭제]합니다.
7. **결과 공개:** 결과는 참여자를 알아볼 수 없는 집계로만 발표합니다.

확인: 참여자 번호 `P___` · 날짜 `____` · 동의 여부 ☐ 예 ☐ 아니오

## 3. 진행 체크리스트 (진행자용)

준비
- [ ] 참여자 번호 배정, 수집 순서 결정: 홀수 번호는 `direct_first`, 짝수는 `selected_first`
- [ ] 선호 수집용 글 1개, **다른** 평가용 글 3개 준비 (`README.md` 2절)
- [ ] 평가용 글마다 핵심 사실 목록(`must_keep`)을 **생성 전에** 작성
- [ ] API 서버를 `PPT_LIVE=1`로 켜고 `npm run dev` - 첫 화면에서 연결 상태 확인
- [ ] 타이머 준비

진행 (수집 순서대로)
- [ ] **직접 작성:** "이 글을 원하는 방식으로 요약하게 하는 지침을 써 주세요." 시작~완료 시간과 고쳐 쓴 횟수를 잰다
- [ ] **비교 선택:** 문서 요약 카드 → 한국어 요약 → 수집용 글 입력 → 결과 화면까지. 시간과 실제 선택 횟수를 잰다
- [ ] 결과 화면의 프롬프트를 **"선호 기준으로 최적화"를 누르기 전에** 복사
- [ ] 평가 화면(`pilot_review.py`)에 blind_packet 만 넣고 평가를 받는다
- [ ] 응답 JSON 다운로드 확인

끝나고
- [ ] 기록표를 `P___-input.json` 으로 옮긴다 (측정 안 한 칸은 `null`, 추정치 금지)
- [ ] 중도 이탈이면 이유와 단계만 따로 적는다 (결과 집계에는 넣지 않는다)
