# 한국어 요약 사용자 비교 — 실행 안내

이 도구는 **직접 쓴 지침 vs 8회 선택으로 만든 지침**을 새 한국어 문서에 적용하고,
생성 방식 이름을 숨긴 상태에서 사용자의 선호·사실 오류·핵심 누락을 기록한다.
주 앱과 분리된 연구용 도구다. 이를 구현했다고 한국어 개인화 효과가 입증된 것은 아니다.

## 1. API 없이 화면부터 확인하기

저장소 루트 PowerShell에서:

```powershell
.\.venv\Scripts\python.exe -m experiments.korean_pilot demo
.\.venv\Scripts\python.exe -m streamlit run pilot_review.py --server.address 127.0.0.1
```

브라우저에서 `data/korean_pilot_demo/P001/blind_packet.json`을 업로드한다.
세 문서를 평가하고 동의를 확인한 뒤 **응답 파일 준비 → 응답 JSON 다운로드**를 누른다.
원문과 후보는 화면에서 처리되며 모델 API는 호출하지 않는다.

- 예시 원문은 가상의 기관·사건으로 작성했다. 실제 기사나 사람 실험이 아니다.
- 후보는 원문의 앞 문장을 자른 연습용 결과다. 모델 생성/8회 선택 성과가 아니다.
- `is_test=true`, 모델 `no-api-demo`로 고정해 실사용자 집계에서 제외한다.
- `private.json`에는 조건 대응표가 있다. 평가자에게 전달하지 않는다.

## 2. 실제 참여자에게 받을 것

처음에는 5~8명으로 불편·실패 유형을 찾는 파일럿을 권장한다. 통계적 우위 증명을
위한 표본 수는 이 도구가 정하지 않는다. 본실험 모집 규모는 파일럿 후 별도로 정한다.

참여자마다:

1. 실명 대신 `P001` 같은 ID를 부여하고 실험 참여/자료 처리 범위를 설명한다.
2. 선호 수집용 원문 1개와, **다른** 평가용 원문 3개를 준비한다. 원문 사용 권한과 민감정보를 확인한다.
3. 본인이 원하는 한국어 요약 지침을 직접 쓰게 하고 시간을 잰다.
4. 주 앱에서 한국어 요약 / 실제 API 모드로 동일한 수집용 원문에 대해 8회 선택한다.
   GEPA를 누르기 **전** 조립 프롬프트를 복사하고 총 시간을 기록한다.
5. 3번과 4번 순서는 참여자 사이에서 균형 있게 바꾼다. `collection_order`에 기록한다.
6. 평가 문서의 핵심 사실 목록은 후보 생성 **전에** 작성한다. 결과를 보고 유리하게 고르지 않는다.
7. 평가자는 두 결과를 보고 선호 A/B/비슷함/둘 다 원하지 않음 중 하나를 선택한다.
   내용 품질도 각 후보별로 따로 평가한다.

직접 지침과 선택 지침 모두 완전한 시스템 프롬프트로 넣는다. 같은 요약 작업과
한국어 출력 지시를 포함하고, 연구자가 직접 지침을 일부러 약화하거나 임의로
보강하지 않는다. 수정이 있었다면 기록하고 해당 비교의 한계를 보고한다.
선호 수집이 데모로 전환됐거나 8회를 완료하지 못했다면 실제 API 조건으로 섞지 않는다.

## 3. 입력 파일과 실행

실제 자료는 Git에서 제외되는 `data/` 아래에 둔다.

```powershell
New-Item -ItemType Directory -Force data/korean_pilot | Out-Null
Copy-Item docs/korean_pilot/protocol.example.json data/korean_pilot/P001-input.json
```

`P001-input.json`을 실제 내용으로 바꾼다:

- `is_test`: 실제 참여자가 실제 절차를 수행한 경우에만 `false`.
- `model`: 평가 두 조건에 동일하게 사용할 모델. 배포 모델과 실험 모델이 다르면 따로 보고한다.
- `prompts.direct`: 사용자가 직접 작성한 전체 지침.
- `prompts.selected`: 주 앱에서 얻은 전체 조립 지침.
- `effort_seconds`: 측정한 초 단위 시간. 측정하지 않았다면 `null`. 추정치를 넣지 않는다.
- `calibration_sources`: 선호 수집에서 사용한 모든 원문.
- `documents`: 새로운 원문과 사전에 정한 `must_keep` 핵심 사실 목록.
- `collection_order`: `direct_first` 또는 `selected_first`.

예시의 지침은 입력 형식을 위한 수기 예시다. 실제 사용자의 지침으로 보고하면 안 된다.

먼저 입력 검사와 요청 수 계획만 확인한다 (API 호출 없음):

```powershell
.\.venv\Scripts\python.exe -m experiments.korean_pilot prepare data/korean_pilot/P001-input.json
```

그다음 실제 생성:

```powershell
.\.venv\Scripts\python.exe -m experiments.korean_pilot prepare data/korean_pilot/P001-input.json --generate
```

원문 3개면 캐시 미스 기준 6번 생성한다. 주 앱의 실행 예산과 별도인 CLI 실험이며,
토큰·금액 상한을 보장하지 않는다. 기존 generator를 호출하므로 API timeout 등의
운영 보완 과제도 그대로 남는다. `.env`는 로컬에서 읽으며 키를 파일에 복사하지 않는다.

`--generate`가 없으면 생성하지 않는다. 양쪽 모델과 temperature=0을 동일하게 사용하지만,
temperature=0이 완전한 결정성을 보장하는 것은 아니다.

실패한 경우 같은 명령으로 재개한다. 완료된 조건별 출력과 A/B 배치는 보존한다.
한 번 생성한 참여자의 입력을 바꾸면 덮어쓰기를 거부한다. 새 실험은 새 `--root`에 만든다.
동일한 연구 폴더에서 여러 생성 프로세스를 동시에 실행하지 않는다.

## 4. 평가·다운로드·분석

평가자는 `pilot_review.py`에 **blind_packet.json만** 넣는다. 전달되는 정보는
원문·핵심 사실 목록·A/B 결과이며, 프롬프트와 조건 대응표는 포함하지 않는다.
출력 문체 자체로 방식을 짐작하는 가능성까지 없애는 완전한 맹검은 아니다.

모든 문서에서 선호를 선택해야 제출할 수 있다. 사실성/누락의 기본값은
**미평가**다. 미평가를 오류 없음이나 0개 누락으로 바꾸어 집계하지 않는다.

다운로드한 응답을 예를 들어 `data/korean_pilot/P001-ratings.json`으로 저장한다.
화면은 응답을 자동 전송하거나 서버 디스크에 저장하지 않으므로 **다운로드가 필요하다**.

```powershell
.\.venv\Scripts\python.exe -m experiments.korean_pilot analyze data/korean_pilot/P001 data/korean_pilot/P001-ratings.json
.\.venv\Scripts\python.exe -m experiments.korean_pilot summarize data/korean_pilot/P001/result.json data/korean_pilot/P002/result.json
```

분석기는 응답의 연구 ID와 패킷 해시가 동결한 파일과 일치하는지 확인하고 A/B를 복원한다.
해시는 실수로 변경/혼합된 파일을 찾는 장치이지 신원 인증이나 위조 방지 서명은 아니다.
같은 참여자 중복 집계와 다른 모델의 혼합 집계를 거부한다. `is_test=true`는 제외한다.

통계는 **참여자별** 선호 비율을 먼저 계산하고 동일 가중 평균을 낸다. 한 사람이
문서 세 개를 평가했다고 참여자 세 명으로 세지 않는다. `mean_selected_share`는
선택 지침을 고른 문서 수 / 전체 평가 문서 수의 사용자별 평균이다. 동률을 0.5승으로
바꾸지 않으며 동률·둘 다 불만족 건수를 따로 보고한다.
시간은 각 조건 원자료로 남긴다. 작은 표본에서 유의성이나 한국어 선호 복원율을 주장하지 않는다.

## 5. 아직 이 도구로 해결하지 않은 것

- 실사용자 모집·응답: 실제 사람이 해야 한다. 자동 생성하지 않는다.
- 반복 평가/중도 이탈 통계: 현재 파일에는 완료 응답만 있다. 모집·완료·중도 이탈 수를 별도 기록한다.
- 참여자가 같은 원문을 표현만 바꿔 가져온 경우: 자동 검사는 공백 정규화 후 동일 텍스트만 잡는다.
- 결과를 보고 방법을 바꾸면 그 자료는 개발용이 된다. 이후 최종 평가는 새 자료에서 수행한다.
- 금액/토큰 정밀 기록, 프롬프트 작성 과정 전체 UI, 여러 LLM 비교, GEPA 추가 기여 실험은 다음 단계다.
- 이 연구 도구는 로컬 실행이 기본이다. 원격 Streamlit에서 실행하면 업로드/응답은 해당 서버에서 처리된다.
  조건 대응표·원문·캐시·응답의 보관 위치와 삭제 시점은 연구 담당자가 관리한다.

## 검증 범위

`tests/test_korean_pilot.py`는 원문 재사용 차단, 배치 정보 분리, 실패 재개,
동결 입력 변경 거부, 응답 연결, 동률·미평가 보존, 테스트 응답 제외,
참여자 단위 집계, 평가 화면 제출을 API 대역으로 검사한다.
기능 회귀 테스트이며 실사용자의 효과 검증 결과가 아니다.
2026-09-19 확인: 신규 평가 도구 테스트 22개, 전체 무과금 테스트
**283 passed / 16 deselected**. `prepare`의 계획 출력과 `demo` 패킷 생성도
실제 명령으로 확인했다. 유료 API 생성 및 실사용자 응답 수집은 수행하지 않았다.
