# 길이 측정 v2 — 실행 전 판단 기준 (2026-10-01)

검사 함수의 길이 측정을 문장 수(v1)에서 원문 대비 단어 비율(v2)로 바꾸는 것이
사람 라벨과 더 맞는지 잰다. 이 문서는 **결과를 보기 전에** 커밋한다. 결과가
나온 뒤 기준을 바꾸지 않는다. 바꿔야 하면 바꾼 이유와 함께 별도로 적는다.

## 이미 본 것 (정직하게 적는다)

이 기준을 쓰기 전에 train+val+test 전체 5,379개로 탐색 측정을 한 번 했다.
같은 데이터로 임계값을 고르고 잰 값이라 낙관적이다.

| 측정 | 중앙값 short / normal / long | 최적 3구간 균형정확도 |
|---|---|---|
| 문장 수 (v1) | 1 / 2 / 3 | 0.489 |
| 단어 수 | 23 / 32 / 65 | 0.556 |
| 원문 대비 단어 비율 | 5.2% / 5.7% / 15.2% | 0.717 |

test 분할도 이 탐색에 들어 있었다. 따라서 아래 test 결과는 "처음 보는 데이터"가
아니라 "임계값 결정에 쓰지 않은 데이터"다.

MACSum 논문 주석 지침의 5–10% / 15–25% / 30–35% 는 분모가 원문 전체가 아니라
관련 텍스트 구간이다. 원문 전체 대비로 잰 위 실측과 맞지 않으므로 임계값으로
쓰지 않는다.

## 절차

- 임계값은 **train 분할에서만** 정한다. 방법: train 비율값의 1~99 백분위수
  격자에서 두 절단점 조합 중 train 균형정확도가 최대인 것. v1 도 같은 방법으로
  다시 맞춘 값(v1-refit)과 현행 YAML 값(v1-yaml)을 둘 다 보고한다.
- 평가는 **test 분할**에서 한다.
- 누수 검사: test 원문이 train 원문과 하나도 겹치지 않는지 코드로 확인한다.
  30쌍 실험(`heldout_comparison`)의 학습·채점 문서는 전부 test 에서 뽑았으므로
  임계값 결정에 들어가지 않는다 - 이것도 코드로 확인한다.

## 보고할 것

1. 균형정확도와 **클래스별 혼동행렬** (v1-yaml, v1-refit, v2).
2. **short 대 normal** 만 떼어 낸 2클래스 균형정확도. 0.60 미만이면 "v2 로도
   short·normal 은 구분되지 않는다"로 적고, 그 두 값을 가진 페르소나의 복원
   한계로 보고한다.
3. **topic 유무로 나눈** 결과. topic 이 있는 요약은 관련 구간이 원문 일부라
   비율이 작게 나올 것으로 예상한다. 판단 기준 없이 탐색으로만 보고한다.

## 판단 기준

- **주 기준:** test 길이 균형정확도가 v2 ≥ v1-refit + 0.10 이면 "v2 가 라벨과
  더 맞는다". 미달이면 v2 를 채택하지 않고 그 사실을 보고한다.
- 주 기준을 넘을 때만 v2 도메인(`summarization_v2.yaml`, `extends:`)으로
  30쌍 실험을 다시 돌린다.
- 30쌍 재실험의 ROUGE-L 은 **탐색 지표**다. D(v1) 대 D(v2) 페어드 승패와 평균차를
  보고하고, 부호검정 p < 0.05 가 아니면 "개선"이라고 쓰지 않는다.

## 범위

앱의 쌍 비교에서 두 후보는 같은 원문을 쓰므로 단어 수 순서와 비율 순서가 같다.
v2 의 효과는 절대 임계값을 쓰는 곳 - 페르소나 오라클 판정, 평가 함수의 위반
피드백, checks 점수 - 에서만 나타난다.

## 3단계 기준 (가): 지시는 v1, 측정만 비율 - 실행 전에 적는다

도메인 `summarization_ratio_check` - length 축의 지시문은 v1(문장 수) 그대로, 검사
함수만 `length_ratio`(임계값 0.068 / 0.127, 1단계에서 train 으로 정한 값). 후보
프롬프트가 v1 과 같으므로 생성은 대부분 캐시를 탄다.

- **주 기준:** 길이 축 학습 정확도가 v1(29/30) 대비 2명 넘게 떨어지지 않는다(≥ 27/30).
  미달이면 "측정만 바꾸는 것도 학습을 해친다"로 보고한다.
- **타당성 점검:** 사람 정답 요약(eval_reference)을 페르소나의 길이 값으로 채점했을
  때 만점 통과율을 v1 측정과 나란히 보고한다. 측정이 라벨과 맞다면 비율 쪽이 높아야
  한다 - 기준 없이 보고만 한다.
- D 의 ROUGE-L 은 프롬프트가 v1 과 같은 문구라 학습 결과가 같으면 바뀌지 않는다.
  탐색 지표로만 보고하고, 부호검정 p < 0.05 가 아니면 차이를 주장하지 않는다.
- checks_score 로 본 D 대 B+ 비교는 측정이 바뀌므로 다시 보고한다. 이 값은 최적화
  관련 지표가 아니라 페르소나 기준 충족도이며, 독립 지표는 여전히 ROUGE-L 이다.

"내보내는 프롬프트가 템플릿이 된다"는 제품 결정이 함께 걸린다.

## 4단계 기준 (나): 원문 길이로 목표 단어 수를 계산해 지시한다 - 실행 전에 적는다

(2026-10-03 작성. 구현·실행 전.)

### 무엇을 시험하나

2·3단계에서 갈라진 것을 다시 묶는다. **측정**은 비율(1단계에서 라벨과 맞음)을 그대로 쓰고,
**지시**는 비율이 아니라 이 원문에 대해 계산한 단어 수로 준다. 근거: 모델은 "원문의 5%" 를
따르지 못했지만(2단계), 요청한 단어 수는 0.99~1.06배로 따른다(`experiments/length_transfer.py`).

### 설계 초안

- **YAML** (`domains/summarization_v3.yaml`, `extends: summarization.yaml`, 현행 파일은 그대로 -
  규칙 10). length 값의 지시문에 자리표시자를 둔다. 비율은 1단계 train 의 topic 없는 중앙값:
  - short: `약 {source_words*0.053}단어로 아주 짧게 요약하라.`
  - normal: `약 {source_words*0.103}단어로 요약하라.`
  - long: `약 {source_words*0.154}단어로 상세하게 요약하라.`
  - 검사 함수는 `length_ratio` 그대로, 임계값도 0.068 / 0.127 그대로.
- **엔진** (`engine/`). 자리표시자 이름은 "원문"과 "단어"뿐이라 도메인 단어가 아니다 (규칙 1).
  - `Axis.instruction_for(value, source=None)`: `{source_words*R}` 를 `round(R × 원문 단어 수)`
    로 채운다. 단어 수는 공백으로 나눈 개수 - 언어·도메인을 가정하지 않는다.
  - `build_prompt(domain, combo, source=None)`: `generate()` 가 원문을 넘긴다.
  - **자리표시자가 없는 도메인은 지금과 글자 하나까지 같은 프롬프트**를 내야 한다 - 그래야
    캐시 키와 기존 결과가 그대로다. 모든 기존 도메인·축조합에 대해 테스트로 고정한다.
  - 원문 없이 부르면(`source=None`) 오류를 낸다. 조용히 비율 문구로 바꾸면 2단계의 실패를
    다시 만든다.
- **D 프롬프트** (`heldout_comparison`). 학습 문서 X 에서 선호를 배우고, 채점 문서 Y 의 단어
  수로 자리표시자를 채운 프롬프트를 Y 에 적용한다. 즉 D 는 이제 "프롬프트 텍스트"가 아니라
  "템플릿 + 채우는 코드"다 - 보너스 5 의 4차에서 예고한 제품 형태와 같다.
- **내보내기(앱)는 이번 단계에서 바꾸지 않는다.** 정적 프롬프트에 무엇을 적을지(사용자가 넣은
  원문 기준 숫자, 또는 숫자와 비율 병기)는 실험 결과를 보고 따로 정한다.

### 절차와 기준

1. **준수 점검 (먼저, 싸게).** 30쌍의 학습 문서 중 12개 x 세 값 = 36회 생성으로 후보의 원문
   대비 비율 중앙값을 잰다 (약 $0.005).
   - **관문:** 세 값 모두 사람 중앙값(5.3% / 10.3% / 15.4%)에서 ±3%p 안이고, 세 값의 순서가

### 등록하지 않은 관찰 (탐색 - 결론으로 쓰지 않는다)

|---|---|---|---|

B+ 는 여전히 문장 수로 지시받고("in 2 sentences or less"), D 만 채점 문서의 길이로 계산한

이긴다"고 쓰지 않는다. 다중 비교 보정도 하지 않았다.

### 남은 것

- **공정한 B+** (단어 수 지시를 받은 B+) - 위 탐색 관찰을 확인하거나 지운다. 기준을 먼저 적는다.
- **앱 연결** - 내보내는 프롬프트가 원문 길이에 의존한다. 앱은 사용자의 원문을 갖고 있으므로
  그 원문 기준 숫자를 넣을 수 있지만, 다른 글에 붙여 쓰면 숫자가 맞지 않는다. 제품 결정이다.
