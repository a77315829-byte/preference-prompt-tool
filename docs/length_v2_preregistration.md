# 길이 측정 v2 — 실행 전 판단 기준 (2026-10-01)

검사 함수의 길이 측정을 문장 수(v1)에서 원문 대비 단어 비율(v2)로 바꾸는 것이
사람 라벨과 더 맞는지 잰다. 이 문서는 **결과를 보기 전에** 커밋한다. 결과가
나온 뒤 기준을 바꾸지 않는다. 바꿔야 하면 바꾼 이유와 함께 별도로 적는다.

## 이미 본 것 (정직하게 적는다)

이 기준을 쓰기 전에 train+val+test 전체 5,379개로 탐색 측정을 한 번 했다.
같은 데이터로 임계값을 고르고 잰 값이라 낙관적이다.

| 측정 | 중앙값 short / normal / long | 최적 3구간 균형정확도 |
|---|---|---|
| 문장 수 (v1) | 1 / 2 / 3 | 0.489 |
| 단어 수 | 23 / 32 / 65 | 0.556 |
| 원문 대비 단어 비율 | 5.2% / 5.7% / 15.2% | 0.717 |

test 분할도 이 탐색에 들어 있었다. 따라서 아래 test 결과는 "처음 보는 데이터"가
아니라 "임계값 결정에 쓰지 않은 데이터"다.

MACSum 논문 주석 지침의 5–10% / 15–25% / 30–35% 는 분모가 원문 전체가 아니라
관련 텍스트 구간이다. 원문 전체 대비로 잰 위 실측과 맞지 않으므로 임계값으로
쓰지 않는다.

## 절차

- 임계값은 **train 분할에서만** 정한다. 방법: train 비율값의 1~99 백분위수
  격자에서 두 절단점 조합 중 train 균형정확도가 최대인 것. v1 도 같은 방법으로
  다시 맞춘 값(v1-refit)과 현행 YAML 값(v1-yaml)을 둘 다 보고한다.
- 평가는 **test 분할**에서 한다.
- 누수 검사: test 원문이 train 원문과 하나도 겹치지 않는지 코드로 확인한다.
  30쌍 실험(`heldout_comparison`)의 학습·채점 문서는 전부 test 에서 뽑았으므로
  임계값 결정에 들어가지 않는다 - 이것도 코드로 확인한다.

## 보고할 것

1. 균형정확도와 **클래스별 혼동행렬** (v1-yaml, v1-refit, v2).
2. **short 대 normal** 만 떼어 낸 2클래스 균형정확도. 0.60 미만이면 "v2 로도
   short·normal 은 구분되지 않는다"로 적고, 그 두 값을 가진 페르소나의 복원
   한계로 보고한다.
3. **topic 유무로 나눈** 결과. topic 이 있는 요약은 관련 구간이 원문 일부라
   비율이 작게 나올 것으로 예상한다. 판단 기준 없이 탐색으로만 보고한다.

## 판단 기준

- **주 기준:** test 길이 균형정확도가 v2 ≥ v1-refit + 0.10 이면 "v2 가 라벨과
  더 맞는다". 미달이면 v2 를 채택하지 않고 그 사실을 보고한다.
- 주 기준을 넘을 때만 v2 도메인(`summarization_v2.yaml`, `extends:`)으로
  30쌍 실험을 다시 돌린다.
- 30쌍 재실험의 ROUGE-L 은 **탐색 지표**다. D(v1) 대 D(v2) 페어드 승패와 평균차를
  보고하고, 부호검정 p < 0.05 가 아니면 "개선"이라고 쓰지 않는다.

## 범위

앱의 쌍 비교에서 두 후보는 같은 원문을 쓰므로 단어 수 순서와 비율 순서가 같다.
v2 의 효과는 절대 임계값을 쓰는 곳 - 페르소나 오라클 판정, 평가 함수의 위반
피드백, checks 점수 - 에서만 나타난다.
