# React 코드 스타일 비교: 현재 3축 지침의 새 과제 검증

2026-11-12. 현재 제품의 **React 코드 스타일 비교**가 내보내는 3축(코드 구성·스타일 관리·타입 작성) 지침을 대상으로 한다. 이전 [AI 답변 방식 4항목 비교](../coding_react_current/README.md)와 별도 실험이다. 유료 모델 API·GEPA·새 패키지는 사용하지 않는다. Codex 사용량은 소비된다.

## 무엇을 비교했는가

| 조건 | 입력 |
|---|---|
| 일반 요청 | 같은 환경·기능 요구·공통 규칙·출력 형식, 선호 절 제외 |
| 수동 프롬프트 | 일반 요청에 세 목표 조건을 같은 의미로 직접 작성 |
| 제품 프롬프트 | 실제 `service.final_prompt(..., language='en')` 반환문과 동일한 작업 요청 |

현재 화면 기본값인 영어 최종 지침을 수정 없이 보존했다. 한국어판, 템플릿, 팀 집계, 선택 UI, 유료 후보 생성·자동 재시도, GEPA는 평가하지 않는다. 목표를 이미 정했다고 가정하고 Estimator에 해당 값을 넣어 최종 지침을 얻었다. 실제 사용자가 선택한 자료가 없으므로 제품 문장의 ‘예시 선택에서 추정했다’는 설명을 연구 근거로 사용하지 않는다.

공개 Props와 strict 컴파일에 꼭 필요한 빈 배열·null·유니언·CSS 타입은 모든 방식의 공통 계약에서 허용했다. 영어 inferred의 ‘public boundaries only’와 실제 컴파일 요구의 충돌을 이 동일 작업 계약으로 해결했다. 불필요한 로컬 타입 반복까지 허용한 것은 아니다. 제품 원문 자체를 개선한 실험은 아니다.

## 새 과제와 설정

| 과제 | 코드 구성 | 스타일 관리 | 타입 작성 |
|---|---|---|---|
| 태그 편집기 | 한 파일 | 직접 값 | 추론 |
| 숫자 표 안정 정렬 | 한 파일 | 직접 값 | 명시 |
| 두 단계 이름 폼 | 한 파일 | 토큰 | 추론 |
| 온도 변환·단위 전환 | 한 파일 | 토큰 | 명시 |
| 암호 표시 전환 | 역할별 파일 | 직접 값 | 추론 |
| 텍스트 펼침·접기 | 역할별 파일 | 직접 값 | 명시 |
| 숫자 범위 선택 | 역할별 파일 | 토큰 | 추론 |
| 중첩 폴더 경로 탐색 | 역할별 파일 | 토큰 | 명시 |

8개 모두 이번에 작성한 합성 기능 과제다. 운영 코드에서 발견한 버그나 공개 벤치마크라고 표현하지 않는다. 세 방식이 각 과제를 풀어 첫 응답 총 24개를 비교한다. 8가지 조합을 한 번씩 다루지만 과제와 설정이 묶여 있으므로 조합별 반복 실험이나 개별 축의 인과 효과가 아니다.

각 과제에는 실제 스타일 관리 대상이 생기도록 동일한 패널 색상 2개·간격 2개를 요구했다. 외부 자료 없이 구현하며 `.ts/.tsx`와 일반 CSS side-effect import를 지원한다. CSS Modules·원격 리소스·escape와 제한 밖 at-rule은 모든 요청에서 명시적으로 제외한다. CSS 변수는 허용한다. JSDOM의 CSS 변수 계산 한계를 고려해 computedStyle을 정답 판정에 쓰지 않았다.

## 검사와 통제

- **타입:** 실제 TypeScript 5.9.3 strict와 설치된 React 타입으로 컴파일한다. 공개 `Component`·`Props`의 양방향 호환성을 확인하고 명시적 `any`·억제문 유무를 별도로 기록한다. 타입 추론 선호도 같은 strict 검사를 받는다.
- **동작:** React/ReactDOM 19.3.0을 JSDOM 20.0.3에서 실제 렌더링하고 입력·클릭·제출·props 갱신을 실행한다. 과제마다 새 마운트를 사용하는 7개 검사, 방식당 56개다. 실제 브라우저의 레이아웃·시각 효과·스크린리더·보안·서버는 검증하지 않는다.
- **세 조건:** 두 독립 검토자가 방식 이름·원 프롬프트·타입/동작 점수·서로의 평가를 보지 않고 동일한 [기준](rubric.json)으로 판정한다. 파일 수·테마라는 변수명·타입 표기 횟수만으로 의미적 충족을 결정하지 않는다. 일반 요청에는 주지 않은 선호를 따르지 않았다고 ‘지시 위반’이라 부르지 않는다.
- **사전 대조:** 정답 8개는 타입·56개 동작 검사를 통과했고, 타입은 맞지만 기능이 틀린 변이 8개를 모두 발견했다. 실행기 개발 대조는 22/22 통과했다. CSS 로딩 지원과 정상 로컬 parent/top 이름의 오탐, select 레이블의 옵션 텍스트 혼입을 생성 전에 보완했다.
- **보존:** 검사·과제·기준·입력을 생성 전에 해시로 고정했다. 조건별 독립 에이전트가 첫 답변을 저장한다. 생성자는 실행·검사·다른 조건 열람을 하지 않는다. 코드 검토 후 필요한 파일을 문자 그대로 적용하며 누락 코드 보완·오류 수정·성능 재시도는 하지 않는다. 미확인/실행 실패를 성공으로 바꾸지 않는다.

조건별 한 대화에서 8개를 생성하므로 응답끼리 상관될 수 있다. 정확한 모델 버전·디코딩 설정·토큰 비용은 별도 API 메타데이터로 제공되지 않았다. 검토와 VM/제한 로더는 완전한 OS 보안 샌드박스가 아니다. 원자료가 확정된 뒤 이 과제로 개선하고 다시 독립 최종 평가라고 보고하지 않는다.

총 24개 첫 응답의 50개 소스 파일(CSS 14개 포함)을 코드 수정 없이 적용했다. 미확정 전달·검사 오류·시간 초과는 없었고, 168개 동작 검사를 모두 통과했다. 생성 코드의 주석이나 타입 표기 수를 실제 컴파일 성공 대신 사용하지 않았다. 56개는 이름을 붙여 사전 고정한 동작 검사 수이며, 모든 가능한 입력과 브라우저 상태를 검사했다는 뜻이 아니다.

두 검토자의 72개 축별 판정 쌍 중 71개가 일치했다. **일반 요청의 텍스트 펼침(S007) 구성만 판정이 달랐다.** A는 CSS가 분리되고 남은 상태가 간단하다고 보았고, B는 props 변화에 따른 초기화·미리 보기·펼침 전환이 의미 있는 상태 책임이라고 보았다. 두 첫 판정을 유지했다. 이 응답은 두 검토자 모두 명시적 타입 목표에는 불일치로 보았으므로 세 축 동시 점수는 달라지지 않는다. 일반 요청에는 이런 목표를 주지 않았으므로 이를 지시 위반이나 기능 실패라고 부르지 않는다.

8개 응답에는 언어별 조건 범위 또는 필수 타입 예외에 관한 해석 메모가 남았다. 수동·제품의 세 축 일치 판정은 모두 같았다. 두 검토자 모두 수동 태그 편집기(S009)의 설명 `小규모`에 한자가 섞인 것도 별도 기록했다. 이는 세 축 점수에 포함되지 않으며 출력의 모든 문구가 완벽했다는 뜻도 아니다. 생성자가 테스트를 실행했다고 근거 없이 주장한 사례는 두 검토 모두 없었다.

이번 결과로 말할 수 있는 것은 **이미 정한 React 스타일 조건을 제품 지침으로 전달할 수 있었고, 이 제한된 과제에서는 기능을 해치지 않았다는 것**이다. 조건을 잘 적은 수동 지침도 같았으므로 더 좋은 코드를 만든다거나 수동보다 우월하다고 주장하지 않는다. 모두 통과한 작은 과제에서는 기능 정확도 차이를 관찰하지 못했다. 통계적 동등성, 실제 사람의 선호 추정, 선택 횟수의 충분성, 설정 편의성, 수정 시간 절감, 팀 채택 의향은 검증하지 않았다.

## 남은 개선과 다음 검증

제품 생성기는 이번 실험에서 변경하지 않았다. 현재 영어 inferred는 ‘필요한 공개 경계에만 타입을 명시’하는 짧은 표현이고, 한국어판에는 빈 배열·null 상태와 별도 이벤트 함수의 필요한 타입 예외가 더 구체적으로 있다. 이번에는 모든 조건에 같은 strict 필수 타입 계약을 덧붙였으므로, 이 계약 없는 임의 작업에서도 같은 결과가 난다고 일반화하지 않는다. 후속 변경에서는 영어·한국어의 필수 타입 예외와 역할별 분리의 범위를 먼저 맞추는 것이 좋다.

이 8개 과제는 이제 관찰한 자료다. 문구를 개선한 뒤 다시 독립 최종 평가라고 부르지 않으며 새 과제에서 확인해야 한다. 실제 기능은 유지하면서 알려진 선택의 전달을 제품의 검증 범위로 두고, 사람의 효과를 대신 입증한 것으로 확장하지 않는다. 유료 모델 API 호출은 0회이며, 운영 중인 AI 생성 기능 전체가 무료라는 뜻은 아니다.
