Revealed의 전체 분석·설계 기준서입니다. 문제 정의와 요구사항부터 유즈케이스, 화면, 처리 흐름, 클래스·함수, HTTP API, 데이터, 권한·운영, 검증까지 연결합니다. **주간보고는 10장의 부록**이며 본 문서를 주간보고용 요약으로 제한하지 않습니다.

현재 검증의 중심은 문서 요약의 명시 조건 전달과 내용 보존입니다. 코딩의 두 경로, 개인 보관함, 팀 기준, 인수인계, 템플릿·작업 공간도 전체 기능으로 명세합니다. 구현·기술 검증·사람의 미측정 효과를 구별합니다.

## 이번 React 코드 스타일 비교 결과

새 합성 기능 과제 8개씩, 일반·수동·제품의 독립 첫 답변 24개를 비교했습니다. 제품의 현재 기본 영어 최종 지침을 수정 없이 사용했습니다.

| 검사 | 일반 요청 | 수동 프롬프트 | 제품 프롬프트 |
|---|---:|---:|---:|
| 실제 strict TypeScript 검사 | 8/8 | 8/8 | 8/8 |
| ReactDOM/JSDOM 동작 검사 | 56/56 | 56/56 | 56/56 |
| 세 스타일 조건 모두 일치 | 1/8 | 8/8 | 8/8 |

두 독립 검토자의 세 조건 동시 점수는 같았습니다. 축별 판정 72쌍 중 1쌍의 해석 차이는 그대로 남겼습니다. **지정한 조건 전달은 확인했지만 수동보다 우위는 확인하지 못했습니다.** 일반 요청에는 스타일 조건을 주지 않았으므로 불일치를 지시 위반으로 보지 않습니다. 사람의 선호 추정·편의성·수정 시간은 검증하지 않았습니다.

실험은 유료 모델 API **0회**이며 Codex 사용량은 소비됐습니다. 실제 코드 실행 전에 검토했고 답변을 고치거나 재생성하지 않았습니다. 필수 타입 예외를 세 방식의 공통 계약으로 제공한 점, 영어/한국어 지침의 차이, 작은 합성 과제라는 한계를 [결과 보고서](evidence/react_style_current/README.md)에 남겼습니다.
