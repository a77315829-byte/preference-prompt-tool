# 10. 문서 관리와 보고 부록

## 10.1 문서 기준과 변경 범위

v1.1 문서 수정일은 2026-11-13이며 현행 정책 대조 기준은 microstone의 `cfd1fe4`다. v1.0은 `43024129a480c1fecb1c8013af5717b7003e3e34`와 당시 진행 중이던 요약 수정에 기초했다. source-evidence.json과 api-inventory.json은 v1.0 기준의 소스 위치·해시·스키마 원자료로 보존하므로 최신 전체 소스 해시라고 해석하지 않는다. 이번 수정은 UC 번호·79개 하위 목표·기능별 그림/명세·WBS 대응과 이미 반영된 요약 v2 정책의 설명을 갱신한다. 제품 코드나 고정된 실험 결과를 바꾸지 않는다.

문서 전용 브랜치의 공개는 로컬 실행 코드를 모두 원격에 반영하거나 앱을 배포했다는 뜻이 아니다. 이 범위를 혼동하지 않도록 분석·설계서, 실험 근거 사본, 그림·PDF 생성 소스만 해당 폴더에 게시한다. 기존 사용자의 앱 변경, .env, 사용자 DB, 원본 첨부 PDF는 포함하지 않는다.

## 10.3 이번 주 보고에 사용할 내용

보고 대상은 2026-11-13, 10주차이며 실적 범위는 11/06~11/12, 차주 계획은 11/13~11/19다. 이 절은 전체 분석·설계서의 부록이다. 기존 주간보고 양식과 제출 파일을 자동 교체한 것이 아니며 필요한 내용을 발췌한다.

| 영역 | 금주 실적 | 차주 계획 |
|---|---|---|

## 10.5 시연 시나리오와 확인 지점

시연은 격리된 예시 계정과 비민감 원문으로 한다. 첫째, 요약의 12,000자 입력 경계와 원문 유지를 확인한다. 짧은 완전 발췌에 여러 문장을 선택해 상한 충돌과 세 해결 분기를 보여 준다. 이어 원문 문장이 최소 분량보다 부족한 하한 충돌에서 가능한 축소·재서술을 확인한다. 원문 문장이 0개면 축소를 제공하지 않는다. 재사용 지침과 작업용 요청의 복사 범위도 확인한다.

둘째, 코딩 도움에서 직접 네 항목을 정하고 실제 지침 전문을 확인한다. React 코드 스타일 비교가 별도 경로임을 보여 준다. 예시 비교를 시작했다가 취소해 기존 선택이 유지되는지도 확인한다.

셋째, 지침을 보관하고 새 작업에서 재사용한다. 팀 기준과 다른 항목을 골라 새 작업용으로 저장하고 출처를 확인한다. 인수인계는 개인 저장, 계정 지정 공유, 지정 수신자의 이어받기와 첨부 권한 순서로 보여 준다.

넷째, 결과 표에서 타입·동작·조건을 분리해 읽는다. 실험의 한계와 수동 대비 동률을 함께 설명한다. 실제 모델 생성·GEPA는 비용과 실행 준비를 확인하지 않은 시연에서 자동으로 시작하지 않는다.

## 10.6 공개 근거의 재현 주의

evidence 아래의 코딩 실험 사본은 원래 파일 바이트를 보존한다. 내부 실행 스크립트와 완료 해시는 원래 benchmarks 경로를 전제로 한다. 문서 폴더 안의 사본만으로 바로 실행되는 설치 패키지가 아니다. 재현하려면 기준 코드·기존 의존성·원래 디렉터리 구조를 맞추고 읽기 전용 verify부터 수행해야 한다.

고정된 prepare/freeze/first outputs/evaluation을 덮어쓰지 않는다. 새 개선 실험은 새 폴더·새 과제로 만든다. publication-manifest.json은 공개 사본과 원본 경로의 SHA-256을 연결한다. 동일 바이트 확인은 결과를 재현 가능하게 검토하는 장치이며 성능 우위의 통계 검정은 아니다.

## 10.7 문서 완성 확인표

전체 목적·범위, 기능·비기능 요구, 액터·유즈케이스, 화면 상태, 알고리즘·시퀀스·활동, 실제 클래스·함수, API 계약, 물리 데이터 사전, 권한·오류·운영·변경, 검증과 한계를 포함한다. 요구 ID가 구현·검사로 이어지는지, 그림과 본문의 용어가 같은지, 미구현 기능을 현재 기능으로 쓰지 않았는지 확인한다.

PDF는 전체 페이지를 렌더링해 잘림·겹침·표 분할·그림 가독성을 점검한다. 정확한 쪽수는 최종 생성 결과에 기록하며 분량을 채우기 위한 빈 페이지를 넣지 않는다. 주간보고는 이 전체 문서에서 필요한 내용만 발췌한다.

## 10.8 WBS 변경과 명명 규칙

WBS v3.1은 중간보고서형 표·간트차트를 유지하고 5단계·16개 주요 작업에 UC 연결 열을 추가한다. UC-01-01 같은 하위 목표는 부모 UC-01의 구현 WBS를 상속한다. 그림을 상세화했다고 모든 하위 UC를 새 일정 행으로 늘리지 않는다. 기능명이 공유되는 부분은 일치시키되 설계·검증·보고 작업은 사용자 기능과 구별한다. 기능 범위·일정·담당이 실제로 달라지면 그때 해당 WBS 작업을 조정한다.

문서 상세화는 WBS 1.2와 2.3의 산출물 보완이다. 3.1~3.4는 구현 소유 범위를, 4.1은 출력 비교 실험을, 4.2는 기능·권한 회귀를 나타낸다. 이번 문서 수정만으로 보완 중인 제품 기능이나 새 원문 비교가 완료된 것으로 바꾸지 않는다. 세부 UC→WBS 대응은 2장과 WBS의 연결표에 함께 제공한다.
