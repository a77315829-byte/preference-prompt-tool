## 3. 학습률 - "0.5~1.0 에서는 결과가 거의 바뀌지 않는다"

5개 앱 도메인의 모든 축조합 x 시드 5개 x 잡음 3단계. 가상 사용자는 숨긴 값에 더 가까운
후보를 고르고, 잡음 확률만큼 반대쪽을 누른다. 실험용 선택기(8회 모두 묻는다) 기준 정확 복원:

| 학습률 | 잡음 0: 4 / 6 / 8회 | 잡음 10%: 8회 | 잡음 20%: 8회 |
|---|---|---|---|
| 0.1 | 0.667 / 0.905 / 1.000 | 0.790 | 0.543 |
| 0.25 | 0.667 / 0.905 / 1.000 | 0.790 | 0.543 |
| 0.5 | 0.667 / **1.000** / 1.000 | 0.829 | 0.590 |
| 0.75 | 0.667 / 1.000 / 1.000 | 0.829 | 0.590 |
| 1.0 | 0.667 / 1.000 / 1.000 | 0.857 | 0.590 |

0.5 는 실험으로 고른 값이 아니었다 - 그대로 인정한다. 다만 0.5~1.0 사이에서는 결과가
거의 같고(잡음 10% 의 8회차만 0.829~0.857), 0.25 이하는 6회차와 잡음 있는 경우에 조금
나쁘다. 1위 값을 고르는 것은 효용의 크기보다 부호에 좌우되기 때문으로 보인다.
**학습률은 이 구간에서 결과를 정하는 변수가 아니다**로 답한다.

## 6·7. 조기 종료와 잘못 누른 선택

앱의 선택기는 같은 질문(축과 두 값)을 다시 묻지 않고, 물을 게 없으면 끝난다. 이미 리뷰의
"adaptive stopping" 이 들어 있는 셈이다.

| 앱 선택기 (학습률 0.5) | 정확 복원 | 평균 회차 |
|---|---|---|
| 잡음 0 | **1.000** | **4.0** (코딩 3, AWS 2, 이메일 4.3, 요약·리뷰 4.7) |
| 잡음 10% | 0.676 | 4.1 |
| 잡음 20% | 0.505 | 4.1 |

잡음이 없으면 평균 4회로 전부 맞힌다. **그런데 한 번 잘못 누르면 회복하지 못한다** -
같은 질문을 다시 묻지 않기 때문이다. 잡음 10% 에서 앱은 0.676, 다시 묻는 실험용 선택기는
0.829 다. 리뷰의 "선택 오류를 너무 믿는다"는 지적이 수치로 확인된 셈이다.

그래서 넣었다.
- **이전 선택 수정** (`service.undo_choice`, `POST /api/sessions/<id>/undo`): 이력에서 마지막을
  빼고 재생한다. 선택기의 난수까지 그때로 돌아가 같은 질문이 다시 나오고, 후보는 캐시에서
  나오므로 모델을 다시 부르지 않는다. 결과 화면에서도 "마지막 선택 수정"으로 돌아갈 수 있다.
- **비슷해요** (`winner="tie"`): Bradley-Terry 에서 무승부를 "반쯤 이김"(목표 확률 0.5)으로
  다루는 흔한 근사를 썼다. 두 값의 효용을 서로 가깝게 당기고, 효용이 같을 때는 아무것도
  바꾸지 않는다. Davidson 모델 같은 정식 무승부 모델은 아니다.
- `a`/`b` 선택의 계산은 예전과 똑같다 (목표 1 또는 0). 기존 실험 결과는 바뀌지 않는다.

**확신도 기준 조기 종료("모든 축 confidence > 0.65 면 종료")는 넣지 않았다.** 값이 3개인
축의 confidence 는 24회 물어도 0.06 근처라 그 기준은 영영 충족되지 않는다
(CLAUDE.md 보너스 3). 지금의 "물을 질문이 없으면 종료"가 이미 평균 4회에 끝난다.

## 8. 팀 - 한 사람 한 표

예전에는 모든 팀원의 비교를 한 추정기에 넣었다. 같은 쪽을 12번 고른 한 사람이 반대쪽을
1번씩 고른 두 사람을 이겼다 (`tests/test_team.py` 의 새 테스트). 값별 확률을 사람마다 같은
무게로 평균하는 것으로도 부족했다 - 12번 고른 사람은 0.99, 1번 고른 사람은 0.62 로 확신해서
여전히 한 사람이 이긴다. 그래서 **축마다 각자의 1위 값으로 다수결**하고, 동률일 때만 평균
확률로 가른다. 화면의 "합의 필요" 표시는 그대로이고, 문구를 "한 사람 한 표"로 바꿨다.

## 5. MIN_AXIS_WEIGHT 0.05 - 측정하지 않은 이유

이 값은 GEPA 최적화가 쓰는 평가 함수의 축 가중치 하한이다. 보고서의 대표 수치(D)는 GEPA 를
쓰지 않은 조립본이라 이 값과 무관하다. 민감도를 재려면 GEPA 를 값마다 다시 돌려야 해서
비용이 들고, 최적화한 지표로 재는 순환 문제도 있다. 지금은 "대표 수치에 영향이 없는
하이퍼파라미터"로 설명하고 측정은 하지 않는다.

## 11·12. 사용자 노력 실험

가장 중요한 지적이고 동의한다. 도구(`experiments/korean_pilot.py`, `pilot_review.py`)와
참여자 안내서(`docs/korean_pilot/participant_kit.md`)는 준비돼 있고 직접 작성 시간·글자 수·
수정 횟수를 기록한다. 사람을 모으는 일은 팀이 해야 한다. 검토가 권한 20~30명은 파일럿
(5~8명)으로 절차를 확인한 뒤 정한다.

## 하지 않은 것

- confidence 함수 이름 변경: 화면·평가 함수·테스트 여러 곳이 쓰고 있어, 이름 대신 정의를
  코드 설명에 적었다. 발표 문구는 "확률이 아니라 효용이 한 값으로 쏠린 정도"로 한다.
- Information Gain 선택기, 선호 프로필 화면, 선호 재학습, 교차 모델 시험: 범위 밖.
