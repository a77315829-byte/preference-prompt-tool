# Revealed 수업 주간보고 관리

수업은 AI/SW융합프로젝트, 팀명은 Revealed, 팀원은 윤정우·고차원이다.
아래 형식은 2026-11-06 사용자 요청에 따라 다음 주간보고에도 유지한다.

## 버전 관리

- 현재 보고서는 **v0.6**다. 다음 전달본부터 v0.7, v0.8처럼 번호를 올린다.
- 전달한 이전 버전은 덮어쓰지 않는다. 보고일과 버전을 표지·바닥글에 표시한다.
- 보고일은 실제 수업에서 보고하는 날이다. 작성일과 다를 수 있다.
- PDF는 `output/pdf/Revealed_진행현황_주간보고서_v0.N.pdf`로 저장한다.
- 함께 갱신하는 발표대본은 같은 버전 번호와 해당 보고서의 쪽 번호를 사용한다.
- 향후 버전은 이 README의 최신 링크와 변경 이력을 함께 갱신한다.

## 본문과 백업

1. **기존 수업 템플릿을 유지한다.** 표지 색상·대학 표기·본문 서식과 순서를 임의로 재디자인하지 않는다. 표지 → `1. 프로젝트 일정 - WBS` → `2. 프로젝트 진행현황` → `[Backup]` 순서다.
2. 3쪽 **`2. 프로젝트 진행현황`의 기존 금주 실적/차주 계획 양식 안에 네 영역을 합친다.** 왼쪽은 금주 실적, 오른쪽은 차주 계획이며 각각 날짜 칸을 둔다. 하단의 `주요 이슈 및 의사결정 사항`과 `프로젝트 요청 사항`도 유지한다. 3열 표나 새로운 카드 양식으로 바꾸지 않는다.
3. 기능별 진행현황 4쪽을 그대로 본문에 두지 않는다. 개인 지침·사용 화면, 팀 공유·업무 연결, 설계·검증·운영, 기존 코딩 실험을 각 1~2줄로 한 장에 요약하고 자세한 사항은 백업으로 내린다.
4. 표지에는 보고일·주차·버전을 쓴다. 2쪽 WBS는 기존 단계·ID·작업·담당의 틀에서 1~15주차 전체와 보고일의 현재 위치를 표시한다.
5. 넘치는 기능 설명·실험 조건·과거 상세 계획·화면은 뒤쪽 백업으로 보낸다. 본 발표에서 백업을 모두 설명하지 않는다.
6. 설계문서는 별도 산출물이다. 현재 포함된 설계 그림은 요청대로 백업에 보존하지만 주간보고 앞부분에 상세 설계를 다시 싣지 않는다.
7. 완료한 구현, 검사로 확인한 결과, 미해결 문제, 제안·미실행 실험을 구분한다. 스타일과 기능 지표를 함께 보고한다. 요약에서 수치를 생략해도 독립 지표의 저하를 숨기지 않고 상세 수치·조건을 백업에서 함께 보존한다.
8. 사용자 요청에 따라 보고 산출물에는 ‘마이크로스톤 구현’이라는 표현을 사용하지 않는다. 수업 팀원에 다른 프로젝트의 참여자를 추가하지 않는다.

## 변경 이력

v0.6은 같은 보고 기간에 `c784808` 코드의 GitHub 브랜치·PR·컨테이너 CI 성공과 자료 의존 검사 3개의 로컬 재검증을 추가했다. 본 보고 1~3쪽, 현재 백업 4~14쪽, 과거 백업 15~32쪽이며 새 근거는 13~14쪽이다. 로컬 Python 1,355 통과·1 건너뜀과 CI 1,353 통과·3 건너뜀을 구분한다. CI에서 자료 부재로 빠진 3개는 이전 로컬 전체 검사 및 이번 별도 검사에서 통과했으며 중복 합산하지 않는다. Windows에서 빠진 심볼릭 링크 검사는 CI에서 통과했다. 실제 API 검사 16개는 제외했고 유료 모델 API 호출은 0회다. v0.5 PDF와 과거 실험은 보존했다.
