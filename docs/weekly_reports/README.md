# Revealed 수업 주간보고 관리

수업은 AI/SW융합프로젝트, 팀명은 Revealed, 팀원은 윤정우·고차원이다.
아래 형식은 2026-11-06 사용자 요청에 따라 다음 주간보고에도 유지한다.

## 버전 관리

- 현재 보고서는 **v0.9**다. 다음 전달본부터 v0.10, v0.11처럼 번호를 올린다.
- 전달한 이전 버전은 덮어쓰지 않는다. 보고일과 버전을 표지·바닥글에 표시한다.
- 보고일은 실제 수업에서 보고하는 날이다. 작성일과 다를 수 있다.
- PDF는 `output/pdf/Revealed_진행현황_주간보고서_v0.N.pdf`로 저장한다.
- 함께 갱신하는 발표대본은 같은 버전 번호와 해당 보고서의 쪽 번호를 사용한다.
- 향후 버전은 이 README의 최신 링크와 변경 이력을 함께 갱신한다.

## 본문과 백업

1. **기존 수업 템플릿을 유지한다.** 표지 색상·대학 표기·본문 서식과 순서를 임의로 재디자인하지 않는다. 표지 → `1. 프로젝트 일정 - WBS` → `2. 프로젝트 진행현황` → `[Backup]` 순서다.
2. 3쪽 **`2. 프로젝트 진행현황`의 기존 금주 실적/차주 계획 양식 안에 네 영역을 합친다.** 금주 실적은 `기능 개선`, `프롬프트 검증`, `팀 공유·권한 보완`, `분석·설계서 작성`으로 묶는다. 왼쪽은 금주 실적, 오른쪽은 차주 계획이며 각각 날짜 칸을 둔다. 하단의 `주요 이슈 및 의사결정 사항`과 `프로젝트 요청 사항`은 제목·테두리를 유지하고 **기본적으로 내용은 공란**으로 둔다. 반드시 의사결정·지원이 필요한 중요한 안건이 있을 때만 작성한다. 빈칸을 채우려고 일반 목표·검증 한계·상태를 반복하지 않는다. 3열 표나 새로운 카드 양식으로 바꾸지 않는다.
3. 본문 항목은 `1. 프로젝트 일정 - WBS`, `2. 프로젝트 진행현황` 두 개로 유지한다. 해당 주에 새로 수행한 작업만 진행현황에 요약하고 자세한 사항은 백업으로 내린다. 이미 발표한 기능 소개·이전 실험·지난주 실적은 반복하지 않는다.
4. 표지에는 보고일·주차·버전을 쓴다. 2쪽 WBS는 기존 단계·ID·작업·담당의 틀에서 1~15주차 전체와 보고일의 현재 위치를 표시한다.
5. 해당 주 실적의 상세 설명·실험 조건·화면과 다음 계획의 완료 기준만 뒤쪽 백업에 둔다. 이전 보고서의 백업 페이지는 복사하지 않는다. 이전 버전 PDF는 별도 기록으로 보존한다.
6. 분석·설계서는 별도 산출물이다. 이번 주 변경 범위만 백업에 정리하고 마지막 페이지에 GitHub 주소와 분석·설계서·WBS 위치를 명시한다.
7. 완료한 구현, 검사로 확인한 결과, 미해결 문제, 제안·미실행 실험을 구분한다. 스타일과 기능 지표를 함께 보고한다. 요약에서 수치를 생략해도 독립 지표의 저하를 숨기지 않고 상세 수치·조건을 백업에서 함께 보존한다.
8. 사용자 요청에 따라 보고 산출물에는 ‘마이크로스톤 구현’이라는 표현을 사용하지 않는다. 수업 팀원에 다른 프로젝트의 참여자를 추가하지 않는다.
9. 11/13 보고의 실적 기간은 **11/06~11/12**, 다음 계획은 **11/13~11/19**다. 11/06에 이미 보고한 내용은 다시 실적으로 싣지 않는다. 마감 뒤의 문서 개정은 최신 공유 위치로만 안내하고 해당 주 실적으로 소급 집계하지 않는다.

v0.5는 같은 보고 기간에 추가 검증 결과를 반영했다. 본 보고 1~3쪽, 현재 백업 4~12쪽, 과거 백업 13~30쪽이다. 두 계정 통합 18시나리오·Python 1,355개·프론트 123개 및 빌드 통과를 기록하고, v0.4의 일부 완료 두 항목을 확인 범위 내 완료로 갱신했다. Windows 심볼릭 링크 검사 1개 건너뜀과 유료 API 검사 16개 제외도 명시했다. v0.4 PDF와 기존 실험 결과는 보존했다. 발표대본 v0.5는 만들지 않았다. 후속 사용자 요청에 따라 수정 코드·검증 근거·보고서는 GitHub의 `microstone` 브랜치에서 함께 관리한다. 공개 서비스 배포와는 별개다.

## 변경 이력

v0.6은 같은 보고 기간에 `c784808` 코드의 GitHub 브랜치·PR·컨테이너 CI 성공과 자료 의존 검사 3개의 로컬 재검증을 추가했다. 본 보고 1~3쪽, 현재 백업 4~14쪽, 과거 백업 15~32쪽이며 새 근거는 13~14쪽이다. 로컬 Python 1,355 통과·1 건너뜀과 CI 1,353 통과·3 건너뜀을 구분한다. CI에서 자료 부재로 빠진 3개는 이전 로컬 전체 검사 및 이번 별도 검사에서 통과했으며 중복 합산하지 않는다. Windows에서 빠진 심볼릭 링크 검사는 CI에서 통과했다. 실제 API 검사 16개는 제외했고 유료 모델 API 호출은 0회다. v0.5 PDF와 과거 실험은 보존했다.
