# 코딩 선호 설정·재사용: 목표와 검증 범위

2026-11-10 · 사용자와 확정한 목표. 실제 참가자 평가는 아직 실시하지 않았다.

## 이번 단계에서 만들고 확인할 것

**개발자가 원하는 AI 답변 방식을 쉽게 정하고, 그 지침을 다음 작업에 재사용하도록 돕는다.**

일차 대상은 AI에 코딩을 요청하는 학생·개인 개발자다. 반복해서 요구하는 설명·주석·코드 구성·출력 방식을 저장해 사용한다. 직접 설정을 기본으로 제공하고, 설정 이름만으로 판단하기 어려우면 준비된 예시를 비교한다. 예시 비교는 최대 8회이며 적게 비교하고 남은 항목을 직접 확인해도 된다.

현재 핵심 경로는 환경 선택 → 네 답변 방식 확인 → 지침 생성 → 보관 → 새 작업에 재사용이다. 팀 기준 공유·GEPA·다른 언어 확대는 기존 기능을 유지하되 이번 편의성 평가의 필수 과제로 늘리지 않는다. 기존 TypeScript/React의 구성·스타일·타입 3항목 비교는 별도 경로다.

검증 주장은 다음처럼 구분한다.

| 주장 | 이번에 필요한 근거 |
|---|---|
| 선택한 설정을 정확히 전달한다 | 직접 설정·예시 비교·저장·재사용·내보내기의 값/지침 대조 |
| 새 작업에 안전하게 재사용된다 | 원본 보존, 옛 작업 요청 혼입 없음, 한 항목 변경 시 나머지 유지 |
| 사람이 혼자 설정하고 다시 쓸 수 있다 | 실제 참여자의 완료 여부·도움 요청·혼란 관찰 |
| 다시 쓰기가 매번 작성하기보다 편하다 | 동일 참여자의 재작성/재사용 비교, 순서와 과제 차이 통제 |
| 생성 코드가 더 정확하거나 수정 시간을 줄인다 | 별도의 여러 코드 과제·동일 조건 비교. 이번 목표의 필수 우위 주장은 아님 |

기능 정확도는 보호해야 할 조건이다. 기능을 망가뜨리면서 형식만 맞춘 결과를 성공으로 계산하지 않는다. 반대로 일반 프롬프트와 기능 검사가 동률이라고 선호 설정·재사용 기능의 가치가 없다고 결론 내리지 않는다.

## 1단계: 보조 에이전트와 자동 검사

부모 대화 이력 없는 검토자에게 검사 범위를 주고, 구현 담당자가 실패를 재현해 고친다. 기존 라이브러리와 별도 임시 DB를 사용한다. API 모델로 후보를 생성하는 작업은 비용 추정과 승인 없이는 추가하지 않는다.

1. **설정 반영:** 네 항목의 16개 조합에서 직접 설정과 4회/8회 예시 선택의 최종 규칙을 대조한다. 한 번 선택과 반복 일치의 표시, 환경 출처도 확인한다. 이는 조립 기능 검사이며 사용자 선호 추정 정확도가 아니다.
2. **저장·다시 쓰기:** 생성 → 저장 → 저장소 재개 → 다른 작업 요청과 복사 → 한 항목 변경 → 다른 이름으로 새 저장. 원본 지침과 출처가 유지되고 새 요청만 복사되는지 확인한다.
3. **화면 연결:** UI가 만드는 프로필을 실제 Python 검증기·저장 함수에 연결한다. 모의 HTTP와 실제 HTTP·로그인·클립보드 검사를 구분해 기록한다. 검사하지 않은 계층까지 성공이라고 보고하지 않는다.
4. **안내 점검:** 이후 별도의 에이전트에게 버튼명·정답 경로 없이 과제를 주어 문구와 이동에서 막히는 곳을 찾을 수 있다. 에이전트가 헤맨 지점은 개선 후보이며 사람의 사용성 점수가 아니다.

기술 단계의 완료 조건은 **정한 사례에서 선호 누락·옛 작업 혼입·원본 덮어쓰기 0건, 알려진 차단 오류 해소, 관련 회귀 검사 통과**다. 이 조건은 해당 검사 범위의 출시 기준이고 모든 환경에서의 무결함 보장이 아니다. 코딩 과제 평가를 추가하면 별도 정답 검사와 답변 방식 확인을 분리한다.

## 2단계: 소수 참여자의 첫 사용·재사용 관찰

우선 개발 경험이 있는 **3~5명**으로 탐색적 파일럿을 제안한다. 충분한 효과 검증 표본이라는 뜻이 아니다. 1인 첫 방문 약 20분, 재방문 약 5~10분을 준비 시간으로 잡되 실제 소요와 중단은 그대로 기록한다. 참여자 모집·동의·일정은 아직 정해지지 않았다.

첫 방문에는 다음 과제만 전달하고 경로를 먼저 가르치지 않는다.

> 평소 받고 싶은 코딩 답변 방식을 정해 주세요. 만든 지침에서 한 항목을 바꾸고, AI에 전달할 내용을 확인한 뒤 다음 작업에도 쓸 수 있게 보관해 주세요.

사용자가 직접 설정/예시 비교 중 필요에 따라 선택하게 한다. 모르는 항목을 억지로 확정시키지 않는다. 진행자가 대신 누른 작업은 도움 없이 완료한 것으로 기록하지 않는다.

가능하면 다음 날 같은 사람에게 아래 과제를 준다.

> 전에 만든 지침을 찾아서 이번에는 다른 작업 요청과 함께 사용할 내용을 만들어 주세요. 이전 저장본은 남겨 주세요.

첫 사용과 재사용의 시간을 따로 잰다. 현재 앱의 ‘실제 작업 비교’ 타이머는 최초 선호 선택 비용을 제외하므로, 여기서는 별도 관찰 시각을 사용한다. 두 과제의 길이가 다르므로 재방문이 빨랐다는 사실만으로 시간 절감 효과를 계산하지 않는다.

### 빈 기록지

| 기록 항목 | 첫 사용 | 재사용 |
|---|---|---|
| 익명 참여자 ID, 날짜, 버전/커밋, 환경 | 미측정 | 미측정 |
| 사용한 경로, 실제 비교 횟수 | 미측정 | 미측정 |
| 과제 시작 / 올바른 복사 완료 / 저장 완료 시각 | 미측정 | 미측정 |
| 휴식·시스템 대기 시간, 중단 여부·이유 | 미측정 | 미측정 |
| 완료 여부, 도움 요청·진행자 개입 횟수 | 미측정 | 미측정 |
| 잘못 누름·되돌아감·다시 입력한 선호 | 미측정 | 미측정 |
| 네 설정과 복사 내용 일치, 옛 작업 혼입 여부 | 미측정 | 미측정 |
| 원본 보존, 찾은 저장본이 본인 의도와 같은가 | 미측정 | 미측정 |

평가에는 공개된 연습 과제나 참여자가 공개 가능한 입력을 사용한다. API 키·비공개 업무 원문·개인정보를 기록지에 남기지 않는다. 참여 중단과 기록 삭제 요청을 받을 담당자를 사전에 정한다.

## 판단과 다음 단계

- 기능 오류가 있으면 먼저 수정한다. 여러 사람이 같은 문구에서 막히면 해당 화면을 고치고 다시 관찰한다.
- 직접 설정만으로 충분한 사람은 비교를 생략할 수 있게 유지한다. 예시 비교가 도움이 되는 대상과 상황을 기록한다.
- 저장본을 찾거나 다시 고치는 비용이 계속 크면 보관함·재사용 흐름을 우선 단순화한다. 새 기능 수를 늘리지 않는다.
- 실제 재작성 대비 절감 주장을 하려면 다음 단계에서 작업 쌍과 순서를 미리 정하고 비교한다. `재작성 먼저/재사용 먼저` 순서를 나누며, 효과 크기와 불확실성을 보고할 표본 계획은 파일럿 후 별도로 잡는다.
- 어제의 한 React 버그 3조건 비교(모두 9/9)는 기능 과제 수행 기록으로 유지한다. 사람의 설정·재사용 편의성 근거로 재해석하지 않는다.

회의 설명: **“이번 목표는 사용자가 원하는 답변 방식을 설정하고 다음 작업에도 전달하는 부담을 줄이는 것입니다. 설정이 유지되는지는 자동 검사로, 실제로 편한지는 사람의 사용 과정으로 나누어 확인하겠습니다.”**
