# 코딩 도움·UI/UX 중간 발표 리허설

작성일: 2026-10-15 · 브랜치: `codex/coding-ai-upgrade`

## 발표의 핵심

“코드 작성 규칙을 직접 설명하지 않아도, 같은 기능을 구현한 코드 예시를 고르면
선호하는 작성 방식을 추정해 재사용할 시스템 프롬프트로 정리하는 도구입니다.”

발표에서는 무료 데모의 조작 시연, 기존 실제 AI 실행 기록, 실제 사람 평가를 구분합니다.
선택으로 프롬프트를 만드는 것이며 모델을 새로 학습시키는 것은 아닙니다.

## 시연 전 준비

기존 의존성이 설치된 macOS 환경에서 저장소 루트의 터미널 두 개를 사용합니다.

```sh
# 터미널 1: API 서버
PPT_LIVE=0 .venv/bin/python api_server.py
```

```sh
# 터미널 2: 화면
npm run dev
```

- API 기본 포트는 8000이며 화면은 Vite가 출력한 주소로 엽니다. 5173이 사용 중이면 다른 포트일 수 있습니다.
- 화면에서도 무료 데모를 선택합니다. `PPT_LIVE=0`은 실제 호출 강제를 해제할 뿐, 모든 AI 기능의 과금을 막는 옵션은 아닙니다.
- 로그인은 본인의 시연용 계정을 사용합니다. 비밀번호나 API 키가 있는 파일을 화면 공유하지 않습니다.
- 코드 전체 보기와 결과 복사를 미리 확인하고, 발표 문서와 검증 기록을 별도 탭에 열어 둡니다.
- 발표 중 실제 생성·최적화·AI 다듬기 등 추가 유료 호출은 하지 않습니다.

## 시연 순서: 약 3~5분

| 순서 | 보여줄 화면 | 설명 |
| --- | --- | --- |
| 1 · 30초 | 로그인 → 카테고리 선택 | 담당은 코딩 도움과 UI/UX이며 기존 핵심·실험실 구분은 유지 |
| 2 · 30초 | 코딩 도움 → 기능 입력 | 실제 AI는 입력한 기능을 생성하고, 무료 데모는 준비된 과제로 비교 |
| 3 · 60~90초 | 코드 전체 보기 → A/B 선택 | 구조·스타일 관리·타입 작성 중 무엇이 다른지 설명 |
| 4 · 30초 | 비슷해요 → 이전 선택 수정 | 선호가 없거나 선택을 바꿀 수 있음을 설명 |
| 5 · 30초 | 결과 → 프롬프트 복사 | 선택한 스타일과 재사용할 코드 작성 규칙을 확인 |
| 6 · 60초 | 실제 AI 검증 기록·비용 표 | 데모와 별개로 실제 생성 코드의 검사 범위와 한계를 설명 |

입력 예: “버튼으로 숫자를 늘리고 줄이며, 초기값으로 되돌리는 카운터를 만들어주세요.”
무료 데모에 실제 표시되는 과제를 확인하고 설명합니다. 입력을 보냈다는 이유만으로
해당 임의 기능을 AI가 생성했다고 말하지 않습니다.
최종 결과까지의 선택 횟수는 화면 진행 상태를 따르며, 시간이 부족하면 사전에 완료한
결과임을 밝히고 보여줍니다. 선택하지 않은 결과를 방금 생성한 것처럼 소개하지 않습니다.

## 실제 AI 검증 기록 설명

- 서로 반대 취향의 가상 사용자 2개를 설정했습니다.
- 카운터 코드 A/B 6쌍에서 정해진 취향으로 선택하고, 결과 프롬프트를 다른 기능인 FAQ 생성에 적용했습니다.
- FAQ 코드 하나의 명시적 반환 타입 누락을 발견했습니다. 별도 AI 수정 후 총 14개 코드 결과가 타입·빌드·지정 동작·스타일 검사를 통과했습니다.
- 취향 2개와 최종 프롬프트의 선호 규칙 6개 일치를 확인했습니다.
- 처음부터 모두 통과한 결과가 아니며, 모든 입력의 기능 동일성이나 시각적 동일성을 보장하지 않습니다.
- 정해진 취향을 자동 선택한 PoC입니다. 실제 사람의 만족도 평가나 모델 학습 결과가 아닙니다.

[AI 수정 및 재검증 기록](history/2026-10-15_coding_ai_repair_attempt.md)을 사용합니다.
생성 원문과 평가 JSON은 Git에서 제외된 로컬 `data/`에 있으므로,
브랜치만 받은 환경에는 원문이 포함되지 않는다는 점을 인계합니다.

## 테스트와 비용 설명

- 전체 비유료 회귀 테스트: 850개 통과, 2개 데이터셋 부재로 건너뜀, API 표시 테스트 16개 제외.
- 프론트 빌드 통과, 복사 보조 로직 테스트 9개 통과. 이 9개를 브라우저 전체 검수라고 설명하지 않습니다.
- 기록된 호출 시도 21회 중 사용량 확인 18회: 입력 23,493토큰·출력 16,487토큰.
- 공식 단가 기준 확인분 계산 금액은 약 $0.01442입니다.
- 사용량이 없는 실패 3회와 미기록 실행은 제외했으며 실제 청구액이나 세션당 고정 가격이 아닙니다.

## 시연 중 문제가 생기면

- 서버 연결 실패: 오류를 보여주고 서버와 Vite 주소를 확인합니다. 연결 실패를 정상 생성으로 소개하지 않습니다.
- API 장애: 추가 유료 재시도를 반복하지 않고, 명시적으로 무료 데모 또는 저장된 검증 기록으로 전환합니다.
- 복사 권한 거부: 안내를 확인하고 프롬프트를 직접 선택해 복사합니다. 실패를 성공으로 설명하지 않습니다.
- 시간이 부족하면: 준비된 결과 화면과 기록으로 대체하며 사전에 준비한 자료임을 밝힙니다.

## 예상 질문과 답변

**왜 이 모델을 사용하나요?**
기본 설정은 `openai/gpt-6-luna`이며 정적 스타일 검사 실패 시 같은 모델로 한 번 수정하고,
계속 실패할 때만 `openai/gpt-6.1-sol`로 한 번 재생성합니다.
비용을 제한하는 설계이며, 모델 간 성능 우위나 절감률을 비교 실험으로 입증한 것은 아닙니다.

**사용자 취향에 맞는다는 것을 확인했나요?**
정해진 반대 취향의 자동 선택과 프롬프트 반영은 확인했습니다.
실제 사람이 만족하는지는 별도 평가가 필요합니다.

**UI 검수는 모두 끝났나요?**
최근 검수는 가입·로그인·로그아웃·오류 안내와 코딩 데모의 선택·수정·실제 복사,
320×568 및 844×390 일부 화면입니다.
실제 AI 로딩·실패 전환과 모든 카테고리·모든 화면 크기를 최신 상태에서 재검수한 것은 아닙니다.
[UI 검수 기록](history/2026-10-15_ui_final_qa.md)의 범위를 따릅니다.

**실제로 얼마 청구됐나요?**
확인된 토큰으로 계산한 금액만 집계했습니다. 제공업체 사용 내역과 청구서 대조는 남아 있습니다.

교수님께 전달할 설명은 [공유 문서](professor-update-2026-10-15.md),
실제 사람 평가는 [평가 진행안](coding-user-evaluation-kit.md)을 참고합니다.
이번 단계는 기존 증거를 발표용으로 정리한 것으로, 새 유료 호출이나 추가 UI 재검수,
커밋·푸시를 진행한 단계가 아닙니다.
