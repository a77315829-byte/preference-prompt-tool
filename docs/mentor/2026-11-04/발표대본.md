# 5분 발표 대본

2026-11-04 기준. 본문 1~16장 300초이며, 17~21장은 질의응답용 상세 화면입니다.
WBS와 R&R은 팀 합의 전 계획안입니다. PPT 발표자 노트에도 같은 대본을 넣었습니다.

## 1. 사용자 선호 기반 맞춤형 프롬프트 생성 도구 (10초)

사용자 선호 기반 맞춤형 프롬프트 생성 도구를 소개하겠습니다. 개인의 AI 사용 방식을 팀 기준과 연결하고, 다음 담당자에게 작업과 자료를 넘기는 도구입니다.

## 2. 누구의 어떤 문제를 해결하나요? (25초)

대상은 AI로 문서 정리와 개발을 하는 개인과 작은 개발팀입니다. 같은 선호를 반복해서 설명하고, 서로 다른 결과 형식을 다시 고치며, 담당자 교체 때 맥락을 재설명하는 문제를 줄이려 합니다. 실제 시간 절감 효과는 앞으로 검증하겠습니다.

## 3. 개인 선호와 팀 기준을 연결하는 흐름 (20초)

예시를 비교하거나 환경을 직접 정해 개인 지침을 만듭니다. 보관함에 저장하고 팀 기준과 다른 항목을 확인합니다. 항목별로 따를 쪽을 골라 작업용을 만들고, 사용한 지침과 작업 맥락을 다음 담당자에게 넘깁니다. 원본은 그대로 유지합니다.

## 4. 처음 사용하는 사람의 시작점 (15초)

첫 화면은 문서 요약, 코딩 도움, 팀 업무 정리로 정리했습니다. 세 번째는 새 선호 추정 분야가 아니라 인수인계 메뉴입니다. 보관함과 팀 초대에도 바로 접근할 수 있습니다.

## 5. 원하는 개발 환경으로 지침 만들기 (20초)

코딩에서는 언어와 프레임워크를 고르거나 직접 입력하고 설명, 주석, 구성 선호를 정합니다. 결과 지침을 저장해 재사용합니다. 이는 설정에 따라 문장을 조립하는 기능이며, 모든 언어의 코드 품질 검증은 아닙니다. 기존 React 비교도 유지했습니다.

## 6. 내 선호 보관함 (15초)

보관함에서는 요약과 코딩 지침을 저장하고 이름이나 내용을 고쳐 새 작업에 씁니다. 작업 원문과 실행 결과는 보관함에 자동 저장하지 않습니다. 인수인계 맥락은 별도로 직접 저장합니다.

## 7. 팀 만들기와 초대로 참여하기 (20초)

팀 이름과 비교할 분류를 정하고 초대 링크로 참여합니다. 예시 선택만으로 팀 기준이 바뀌지는 않고 마지막에 합치기를 눌러야 반영됩니다. 다수 선호를 모은 것이며 전원 합의가 완료된 것은 아닙니다.

## 8. 항목별로 선택하는 이번 작업용 지침 (25초)

개인 선호와 팀 기준이 다른 부분을 표로 보여줍니다. 파일 구성은 팀 기준, 타입 설명은 개인 선호처럼 항목별로 고를 수 있습니다. 조합은 다른 이름으로 저장합니다. 직접 입력한 임의 언어 지침을 React 팀 기준과 자동 조합하는 것은 후속 범위입니다.

## 9. 조합의 출처와 변경 이력 확인 (20초)

저장한 조합에는 항목별 개인·팀 출처를 남깁니다. 나중에 선택을 바꾸면 전후를 비교하고 원하는 것만 되돌려 새 항목으로 저장합니다. 원래 작업용부터 새 조합과 복원본의 연결을 보고 이전 항목도 바로 열 수 있습니다.

## 10. 작업 맥락과 자료를 함께 인수인계 (30초)

인수인계에는 목적, 진행, 남은 일, 링크, 사용한 프롬프트와 파일 원본을 담습니다. 지정된 팀원이 로그인해 이어서 맡고 진행을 갱신합니다. 파일은 하나당 5MB, 현재 10개, 과거 첨부를 포함해 총 20MB입니다. 링크만으로 권한이 생기지 않고 팀 초대와도 별개입니다.

## 11. 템플릿과 요청문 점검 (15초)

업무별 템플릿 24개에서 시작하고, 요청문 점검과 업무 지침 만들기도 이 메뉴에서 엽니다. 구조 점검은 무료이고 AI 수정안은 실제 생성 모드가 필요합니다. 표현 점검이 곧 결과 품질 보장은 아닙니다.

## 12. 기존 기능과 이번 확장 범위 (20초)

문서 요약과 React 비교, 선호 추정과 프롬프트 생성은 유지했습니다. 보관함, 팀 참여 안내, 항목별 조합과 이력, 언어 직접 설정과 파일 인수인계를 확장했습니다. AWS는 현재 서비스에서 제외했습니다. 기능 구현과 실제 효과는 구분하겠습니다.

## 13. 다음 단계는 실제 사용 효과 검증 (20초)

다음은 작은 팀 두세 곳의 파일럿을 제안합니다. 같은 과제에서 직접 작성한 요청문과 저장한 지침을 비교해 시간과 수정량을 기록합니다. 인수인계는 다음 행동을 시작하는 시간과 추가 질문을 보겠습니다. 모집과 일정은 아직 미확정입니다.

## 14. WBS: 앞으로 4주 개선·검증 계획 (20초)

오늘 기준 4주 계획안입니다. 첫 주는 사용 흐름과 질문 정리, 둘째 주는 개인 지침 비교, 셋째 주는 팀 기준과 인수인계 검증, 넷째 주는 피드백 반영과 보고입니다. 실제 마감과 멘토 의견에 맞춰 확정하겠습니다.

## 15. R&R: 개발 총괄과 검증 역할 배정안 (15초)

개발과 통합은 제가 중심으로 맡습니다. 다른 팀원에게는 기능 검증, 처음 사용자 관찰, 인수인계 점검, 일정과 발표 정리를 제안합니다. 수행 실적이 아닌 배정안이며, 실제 진행은 산출물로 보고하겠습니다.

## 16. 멘토님과 확인할 내용 (10초)

멘토님께는 우선 좁힐 대상 업무, 개인과 팀 기준의 선택 안내, 인수인계 효과의 검증 기준에 조언을 부탁드리고 싶습니다. 감사합니다.
