# 5분 발표 대본 - 최신 UI 및 GEPA 반영

본문 1~20장, 총 300초. 21~27장은 질의응답용 부록입니다.
WBS와 R&R은 팀 합의 전 계획안입니다. 이 대본은 업데이트 PDF의 페이지 순서에 맞췄으며 이전 PPT는 갱신하지 않았습니다.

## 1. 사용자 선호 기반 맞춤형 프롬프트 생성 도구 (10초)

개인이 원하는 AI 답변 방식을 저장하고, 팀 기준과 연결해 다음 담당자에게 작업과 자료를 넘기는 도구입니다.

## 2. 누구의 어떤 문제를 해결하나요? (20초)

대상은 AI로 문서와 코드를 만드는 개인과 작은 개발팀입니다. 같은 선호를 반복해서 설명하고, 담당자가 바뀔 때 맥락을 다시 설명하는 수고를 줄이려 합니다. 실제 효과는 앞으로 검증합니다.

## 3. 개인 선호와 팀 기준을 연결하는 흐름 (15초)

예시를 골라 개인 지침을 저장하고 팀 기준과 비교합니다. 다른 항목은 따를 쪽을 골라 작업용으로 조합합니다. 원본을 유지하면서 지침과 맥락을 다음 사람에게 넘깁니다.

## 4. 처음 사용하는 사람의 시작점 (10초)

시작점은 문서 요약, 코딩 도움, 팀 업무 정리입니다. 팀 업무 정리는 작업 인수인계로 연결됩니다.

## 5. 개발 환경과 예시를 고르는 코딩 화면 (20초)

코딩은 언어와 도구를 버튼으로 고릅니다. FastAPI와 Spring Boot에는 API 코드 비교 예시가 있습니다. 다른 도구는 기본 문법 예시임을 안내합니다. 준비 예시를 고르는 기능이며 코드 품질 검증은 아닙니다.

## 6. 내 선택 요약과 실제 프롬프트를 구분 (15초)

왼쪽은 내가 고른 방식, 오른쪽은 실제 프롬프트입니다. 복사해 AI 대화창에 붙이고 작업 요청을 덧붙입니다. 보관함에는 재사용할 지침만 저장합니다.

## 7. 내 선호 보관함 (10초)

보관함에서 요약·코딩 지침을 찾아 수정하고 다시 씁니다. 작업 원문과 실행 결과는 자동 저장하지 않습니다.

## 8. 팀 만들기와 초대로 참여하기 (15초)

팀을 만들고 초대로 참여합니다. 마지막에 선호 합치기를 눌러야 반영됩니다. 다수 선호의 집계이며 전원 합의 완료와는 구분합니다.

## 9. 항목별로 선택하는 이번 작업용 지침 (20초)

개인과 팀 기준이 다른 항목을 보여줍니다. 파일 구성은 팀 기준, 타입 설명은 개인 선호처럼 고를 수 있습니다. 원본은 유지하고 새 이름으로 저장합니다. 임의 언어와 React 팀 기준의 자동 조합은 후속 범위입니다.

## 10. 조합의 출처와 변경 이력 확인 (10초)

조합의 출처와 전후 차이를 확인합니다. 일부만 되돌려 새 항목으로 보관하고 이전 작업용도 바로 엽니다.

## 11. 팀 업무 정리: 넘길 일과 받은 일부터 (15초)

넘길 작업과 받은 작업을 카드로 나눴습니다. 먼저 내 기록으로 저장하고 받을 계정을 지정합니다. 링크만으로 열람 권한이 생기지는 않습니다.

## 12. 작업 맥락과 자료를 함께 이어받기 (20초)

목적과 현재 진행, 남은 일을 색으로 구분했습니다. 링크·사용한 프롬프트·파일도 함께 남깁니다. 지정된 팀원이 이어서 맡아 진행을 갱신하고 이전 기록을 확인합니다.

## 13. 템플릿과 요청문 점검 (10초)

업무별 템플릿 24개에서 시작합니다. 구조 점검은 무료이고 AI 수정안은 실제 생성 모드가 필요합니다.

## 14. 기존 기능과 이번 확장 범위 (10초)

요약과 React 비교 기반을 유지하고 보관함, 팀 조합, 언어 선택과 파일 인수인계를 확장했습니다. AWS는 제외했습니다.

## 15. GEPA: 선택한 선호를 평가 기준으로 연결 (25초)

GEPA는 여러 과제에서 답변을 평가하고 실패 피드백으로 프롬프트를 개선합니다. 개인 선호가 평가 기준이 됩니다. 기존 요약과 React에는 실제 모델 모드의 선택적 최적화 경로가 있습니다. 무료 데모와 새 언어 화면에는 아직 연결하지 않았습니다.

## 16. GEPA 확장 계획: FastAPI부터 작게 검증 (25초)

새 코딩 화면은 FastAPI부터 연결하는 계획입니다. 기능 검사와 선호 평가를 먼저 만들고, 개선에 쓰지 않은 과제와 사용자 비교로 확인합니다. 비용과 시간도 기록합니다. 개선안은 원본과 비교해 새 항목으로 저장하도록 설계할 예정입니다.

## 17. 다음 단계는 실제 사용 효과 검증 (15초)

작은 팀 두세 곳의 파일럿을 제안합니다. 같은 과제의 작성·수정 시간과 결과 선호를 비교합니다. 인수인계는 다음 행동까지의 시간과 추가 질문을 기록합니다.

## 18. WBS: 앞으로 4주 개선·검증 계획 (15초)

4주 계획안입니다. 사용자 관찰, 개인 지침 비교와 FastAPI 평가 준비, 인수인계 점검과 GEPA 시범 검토, 결과 정리 순서입니다. 실제 실험 범위는 준비 후 확정합니다.

## 19. R&R: 개발 총괄과 검증 역할 배정안 (10초)

구현은 제가 총괄하고 팀원에게 검증과 관찰, 일정 정리를 제안합니다. 수행 실적이 아닌 합의 전 배정안입니다.

## 20. 멘토님과 확인할 내용 (10초)

우선 좁힐 대상 업무와 개인·팀 기준의 안내 방식, 효과 검증 기준에 조언을 부탁드리고 싶습니다. 감사합니다.
