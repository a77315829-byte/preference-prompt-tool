# 2026-11-17 주간 구현 검증

주간보고서 v0.9의 11/13~11/19 계획 중 React 한·영 지침 정렬, 비교 세션 접근·만료 정책, 화면 복구를 구현했다. 새 출력 비교는 [별도 파일럿](../../../benchmarks/weekly_validation_2026_11_17/README.md)에 보존한다. 유료 모델 API는 사용하지 않는다.

## 검증 범위

| 구분 | 확인한 내용 |
|---|---|
| API 소유권 | 두 익명 브라우저·두 계정을 분리해 조회/선택/되돌리기/최적화/팀 반영을 확인한다. 세션 ID만 전달하면 공통 404로 거절한다. |
| 인증 전환 | 같은 익명 브라우저의 로그인 후 비교 유지, 다른 계정 전환·로그아웃·쿠키 재전송·인증 만료를 확인한다. |
| 시간·동시성 | 정확히 TTL에 도달한 시점의 접근, 로그아웃 중 진행하던 선택, 늦게 끝나는 최적화가 데이터와 보고서를 복구하지 않는지 확인한다. 최적화 호출은 모형 함수로 대체한다. |
| React 지침 | 3축의 8조합에서 한·영 기능 우선·파일 분리·필수 타입 예외를 확인한다. 이전 기본 생성문 전체와 일치하는 저장본은 계속 인식하고, 임의 수정문은 추측하지 않는다. |
| 프론트 | 401/403/404 정리와 500 상태 유지, 창 복귀·TTL 자동 정리·늦은 응답 무시, 로그인 후 저장 제목 유지 등 기존 UI 검사를 실행한다. |
| Chromium | 실제 요약 완료, 다른 익명 브라우저 접근 거부, 로그인 승계/다른 계정 접근 거부, 로그아웃 후 원문 정리, 클릭 없이 TTL 정리, 실제 React API v2의 한·영 지침을 확인한다. |

브라우저 검사는 임시 DB·합성 계정·36초 TTL·로컬 서버에서 실행했다. 외부 요청을 차단했으며 페이지 오류와 외부 요청 목록도 함께 보존한다. 요약 결과 화면과 폐기 후 화면은 `results/`의 PNG에 있다. 브라우저 검사는 기존 저장 지침 안내 문구 보완 전 실행했으며, 그 보완은 뒤의 전체 프론트 검사와 이전 저장본 API 검사에서 확인한다.

## 결과와 재현

수정 후 최종 결과를 `collect_results.py`로 읽어 [validation.json](results/validation.json)에 수집했다. 실패·오류가 남아 있으면 이 수집기는 결과를 통과로 발행하지 않는다. 전체 로그와 JUnit 원자료, 브라우저 결과, 변경한 제품·검사 소스의 SHA-256을 함께 보관한다.

| 실행 | 최종 결과 | 근거 |
|---|---|---|
| Python 전체 회귀 | 1,433 통과·1 건너뜀·API 16개 제외 | [로그](results/full-offline.log), [JUnit](results/full.xml) |
| 프론트 전체 검사 | 136 통과·실패 0 | [로그](results/frontend-final.log) |
| 프로덕션 빌드 | 성공, 기존 큰 번들 경고 유지 | [로그](results/build.log) |
| 실제 Chromium | 6/6, 페이지 오류·외부 요청 0 | [결과](results/browser.json) |
| 문서 연결·WBS | 로컬 링크 누락 0, 16작업 ID·이름·계획일 유지 | [확인](results/document-checks.json) |

건너뛴 1개는 `test_symlink_outside_build_is_not_served`다. 현재 Windows 권한에서 심볼릭 링크를 만들 수 없어 실행되지 않았으며 통과로 세지 않는다. 실제 모델 API 검사 16개는 비용 없는 검증 조건에 따라 제외했다. [실행 환경 제한 기록](results/pytest-offline-guard.json)도 보존한다.

```powershell
.venv/Scripts/python.exe -X utf8 docs/verification/2026-11-17/offline_python.py pytest -vv --tb=short --junitxml=tmp/weekly-20261117/full.xml
node --test "frontend/src/**/*.test.js"
npm run build --prefix frontend
```

`offline_python.py`는 `.env` 로딩을 끄고 모델 자격 증명·live 설정을 제거하며 임시 DB를 지정한다. Python 프로세스의 외부 소켓 연결을 차단하고 `-m "not api"`로 실제 API 검사를 제외한다. 하위 검사 프로세스는 제거된 환경을 상속한다. 이를 운영 배포의 네트워크 격리나 모든 하위 프로세스의 시스템 수준 샌드박스라고 주장하지 않는다.

실제 브라우저 재현은 이 래퍼의 `server` 모드와 `browser.cjs`를 사용한다. 스크립트 상단의 기존 Playwright/Chromium 절대 경로는 현재 Windows 환경에 맞춘 값이다. 새 패키지를 설치하지 않았다. 브라우저 검사는 짧은 TTL을 전제로 하므로 `VERIFY_SESSION_TTL_HOURS=0.01`을 서버 실행 전에 설정해야 한다. 저장된 결과와 달리 재실행은 새 임시 DB에서 해야 한다.

## 발견하고 수정한 회귀

- 정확한 만료 경계에서 부동소수점 뺄셈에 의존하던 조건을 `now >= started + TTL`로 맞췄다.
- 비교 초안을 다시 저장할 때마다 복귀 조회가 생기던 효과를 최초 복귀 ID에 한정했다.
- 익명에서 로그인할 때 컴포넌트가 교체되어 저장 제목이 사라지던 문제를 고쳤다. 기존 계정에서 나갈 때만 폐기한다.
- v2 지침 도입으로 v1 저장 지침을 수정문으로 오인하던 문제를 고쳤다. 전체 문장 일치로만 구버전을 인식하며 새 조합에서 현재 지침을 사용한다는 안내를 추가했다.
- 오래된 HTTP 테스트의 쿠키 없는 호출을 그대로 두면 비교 소유권을 표현하지 못했다. 익명 비교 쿠키는 유지하되 인증은 명시한 계정 쿠키로 전달하도록 도우미를 수정했다. 가입 쿠키를 모든 호출에 자동 적용해 비로그인 검사가 로그인으로 바뀌는 문제도 고쳤다. 실제 보안 검사는 독립된 두 CookieJar를 사용한다.

초기 네트워크 제한 환경의 연결 실패, 중단한 진단 실행, 수정 전 회귀 실패를 최종 통과에 합산하지 않았다. 최종 전체 검사는 호환성과 테스트 도우미 수정 후 다시 실행했다.

## 해석의 한계와 연결

기술 검사는 명시한 경로와 입력에서 동작을 확인한 것이다. 완전한 보안 감사·운영 배포 검증·실제 모델 API 성공률·사람의 편의성이나 시간 절감을 입증하지 않는다. 기존 Vite 번들 크기 경고와 운영 배포 점검은 별도 후속 사항이다. 이미 시작된 외부 모델 호출을 중간 취소하는 기능은 추가하지 않았다.

기존 보고서 PDF와 고정된 과거 실험은 덮어쓰지 않는다.

파일 해시는 실행 당시 Windows 작업 트리를 기준으로 한다. 기술 검증에는 CRLF를 LF로 정규화한 소스 해시도 병기한다. 출력 파일럿의 엄격한 원본 해시 중 `engine/domain_loader.py`와 `engine/generator.py`는 Git 체크아웃 줄바꿈에 따라 달라질 수 있으며, 현재 Git blob과의 차이가 줄바꿈뿐임을 확인했다. 그 실험의 고정 해시를 바꾸지 않았다. 다른 OS에서 정확한 바이트 재현까지 완료했다고 주장하지 않는다.
