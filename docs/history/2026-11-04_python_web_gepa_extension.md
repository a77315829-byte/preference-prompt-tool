# 2026-11-04 환경별 GEPA 확장 2차: Flask·Django

## 연결한 범위

Python/Flask·Python/Django를 기존 GEPA 실행·전후 비교·직접 확인·새 항목 저장·재사용 흐름에 연결했다. 현재 지원은 FastAPI·Flask·Django·Spring Boot와 JavaScript/TypeScript의 React·Express 총 8조합이다. 기존 React 비교와 원본 지침·팀 기준은 유지한다.

`PPT_PYTHON_WEB_GEPA_LIVE=1`로 두 환경만 독립적으로 켤 수 있다. 미지정 시 `PPT_LIVE`를 따른다. 다른 환경과 같은 모델·캐시·하루 한도·동시 작업 제한·소유권·서버 결과 기반 저장을 사용한다. 새 라이브러리·DB migration·`engine/` 수정은 없다.

## 과제와 검사

- `python_web_evaluation.py`는 프레임워크마다 개선용 2개·후보 선택용 2개·별도 확인용 2개를 분리한다. 평가 버전은 `python-web-ast-v2`이며 환경별 캐시를 사용한다.
- Flask는 import한 Flask의 app 생성, GET 경로 데코레이터, `request.args` 정수 입력, 누락·비정수·음수의 JSON 400 응답과 정상 계산값을 확인한다.
- Django는 실제 `urlpatterns`의 `path`, `require_GET` 함수형 뷰, `request.GET`, `JsonResponse`의 400 응답과 정상 계산값을 확인한다. 제공된 답변 안의 URL/뷰 분리·import 별칭·계산 함수를 다룬다.
- `python_web_ast.py`는 제한된 AST만 해석한다. 생성 코드를 import/exec하지 않고 프레임워크 패키지도 불러오지 않는다. 노드 수·깊이·명령 수와 허용 구문을 제한한다. 외부 파일을 읽거나 실제 모듈 경로를 해결하지 않는다.
- 변경 부분 답변은 제공된 기존 뷰의 함수 또는 마지막 return 맥락에서 확인한다. 필요한 import가 함께 있어도 부분 수정으로 인식하며, 필요한 계산 함수가 같은 블록/별도 블록에 있는 경우를 검사한다.
- 설명/출력 형식만 자동 선호 점수에 포함한다. 주석·역할 구성은 실제 전후 답변을 보고 사람이 판단한다. 이 판단은 새 후보에 함께 저장할 수 있다.

실제 서버·HTTP·프로젝트 설정·미들웨어·DB·보안·사용자 만족도 검증은 아니다. Django REST Framework·클래스 기반 뷰는 지원하지 않으며, 다른 올바른 표현도 허용 구문 밖이면 자동 확인에 실패할 수 있다. 제한된 과제 점수 상승을 일반적인 개선 효과로 해석하지 않는다.

## 검증

- 관련 Python 검사 77개, 프론트 검사 83개, Vite 빌드가 통과했다. Python 새 검사 14개는 두 환경의 정상/오류 경로, 입력·계산 오류, 부분 수정, URL/뷰·함수 분리, 가짜 import, 문법 오류와 실행 부작용 방지를 포함한다.
- 실제 설치된 GEPA 엔진에 테스트 모델을 연결해 각 환경의 탐색·별도 과제·캐시·원본 고정·직접 판단의 새 저장을 확인했다. 프론트는 환경별 비교·채택·새 저장·재열람·다음 작업 재사용 및 비활성 환경 차단을 검사했다.
- 예시 계정의 로컬 화면에서 Python/Django와 네 답변 방식을 선택하고 프롬프트 생성, 환경별 검사 범위, 활성화한 GEPA 시작 버튼을 확인했다. 화면 증거는 Git에 넣지 않는 `data/django-gepa-ready.jpg`다.
- 이번 연결 확인에서 새 유료 모델 호출은 하지 않았다. 실제 모델로 개인화 효과를 입증한 실험은 후속 검증이다.
- 예시 DB의 기존 개인 보관 항목 15개는 전체 행 해시가 유지됐다. 기존 개인 선호·팀 기준을 덮어쓰는 저장 경로를 추가하지 않았다.
