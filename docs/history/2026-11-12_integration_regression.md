# 두 계정 통합·최신 전체 회귀 완료와 주간보고 갱신

사용자는 주간보고 v0.4의 남은 두 계정 공유·첨부·권한 통합 검증과 최신 전체 회귀 검사를 실행하고, 문제를 수정해 보고서에 반영하도록 요청했다. 유료 API는 사용하지 않았다.

## 결과

- 실제 Chromium의 독립 계정 세션과 로컬 HTTP·SQLite를 이용한 18시나리오 통과. 수신자 교체용 계정과 익명 대조를 추가했다.
- 최신 Python `not api` 전체: **1,355 통과, 0 실패, 1 건너뜀, 16 제외**, 422.41초.
- 프론트 전체: **123 통과, 0 실패**. 프로덕션 빌드 성공. 기존 500KB 초과 번들 경고 유지.
- 환경 제약으로 Windows 심볼릭 링크 생성 검사 1개를 건너뛰었다. 실제 모델 API 검사 16개는 사용자 비용 조건에 따라 제외했다.
- 기준 소스 342개의 해시를 기록·대조했다. 기존 사용자 DB·키를 읽지 않고 테스트 전용 DB·합성 자료를 사용했다. 검증용 서버는 종료했다.

## 수정

1. 공유 대상이 변경되어 서버가 404를 반환해도 이미 열린 인수인계 화면과 초안이 남는 문제를 실제 브라우저에서 재현했다. HTTP 오류 상태를 보존하고 현재 읽기 권한이 없음을 확인하면 해당 작업의 화면·목록·기록·임시 초안을 정리한다. 409 충돌, 현재 읽기 권한이 있는 과거 기록 부재, 일시 장애에서는 미저장 내용을 유지한다. 새 UI 회귀 3개와 기존 관련 7개를 통과했다.
2. 요약 보조 설정 `summary_contract.yaml`을 엔진 도메인으로 수집하던 네 검사를 수정했다. 보조 자료 하나를 명시하고, 다른 모든 도메인은 기존 검사를 유지한다. 보조 자료에 영어·한국어 전용 형식 검사 두 개를 추가했다. 설정 파일 경로·바이트 및 고정 실험 해시는 바꾸지 않았다. 관련 묶음 122개가 통과했고 이후 전체 검사를 다시 실행했다.

초기 제한된 실행 환경의 로컬 HTTP/브라우저 연결 실패와, 브라우저 스크립트의 파일 링크 이름 공백 문제는 제품 실패와 구분해 기록했다. 정상 연결 환경에서의 수정 전 전체 결과는 1,353 통과·4 실패·1 건너뜀이었다.

## 보고서

[주간보고 v0.5](../../output/pdf/Revealed_진행현황_주간보고서_v0.5.pdf)는 기존 표지·WBS·금주/차주 양식을 유지한다. 본 보고 3쪽, 현재 근거 4~12쪽, 과거 백업 13~30쪽이다. v0.4의 두 일부 완료 묶음을 확인 범위 내 완료로 갱신하고 남은 비교 세션 접근 정책·입력/지침 의미 정렬을 차주 계획으로 분리했다.

이 결과는 실제 사용자 효과, 공개 배포, 모든 보안 경계, API 모델 품질을 검증한 것은 아니다. 기존 요약·코딩 프롬프트 비교의 동률과 한계는 그대로 보존했다. 전체 설계서 v1.0은 기존 기준 코드의 스냅샷이며 이번 수정은 이 기록과 추가 검증 문서에 남긴다. 앱 수정과 보고서를 원격에 push하거나 배포하지 않았다.
