# 2026-11-04 FastAPI GEPA 개선 연결

## 구현

- `fastapi_optimization.py`: 실제 `gepa.optimize()`를 호출한다. 사용자 설정으로 조립한 원본은 고정하고 `guidance`라는 보충 안내만 탐색한다. 충돌 시 기존 환경·선호·추가 선호를 우선한다는 문구를 포함한다.
- `fastapi_evaluation.py`: 개선용 2개, 후보 선택용 2개, 개선 후 확인용 2개의 FastAPI 합성 과제를 분리했다. AST로 문법·API 선언·음수 입력 선언·제한된 곱셈/덧셈 반환식을 확인하며 생성된 코드를 실행하지 않는다.
- 설명 길이/번호, 주석 수, 함수/파일 수, 변경/전체 코드 출력은 작성 선호의 대리 지표다. 실제 사용자 만족도나 일반적인 코드 품질로 해석하지 않는다. 별도 과제 점수와 API·계산 검사 충족 수도 표시하고 사용자가 실제 답변을 직접 비교한다.
- 후보 선택 과제에서 점수가 높고 API·계산 검사 충족 수가 줄지 않은 유효 후보만 제안한다. 더 나은 후보가 없으면 원본으로 끝난다. 별도 과제 결과는 후보 선택에 사용하지 않는다.
- `coding_optimization_jobs.py`: 계정별 비동기 실행/조회/저장을 관리한다. 진행 중인 동일 설정 요청은 중복 실행하지 않는다. 최대 동시 작업은 서버 2개·계정 1개이며 결과는 서버 재시작 또는 약 2시간 뒤 사라질 수 있다.
- 과제 모델과 성찰 모델 모두 기존 파일 캐시를 사용한다. GEPA 평가 예산 18회와 별도로 전체 모델 요청 최대 32회·성찰 최대 4회의 제한을 적용하며 기존 최적화 하루 할당량을 공유한다. 요청 횟수는 캐시 조회를 포함할 수 있어 청구 횟수/금액 한도와 다르다.
- API: GET/POST `/api/coding-instructions/optimizations`, GET `/{id}`, POST `/{id}/save`. 생성/결과/저장은 로그인 계정에 한정한다. 저장 시 클라이언트가 보낸 프롬프트·소유자·보고서로 바꾸지 않고 서버 결과만 사용한다.
- `PPT_FASTAPI_GEPA_LIVE`는 미지정 시 `PPT_LIVE`를 따른다. `1`로 지정하면 다른 기능을 데모로 유지하면서 FastAPI GEPA만 실제 호출로 켤 수 있다. 모델은 기존 `PPT_CODING_MODEL`·`PPT_REFLECTION_MODEL` 설정을 쓴다.

## 보관과 화면

- FastAPI 결과 아래 선택적으로 실행한다. ‘이번 작업’ 입력은 보내거나 저장하지 않는다.
- GEPA의 보충 안내, 원본/후보 전문과 별도 과제의 실제 답변을 비교한다. 별도 과제 점수가 같거나 낮으면 그 사실을 따로 안내한다.
- 사용자가 후보 채택을 누르고 새 이름으로 저장해야 보관함에 추가한다. 저장한 개선본에는 원래 지침·고정한 설정·보충 안내·평가 기록을 남긴다.
- 기존 `coding_profile_json`을 확장해 보관하므로 DB migration은 추가하지 않았다. 일반 저장 API는 최적화 기록을 위조할 수 없다. 수동 편집 뒤에는 저장 당시 기록과 현재 본문의 불일치를 안내한다.
- 저장한 개선본 그대로 새 작업에 사용한다. 설정으로 새 초안을 만드는 버튼은 보충 안내를 제외한 재조립임을 명시한다. 기존 개인 지침·팀 기준·보관함 원본은 갱신하지 않는다.

## 실제 확인

- 관련 Python 회귀 검사 110개 통과: 새 GEPA, 기존 코딩 지침/예시, 개인 보관함, 팀 비교·출처·연결·조합·부분 복원·작업용 저장.
- 프론트 전체 73개 통과, 마지막 화면 수정 후 코딩/GEPA 흐름 13개 재확인, Vite 빌드 통과.
- 실제 GEPA 엔진에 테스트 모델을 연결한 단위 검증으로 후보 탐색·원본 고정·별도 과제 평가·호출 중복 방지를 확인했다. 호출/동시 실행 상한, 권한, 실패, 위조 저장도 검사했다.
- 별도 예시 DB `data/task-library-preview.db`에서 실제 모델로 GEPA 1회 실행했다. 요청 16회(성찰 2회 포함), 후보 선택 과제 대리 점수 0.7375 → 0.8687, 별도 과제 0.7375 → 0.7375였다. 별도 과제의 API·계산 정적 검사 충족 수는 전후 2/2였다.
- 위 실행은 연결 확인 사례 하나다. 별도 과제에서 대리 점수가 오르지 않았으므로 일반적인 개인화 개선 효과나 실제 개발 품질 향상으로 보고하지 않는다. 생성 코드를 실행하거나 FastAPI 서버를 띄운 검증이 아니다.
- 예시 계정에서 `FastAPI GEPA 실행 확인 · 예시`를 새 항목으로 저장했다. 저장 전후 전체 기존 항목 14개의 행 해시가 같고 새 항목 1개만 추가됨을 확인했다. 원본 지침과 팀 기준을 갱신하지 않았다.
- 서버 재시작 뒤 보관함에서 해당 개선본을 다시 열고 개선 전 원본·고정한 선택·평가 기록을 확인했다. 새 작업 입력에 개선본과 보충 안내를 포함한 요청문이 만들어지는 것도 실제 화면에서 확인했다.
- 화면 증거와 실행 상세는 Git에 넣지 않는 `data/fastapi-gepa-live-*.jpg`, `data/fastapi-gepa-live-check.json`에 있다. 실제 사용자 자료를 사용하지 않았다.

GEPA API 근거: [공식 optimize 문서](https://gepa-ai.github.io/gepa/api/core/optimize/). 호출은 설치된 패키지의 `DefaultAdapter`/`EvaluationResult` 시그니처를 확인해 연결했으며 라이브러리나 `engine/` 코드는 변경하지 않았다.
