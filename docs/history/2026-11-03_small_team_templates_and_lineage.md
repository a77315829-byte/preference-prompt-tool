# 작은 팀 업무 템플릿·화면 정리·조합 연결

작업 브랜치: `codex/summary-coding-no-aws`. 기존 개인화와 팀 비교를 유지하면서
시작 위치와 기능 구분을 정리했다.

- 시작 화면에 **팀 업무 정리**를 추가했다. 별도 선호 도메인으로 취급하지 않고 팀 업무 템플릿을 연다.
- 상단 메뉴는 시작하기·내 선호 보관함·템플릿·팀 기준 맞추기로 줄였다.
  요청문 점검은 템플릿 화면 안에, 업무 지침 작업 공간은 템플릿의 직접 만들기 동선에 둔다.
- 템플릿은 6개에서 24개로 늘렸다. 문서 7·코딩 9·팀 업무 8이며 추가한 18개는 직접 작성한 검토 필요 초안이다.
  회의 행동 목록·진행 공유·인수인계·의사결정·회고·장애·릴리스·요구사항·PR·버그 등의 양식을 제공한다.
  기존 6개만 선택 비교를 지원하고 새 초안은 복사·점검만 지원한다. 서버에서도 미지원 비교를 차단한다.
- 요청문 점검은 선택한 초안을 불러오며 수정안 생성은 명시적 버튼으로 실행한다.
  입력 변경 시 옛 결과를 비우고 늦게 도착한 이전 구조 점검 응답을 무시한다.
- 새 재조합·복원 저장본에 직전 항목 ID와 작업 종류를 기록한다. 목록 응답에는 관계 요약만 내리고
  지침 본문·축 상세는 노출하지 않는다. DB 스키마는 기존 출처 JSON을 사용한다.
- 보관함의 **이어진 조합 보기**는 원래 작업용·새 조합·선택 항목 되돌림을 묶어 표시한다.
  검색 시 연결된 가족도 함께 보여 주며 항목 이름으로 연다. **이전 작업용 바로 열기**도 제공한다.
  작성 중 내용은 이동 전에 확인하고 이전 항목 수정 시 현재 버전을 연다고 안내한다.
  삭제된 항목과 ID 미기록 과거 저장본을 구분한다. 이름으로 연결을 추측하지 않는다.
- `docs/product_direction_small_teams.md`에 반복 업무·팀 집계의 실제 의미, 업무 양식 참고 자료,
  아직 검증하지 않은 협업 효과와 파일럿 평가 계획을 분리했다. 팀 화면에도 집계 방식 설명을 넣었다.

검증:

- 관련 Python 검사 44개 통과. 재조합·복원 생성 경로의 부모 ID·작업 종류 검사도 14개 통과.
- 프론트 검사 54개와 프로덕션 빌드 통과.
- 전체 Python 회귀 검사 887개 통과. 실제 모델 호출 16개와 기존 Windows 실행 경로 관련 5개를 제외했다.
  실행: `python -m pytest -m "not api" -k "not holdout_runtime_checks_accept_known_correct_examples and not faq_runtime_checks_reject_an_answer_visible_before_click" -q`.
- 별도 예시 DB로 실제 화면에서 세 번째 시작점 → 팀 업무 8개 → 요청문 점검을 확인했다.
  유료 수정안은 모의 응답으로만 검사했다.
- 실제 화면에서 원래 작업용 → 두 항목 변경한 새 조합 → 코드 구성만 복원한 조합을 별도 저장하고,
  검색으로 세 항목이 한 흐름에 표시되는 것과 이전 작업용으로 두 번 돌아가는 것을 확인했다.
  기존 개인·팀·작업용은 수정하지 않았다.

새 의존성·유료 모델 호출·원격 배포는 없다. `master`·`submission`은 변경하지 않는다.
