# 2026-11-04 환경별 GEPA 확장 5차: NestJS

## 연결한 기능

TypeScript/NestJS를 기존 GEPA 실행·전후 프롬프트/답변 비교·직접 판단·새 항목 저장·재열람·새 작업 재사용 흐름에 연결했다. 기존 개인 선호·저장 항목·팀 기준은 갱신하지 않는다. 더 나은 후보가 없으면 원본을 유지한다. 현재 명시적 지원은 13조합이며 JavaScript/NestJS는 지원으로 승격하지 않는다.

`coding_environments.py`에 지원 쌍을 추가하고 `nestjs_coding_evaluation.py`에 독립 과제를 두었다. 개선용 2개·후보 선택용 2개·별도 확인용 2개를 구분하며 평가 버전은 `nestjs-ast-v2`다. 환경별 캐시와 기존 `PPT_WEB_GEPA_LIVE`, 모델 설정, 최대 32회 요청/성찰 4회, 계정별 소유권·공유 할당량·동시 실행·서버 결과 기반 저장을 사용한다. 새 라이브러리·DB migration·`engine/` 수정은 없다.

## 검사 계약

- TypeScript 파서로 클래스·데코레이터를 읽고 실제 @nestjs/common import/별칭의 Controller·Get·Query와 Module controllers를 확인한다. 주석 속 이름만으로 등록됐다고 판단하지 않는다.
- 두 원시 쿼리를 Number로 변환하고 누락·빈 값·공백·비숫자·무한대·음수에서 BadRequestException을 만드는 분기를 확인한다. 세 정상 입력의 반환 객체 키·계산식을 확인한다.
- 서비스를 나누면 Injectable·Module providers·타입이 명시된 생성자 매개변수 속성의 연결을 제한된 내부 모델로 따라간다. 실제 계산 메서드가 호출되는지 검사하며 서비스/함수 개수로 역할 구성을 채점하지 않는다. 제공된 컨트롤러·서비스·모듈의 분리와 import 연결도 다룬다.
- 변경 부분은 quote 메서드 전체 또는 마지막 return을 제공된 기존 컨트롤러 맥락에 적용한다. 추가 import는 별도 코드 블록으로 제시할 수 있고 실제 보관 원본은 변경하지 않는다.
- 기존 JS/TS AST 해석기에 내부 인스턴스·this·메서드·허용된 예외 모델만 추가했다. 생성된 클래스/데코레이터/모듈을 import/eval하지 않는다. 미지원 데코레이터·파이프와 순환 의존성은 확인하지 못한 것으로 처리한다. 크기·노드 수·깊이·명령 수·6초 제한을 유지한다.
- 주석·역할 구성은 자동 점수에서 제외하고 실제 답변으로 직접 판단한다. 선택한 후보를 새 항목으로 저장할 때 판단 기록도 함께 보관한다.

실제 Nest 빌드·타입 검사·DI 컨테이너·HTTP·ValidationPipe·DB·보안·전체 품질 검증이 아니다. 커스텀 provider/guard/pipe·상속·비동기 IO와 다른 올바른 문법도 범위 밖이면 미확인될 수 있다. 제한된 과제 점수를 일반적인 개인화 효과로 주장하지 않는다.

## 검증과 화면

NestJS 기본 검사 7개는 전체/메서드/return 답변, 잘못된 경로·Query·Module 등록·입력 거절·오류 예외·계산식, 서비스 providers/Injectable/생성자/메서드 연결, 파일 분리와 import, 별칭과 부분 수정, 가짜·타입 전용 import·예약 이름 가림·위험한 코드 비실행·순환 의존성을 확인했다. 설치된 실제 GEPA 엔진에 테스트 모델을 연결해 후보 탐색·별도 과제·환경별 캐시·원본 고정과 새 항목/직접 판단 저장을 확인했다. 미지원 데코레이터/파이프 차단 보완 뒤 같은 7개 검사를 다시 통과했다.

관련 Python 회귀 검사 103개(NestJS HTTP 검사 포함), 프론트 전체 83개 검사와 Vite 빌드가 통과했다. TypeScript/NestJS도 비교→직접 판단→채택→새 저장→재열람→다음 작업 재사용을 확인했다. 다른 환경이 활성화돼 있어도 NestJS 설정이 없으면 시작하지 못한다.

로컬 예시 계정에서 NestJS 선택→네 선호→프롬프트 생성→환경별 검사 범위와 활성화된 시작 버튼을 확인했다. Git에 넣지 않는 화면 증거는 `data/nestjs-gepa-ready.jpg`다. 예시 DB의 기존 보관 항목 15개는 전체 행 해시가 유지됐다. 이번에는 새 유료 모델 호출을 하지 않았다. 실제 모델의 개인화 효과는 후속 검증이다.
