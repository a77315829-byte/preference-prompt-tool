# 새 코딩 지침의 팀 연결·도구 적용·실제 작업 비교

2026-11-09, `microstone`. 사용자가 선택한 우선 과제는 **TypeScript/React 버그 수정·기능 추가**다.
이번 작업은 기존 새 코딩 흐름에 아래 세 기능을 연결했다. 실제 사용자에게 효과가 있다는 결과를 새로 얻은 것은 아니다.

## 1. 개인 선호와 팀 기준 연결

- 새 팀 종류 `coding_profile`은 설명·주석·구성·출력 네 항목을 사용한다. 기존 React 비교의 축과 기록은 변환하지 않는다.
- 기존 계정·팀 목록·7일 초대·팀장 초대 닫기를 재사용한다. 팀 기본값 변경은 팀장만 가능하고 비참여자는 지침을 볼 수 없다.
- 팀장은 기본값과 필수 규칙을 제안한다. 이 값은 팀원의 투표나 합의 완료로 표시하지 않는다. 개인 추가 메모와 A/B 비교 이력은 팀에 자동 공유하지 않는다.
- 같은 언어·프레임워크에서 서로 다른 항목마다 개인/팀 중 직접 선택한다. 필수 규칙은 결과에 포함한다. 프롬프트에 넣는 것으로 준수를 보장하지는 않는다.
- 작업용 지침은 별도 개인 항목으로 저장한다. 원래 개인 설정·팀 기본값·선택 출처·팀 버전·당시 규칙을 보관하며 원본을 덮어쓰지 않는다. 팀 변경 시 진행 중인 낡은 조합은 다시 확인해야 한다.
- 보관함의 출처 펼치기에서 당시 선택을 확인한다. 저장 이후의 팀 변경은 보관한 지침에 자동 반영하지 않는다.

## 2. 개발 도구 적용

새 코딩 결과와 보관함의 `새 작업에 사용`에 `1. 팀 기준과 연결 / 2. 도구에 적용 / 3. 작업 시간·기능 비교`를 연결했다.

- AGENTS.md, CLAUDE.md, GitHub Copilot, Cursor, 일반 Markdown 형식.
- 기존 파일 내용을 붙여 넣으면 변경 차이와 최종 내용을 미리 볼 수 있다. 다운로드 후 사용자가 해당 위치에 적용한다.
- 생성 영역 표시는 `preference-prompt-tool:coding:begin/end`. 재내보내기 시 그 영역만 교체하며 영역 밖 텍스트·공백은 보존한다. 잘못된 표시는 오류로 안내한다.
- Cursor 기존 파일의 frontmatter/적용 범위는 자동 병합하지 않는다. 새 규칙 파일은 항상 적용 설정임을 안내하고 사용 도구에서 범위를 검토하게 한다.
- 파일 자동 설치, IDE 확장, 저장소 직접 쓰기는 구현하지 않았다. 다운로드만으로 도구에 적용됐다고 표시하지 않는다.

## 3. 실제 작업의 독립 기록

두 조건은 **일반 지침**과 **현재 선택한 지침 전체**다. 일반 조건은 개발 환경·공통 원칙·동일한 팀 필수 규칙을 유지한다. 선택 조건에는 네 선호 외에 추가 메모나 저장된 개선 안내가 있을 수 있으므로 네 항목만의 인과 효과로 해석하면 안 된다.

| 기록 | 처리 |
|---|---|
| 과제·도구·모델/설정·저장소/기준 커밋/완료 조건 | 시작 시 지침과 함께 고정 |
| 수행 순서 | 기록별 무작위 권장 순서; 준수 여부를 자동 보장하지 않음 |
| 준비·요청·응답 대기 | 사용자 시작/멈춤, 서버 시각 누적 |
| 답변 수정·검사 | 준비 시간과 별도 타이머·집계 |
| 기능 결과 | 미확인 / 통과 / 실패 / 진행 불가; 통과·실패는 근거 필수 |
| 테스트 수 | 선택 입력. 일부 실패를 전체 통과로 저장할 수 없음 |
| 선호 | 일반 / 선택 지침 / 비슷함 / 미확정과 이유, 기능 결과와 별도 |
| 답변 본문 | 사용자가 명시적으로 저장할 때만 보관 |
| 복구·공유 | 계정별 기록 재조회·JSON 다운로드. 팀 자동 공유 없음 |

미측정은 0초가 아니고 미확인/진행 불가는 실패가 아니다. 두 기능 결과가 모두 통과했는지와 시간 차이를 독립적으로 보여준다. 최초 8~10회 선호 선택·팀 설정 시간은 이 타이머에 포함되지 않는다. 창을 닫아도 타이머는 계속되므로 자리 비움 전에 멈춰야 한다. 같은 계정에서 여러 타이머를 동시에 시작할 수 없고, 다른 창의 오래된 버전으로 변경하면 충돌로 거절한다.

### TypeScript/React 실사용 절차

1. 실제 이슈를 정하고 재현 절차·대상 파일·완료 조건·기준 커밋을 먼저 적는다. 첫 사용의 선호 선택 비용은 별도로 기록한다.
2. 각 조건은 같은 커밋에서 분리해 시작한다. 같은 도구·모델·추론 설정·파일 맥락을 제공하고 기존 AGENTS/Copilot/Cursor 등 지침의 적용 여부도 같게 맞춘다.
3. 별도 새 대화에서 해당 조건의 지침+작업을 사용한다. 준비/대기와 수정/검사 타이머를 구분해 재고 중단 시간을 빼기 위해 멈춘다.
4. 프로젝트의 타입 검사, 관련 회귀 테스트, 빌드, 화면 재현 절차를 실행한다. 빌드 성공만으로 기능 통과라 하지 않는다. 검사 명령·결과·검토한 diff를 근거로 남긴다.
5. 선호를 별도로 판단한다. 같은 과제의 반복에는 학습 효과가 있으므로 여러 과제에서 순서를 교차하고, 가능하면 검토자에게 어떤 지침의 결과인지 가린다.
6. 사용자·과제별 결과가 충분히 모이기 전에는 효과를 확정하지 않는다. 미완료/진행 불가와 실패를 제외해 유리한 사례만 보고하지 않는다. 정확도 저하 없이 수정 시간이 줄었는지, 최초 설정 비용을 회수하는지를 따로 분석한다.

이 기능은 실제 코드를 실행하거나 정답을 채점하지 않는다. 기능 결과와 테스트 수는 **사용자의 확인 기록**이다. RACE/EvalPlus·Luna 파일럿의 자동 검사와 사용자 선호/시간 측정은 계속 구분한다.

## 구현·데이터·비용

- SQLite migration 14: `coding_team_guides`, `coding_work_trials`. 기존 데이터는 보존하고 계정 삭제 시 개인 비교 기록은 연쇄 삭제한다.
- `coding_team_guides.py`, `coding_work_exports.py`, `coding_work_trials.py`, `/api/coding-work/*`에 신규 기능을 분리했다. `engine/`은 변경하지 않았다.
- UI는 `CodingWorkflowPanel`과 팀/내보내기/작업 비교 패널이며 기존 팀 메뉴·보관함에 연결했다.
- 새 라이브러리와 유료 모델 호출은 추가하지 않았다. 이번 구현·검사에 모델 API 비용은 없다. 사용자가 외부 AI 도구에서 실제 과제를 실행하면 해당 도구 요금이 별도로 적용된다.
- 공개 배포·원격 push·Streamlit 계정 삭제는 이번 변경에 포함하지 않았다.
