# 3단계: 실제 AI 반환 타입 수정 요청

## 목적과 범위

기존 자동 취향 검증에서 남은 FAQ 공개 함수의 반환 타입 누락을 AI로 수정하고,
수정 후 기능·타입·스타일을 재검사하는 단계다. 모델 학습이나 사람 대상 평가는 아니다.

## 이번 실행

- 브랜치: `codex/coding-ai-upgrade`.
- 도구: `benchmarks/coding_ai_quality/repair_persona_transfer.py`.
- 기본 실행은 dry run이며 `--execute`에만 실제 요청을 허용한다.
- 원본 `data/coding_persona_live_2026-10-15.json`은 변경하지 않았다.
- 원본 해시와 수정 요청 결과는 별도 로컬 증거
  `data/coding_persona_repair_2026-10-15.json`에 보존했다.
- 기존 생성 캐시를 사용하며, 호출 상한은 1회, SDK 재시도는 0회다.
- 기존 FAQ 동작, 문구, 파일 구조, 테마는 유지하고 공개 함수 반환 타입과
  필요한 타입 import만 수정하도록 요청했다.

## 결과와 한계

요청 시 DNS/네트워크 경고가 발생했고, 최종 호출은 `InternalServerError`로 실패했다.
응답 코드와 토큰 사용량을 받지 못했다. 추가 호출은 하지 않았다.
따라서 **실제 AI 수정 성공과 수정 코드 검증은 미완료**다.
호출 시도 1회는 성공한 생성 1회 또는 실제 과금 1회를 의미하지 않는다.
토큰 정보와 제공업체 청구 내역을 확보하지 못해 비용을 0원으로 확정하지 않는다.

단가 확인은 OpenAI 공식 모델 문서를 기준으로 했다.
[GPT-6 Luna 공식 문서](https://developers.openai.com/api/docs/models/gpt-6-luna)의
표준 100만 토큰당 입력 $0.10, 캐시 입력 $0.01, 출력 $0.50을 적용할 예정이었다.
토큰 정보가 있을 때의 계산식은
`(입력 - 캐시 입력) × 0.10 / 1,000,000 + 캐시 입력 × 0.01 / 1,000,000 + 출력 × 0.50 / 1,000,000`이다.
이는 기본 단가에 따른 계산이며 실제 청구서 확인과 구분한다.

## 로컬 회귀 검사

`tests/test_coding_domain.py`, `tests/test_coding_persona_evaluation.py`,
`tests/test_coding_ai_quality_stage4.py`, `tests/test_coding_ai_quality_benchmark.py`를
`-q -m 'not api'`로 실행해 **69개 통과**했다(18.03초).
`git diff --check`도 통과했다. 이는 기존 로직의 회귀 검사이며 실제 AI 수정 성공을
증명하는 결과는 아니다.

## 후속 작업

먼저 네트워크/제공업체 접근과 기존 실패 증거를 확인한다. 이번 도구는 기존 증거가
있으면 중단하므로 파일을 지우거나 캐시를 우회해 자동 반복하지 않는다.
후속 호출은 별도 승인을 받아 실패 증거를 보존하는 방식으로 진행한다.
새 코드를 받으면 실행 전 검토하고 strict TypeScript, 빌드, FAQ 독립 토글 동작,
공개 함수 반환 타입 및 기존 스타일 검사를 수행한다.

## 후속 재시도 및 실제 검증 완료

사용자의 검증 재개 요청으로 네트워크 접근을 허용한 별도 실행을 1회 수행했다.
실패 증거와 원본은 유지하고 `--output`으로 별도 결과 경로를 지정하도록 도구를 보완했다.

- 모델: `openai/gpt-6-luna`, 응답 모델: `gpt-6-luna`.
- 성공 응답 1회: 입력 1,957 / 출력 1,463 / 합계 3,420 토큰, 캐시 입력 0.
- 수정 증거: `data/coding_persona_repair_retry_2026-10-15.json`.
- 실행 전 원본과 파일별 diff를 검토했다. `ReactElement` 타입 import와
  `FAQ(): ReactElement`만 변경됐으며 CSS 두 파일은 동일했다.
- 원본을 보존한 파생 자료: `data/coding_persona_repaired_2026-10-15.json`.
- 전체 오프라인 검증: `data/coding_persona_repaired_evaluation_2026-10-15.json`.

두 가상 취향의 A/B 6쌍과 별도 FAQ 2개, 총 14개 코드가 strict TypeScript,
빌드, 시나리오 동작 검사, 스타일 검사 및 독립 반환 타입 검사에 통과했다.
선호 추정 2건과 최종 프롬프트의 스타일 조항 6개도 일치했다. 전체 판정은 통과다.
검증 재실행에는 추가 API 호출이 없다. 관련 회귀 테스트는 69개 통과(23.88초),
`git diff --check`도 통과했다.

이는 준비된 시나리오에 대한 자동 검증 PoC다. 모든 기능 입력에서의 동일성,
CSS를 실제로 렌더링한 시각적 동일성, 사람의 만족도를 증명하지 않는다.
실제 청구 내역은 대조하지 않았으며, 앞선 실패 요청의 과금 여부도 미확정이다.
이번 기록의 토큰 수를 실제 결제 금액으로 표현하지 않는다.
