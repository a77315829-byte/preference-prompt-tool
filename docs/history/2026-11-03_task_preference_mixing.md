# 이번 작업용 개인·팀 항목 선택

개인 선호 보관함에서 팀 기준과 비교한 뒤 다른 항목마다 내 선호 또는 팀 기준을
고르고, 이번 작업에만 사용할 프롬프트를 만든다. 같은 항목은 유지하고,
미정 값을 선택하면 해당 축의 지시를 제외한다. 팀의 미합의 상태도 안내한다.

- `preference_comparison.compose_task_prompt`가 확인된 축 값만 조합한다.
  모든 다른 항목의 선택을 검증하고 모르는 축·값은 거부한다.
- `POST /api/preferences/{id}/compose-task`는 로그인 소유권, 개인 버전,
  팀 분류·스냅샷을 확인하고 지침·선택·작업용 스냅샷을 반환한다.
  모델 호출·DB 쓰기·사용량 차감은 하지 않는다.
- 실행의 `basis=custom`은 개인 원본과 현재 팀 기준에서 서버가 다시 조립한다.
  클라이언트의 임의 프롬프트는 사용하지 않는다. 팀·개인 버전·선택이 바뀌면
  모델 호출과 사용량 차감 전에 멈춘다. 기존 생성기의 캐싱을 사용한다.
- 화면은 항목별 선택, 진행 개수, 작업용 만들기, 개인용·팀용·작업용 전환,
  미리 보기·복사·실행을 제공한다. 선택 변경 시 작업용은 무효화하며
  새 작업 입력은 유지한다. 이전 실행 결과는 현재 선택과 구분한다.
- 기본 생성문 전체로 확인되지 않는 수정·추가·최적화 지침은 축을 추측하지
  않고 조합 제한 이유와 기존 전체 지침 선택을 안내한다.

개인 보관함·팀 기록·팀 합의 상태는 갱신하지 않는다. 새 의존성이나 DB 변경은
없고 `engine/`과 기존 선호 추정·팀 집계는 변경하지 않았다.

검증: 관련 Python 검사 22개, 프론트 검사 42개와 프론트 빌드 통과.
전체 Python 검사도 863개 통과했다. 유료 API 검사 16개와 기존 Windows
코딩 평가 실행 경로 문제에 해당하는 5개는 제외했다(21 deselected).
샌드박스의 임시 폴더·localhost 접근 제한을 확인한 뒤 로컬 서버 테스트는
승인된 샌드박스 밖 실행으로 검증했다.
실제 유료 모델 호출과 원격 배포는 수행하지 않았다.
