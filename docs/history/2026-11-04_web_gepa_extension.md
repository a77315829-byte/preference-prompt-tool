# 2026-11-04 환경별 GEPA 확장 1차: React·Express

## 연결한 범위

JavaScript/React·TypeScript/React·JavaScript/Express·TypeScript/Express 네 조합을 기존 Python/FastAPI·Java/Spring Boot와 같은 실행·전후 비교·직접 확인·새 항목 저장·재사용 흐름에 연결했다. TypeScript의 프레임워크 선택에도 Express를 추가했다. 기존 React 비교와 저장된 개인 지침·팀 기준은 유지한다.

`coding_environments.py`에서 지원 쌍을 명시적으로 관리한다. 이름이 비슷한 Vue·Next.js·NestJS·직접 입력 도구를 지원한다고 추측하지 않는다. 모든 환경의 하루 한도·동시 작업·요청 한도는 공유하며 새 라이브러리나 DB migration은 없다.

## 과제와 검사

- `web_coding_evaluation.py`는 React/Express 각각 개선용 2개·후보 선택용 2개·별도 확인용 2개를 준비한다. JavaScript와 TypeScript 요청은 해당 문법을 명시하고 환경별 캐시 경로를 사용한다.
- React는 숫자 props의 유효성 검사와 오류 표시, 정해진 output 요소의 계산값을 확인한다. Express는 ESM import·app 생성·GET 경로·핸들러 연결, 숫자 쿼리 변환과 음수/누락/비숫자의 400 응답, 정상 입력의 JSON 계산값을 확인한다.
- `scripts/check_web_coding.mjs`는 기존 프론트 의존성 TypeScript 파서로 AST를 만든다. 크기·노드 수·깊이·명령 수와 6초 제한을 둔 해석기로 허용된 선언·산술·조건·함수·JSX·응답 패턴만 다룬다. 생성 코드를 import/eval하거나 서버/브라우저를 실행하지 않는다.
- 변경 부분 답변은 제공된 원래 파일의 함수 또는 마지막 return 문에 적용한 맥락에서 검사한다. JavaScript 답변에 TypeScript 타입 문법이 섞인 경우도 거절한다.
- v2의 설명/출력 자동 형식 점수와 주석/역할 구성의 직접 확인을 유지한다. 다른 올바른 표현이라도 지원 패턴 밖이면 확인하지 못할 수 있다. TypeScript 타입 검사·실제 렌더링·HTTP 통합·보안·일반적인 품질 검증으로 보고하지 않는다.

## 실행 설정과 화면

`PPT_WEB_GEPA_LIVE=1`이 JS/TS의 React/Express를 켠다. 미지정 시 `PPT_LIVE`를 따른다. Node.js와 `npm ci --prefix frontend`로 설치한 기존 의존성이 없으면 모델 호출 전에 시작을 차단한다. 실행 버튼 앞에 선택 환경의 검사 범위와 한계를 표시한다. 기존 모델·성찰 설정과 계정별 소유권·서버 결과 기반 저장을 사용한다.

## 검증

- 새 평가 검사 9개는 네 조합의 정상 답변·잘못된 계산·음수 검사 누락·경로 오류·props 출력 오류·부분 수정·문법 오류·가짜 주석·실행 부작용 코드와 분리 함수의 계산·import 연결을 다뤘다. 실제 GEPA 엔진에 테스트 모델을 연결해 개선 후보 탐색·별도 과제·캐시·고정 원본·직접 판단의 새 저장을 확인했다.
- 관련 Python 61개·프론트 전체 81개 및 Vite 빌드 통과 후, 함수 연결 2개를 추가하고 웹 평가 전체 9개를 다시 확인했다(관련 Python 총 63개). 네 조합 모두 실제 화면 컴포넌트를 사용한 비교·채택·새 저장·재열람·새 작업 재사용을 검사한다. 도구 미설치와 환경별 활성화·미지원 쌍 차단도 확인했다.
- 예시 계정의 실제 로컬 화면에서 TypeScript/Express를 선택하고 프롬프트·GEPA 검사 범위·활성화한 시작 버튼을 확인했다. 이번 연결 확인에서는 새 유료 모델 실행을 하지 않았다. 실제 개인화 효과를 입증한 결과는 아니다.
- 화면 증거는 Git에 넣지 않는 `data/typescript-express-gepa-ready.jpg`다. 예시 DB 보관함의 기존 15개 행 해시가 유지됨을 확인했다.
