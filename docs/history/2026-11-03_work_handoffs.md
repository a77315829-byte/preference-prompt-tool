# 작업 맥락과 프롬프트를 넘겨 이어서 진행하는 인수인계

브랜치: `codex/summary-coding-no-aws`.

목적·진행 상황·남은 일·참고 파일 경로/링크·사용한 프롬프트를 별도 작업 기록으로 저장한다.
기존 선호 보관함과 투표 기반 팀 모드를 유지하며, 명시적 저장·공유·이어받기를 추가했다.

- `handoffs.py`는 계정별 저장·열람·공유 대상 지정·이어받기·진행 갱신·완료/다시 진행·버전 기록을 담당한다.
  모델 호출, 파일 내용 업로드, 자동 알림·메시지 발송은 없다.
- migration 9에 `handoffs`·`handoff_versions`를 추가했다. 기존 개인 지침과 버전은 갱신하지 않는다.
  작성자는 같은 서버의 사용자 아이디 하나를 지정해 공유한다. 링크만으로 접근 권한을 부여하지 않는다.
- 저장만 하면 개인 기록이다. 받는 계정은 공유 이후의 기록만 열 수 있고, 공유 전 개인 초안은 볼 수 없다.
  이어받기 전 대상 변경 시 이전 대상의 본문·버전 접근을 차단한다.
- 이어받기 후에는 받는 사람이 현재 작업을 편집하고 작성자는 읽기 전용으로 진행을 확인한다.
  변경마다 스냅샷과 수행자를 기록하고, 저장 버전이 다르면 409로 거절한다. SQLite 쓰기 트랜잭션으로 동시 이어받기를 보호한다.
- 파일은 경로·파일명 또는 http/https 링크로 기록한다. 웹 링크는 새 창으로 열고 파일 경로는 텍스트로만 표시한다.
  사용한 프롬프트와 작업 맥락을 붙인 요청문은 명시적으로 복사하며 AI를 자동 실행하지 않는다.
- 시작 화면의 팀 업무 정리는 인수인계로 연결한다. 팀 기준 화면에서도 열 수 있다.
  보관함에서 현재 선택한 개인용·팀용·조합 지침을 초안으로 가져올 수 있고, 다음 화면에서 확인한 뒤 저장·공유한다.
  원문/실행 결과의 보관함 자동 저장 정책은 바꾸지 않았다. 상단 메뉴는 네 개를 유지한다.
- 작성자 계정 삭제 시 공유본·버전도 삭제된다. 수신자 계정 삭제 시 기록은 남고, 완료 전 작업의 대상은 다시 지정할 수 있다.

검증:

- 관련 Python 검사 102개 통과. 새 인수인계 검사 24개에서 권한, 공유 전 기록 비공개,
  공유 대상 변경, 버전 충돌, 동시 이어받기, 원본 개인 지침 보존, DB 이전과 계정 삭제 동작을 확인했다.
- 전체 Python 회귀 검사 932개 통과. 실제 모델 호출 16개와 기존 Windows 실행 경로 관련 5개를 제외했다.
  실행: `python -m pytest -m "not api" -k "not holdout_runtime_checks_accept_known_correct_examples and not faq_runtime_checks_reject_an_answer_visible_before_click" -q`.
- 프론트 검사 62개와 프로덕션 빌드 통과. 새 저장·공유·로그인 후 링크 열기·이어받기·현재/이전 기록·완료/재개,
  저장 실패 입력 보존·초안 이동 확인·보관함 지침 가져오기를 확인했다.
- 별도 예시 DB의 두 가상 계정으로 실제 화면에서 저장 → 공유 → 수신자 로그인 → 이어받기 → 진행 갱신 → 공유 당시 기록 조회를 확인했다.
  작성자로 다시 로그인해 다음 담당자의 진행 내용이 읽기 전용으로 표시되는 것도 확인했다.

기능 동작 검증이며 실제 인수인계 시간·추가 질문 감소 효과는 별도 사용자 검증 대상이다.
새 의존성·유료 모델 호출·원격 배포는 없다.
