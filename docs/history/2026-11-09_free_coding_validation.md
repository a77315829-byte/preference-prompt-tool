# 2026-11-09 RACE·EvalPlus 무료 검증

사용자 요청: RACE와 EvalPlus로 돈이 들지 않는 검증부터 실행하고,
유료 API가 필요한 단계는 실행 전에 예상 비용을 제시한다.
작업 브랜치는 `microstone`이다.

## 이번에 확인한 범위

- **추가 모델 API 호출 0회, API 비용 $0.** `.env`와 API 키를 읽지 않았다.
- 새 프로젝트 라이브러리·서버 기능·DB 변경 없이 `benchmarks/coding_public/`에 분리했다.
- [RACE 공식 저장소](https://github.com/jszheng21/RACE)의 정적 함수 7개를 동작 변경 없이 분리해
  커밋·원본 파일 해시·함수 AST를 대조했다. 라이선스도 함께 보존했다.
- 현재 Python 기본 문법의 비교 선택지 24개(주문·대여·인쇄 × 4항목 × 2선택지)를 확인했다.
  20개 숫자 입력 조합씩 총 **480/480**이 기대한 계산값과 일치했다.
  부분 수정 선택지는 원래 함수에 적용한 뒤 검사했다. 제한된 AST 해석기 검사이며 일반 코드 실행 검사가 아니다.
- 주석 비교 3쌍은 주석 토큰 0/1과 RACE 주석 비율 조건의 차이를 보였다.
  구조 비교 3쌍은 함수 1/2개로 구분됐다. 모든 예시에 함수 docstring이 없으므로 해당 지표는 통과하지 않는다.
  주석이 많거나 함수가 많을수록 무조건 좋다는 점수는 만들지 않았다.
- 직접 설정 16조합이 서로 다른 지침으로 조립됐다.
- HumanEval+ 164개, MBPP+ 378개의 원본 해시·진입점·참조 코드 문법을 확인했다.
  원본 MBPP/793에는 추가 입력이 없고, MBPP/305·593에는 Python 3.12 escape 경고가 있다.

## EvalPlus 실행

공개 참조 정답과 항상 예외를 내는 의도적 오답을 공식 평가기에 넣었다.
이들은 모델이 우리 프롬프트로 생성한 답변이 아니다.
따라서 여기서의 통과율은 **평가기 대조 검사**이며 서비스 성능이 아니다.

실행 결과는 `benchmarks/coding_public/results/2026-11-09.json`에 집계한다.
원본 로그와 과제별 JSON은 `data/public-code-benchmarks/evalplus-runs/`에 있다.

| 실행 범위 | 정답 대조 | 의도적 오답 대조 |
|---|---:|---:|
| HumanEval+ v0.1.10 전체, 공식 판정 수정 적용 | 164/164 통과 | 164개 모두 실패 검출 |
| MBPP+ v0.2.0 NoExtreme | 기본 378/378, base+plus 377/378 통과 | 378개 모두 실패 검출 |

**MBPP/255는 추가 입력 1건에서 참조 정답도 실패**했다. 색상 5개로 길이 77의 중복 조합을
모두 반환하는 입력으로 조합 수는 `C(81, 4) = 1,663,740`개다.
공식 결과 JSON은 실패한 입력은 남기지만 발생 예외를 남기지 않으므로
메모리/시간 경계의 영향 가능성을 기록하며 원인을 확정하지 않는다.
이 한 건을 임의로 제외하거나 통과로 바꾸지 않았다.
최종 실행은 모든 과제를 처리했지만 `status=unexpected_results`, 종료 코드 1이다.
이는 누락된 검사나 모델 성능 저하가 아니라 **참조 정답 대조가 하나 완전히 통과하지 못했다는 뜻**이다.
기본 실행을 대조가 모두 통과한 HumanEval로 설정했고, 두 데이터셋 결과 재현은 `--dataset both`로 한다.

MBPP NoExtreme은 **378개 과제·1,174개 기본 입력은 동일**하고 추가 입력 39,841개에서
7개 과제의 극단 입력 205개를 제외한 **39,636개**를 쓴다.
과제 지문·정답·다른 필드가 그대로인지 대조했다.
원래 전체 입력의 실행은 3GiB 컨테이너에서 종료 코드 137로 중단되었으므로
**MBPP+ 전체 입력을 모두 검증했다고 보고하지 않는다.**

## 실제 발견·해결한 실행 문제

1. Docker Desktop이 시작되지 않았다. `Docker/run/dockerInference`와
   `docker-secrets-engine/engine.sock`의 빈 통신 파일에 접근하지 못하는 오류였다.
   Docker 종료를 확인한 후 **빈 통신 소켓만 있는 폴더**를 백업 이름으로 옮겨 재생성했다.
   공장 초기화·이미지 삭제·컨테이너 삭제·설정 초기화는 하지 않았다.
   백업은 `%LOCALAPPDATA%/Docker/run.before-free-eval-20261109*`와
   `%LOCALAPPDATA%/docker-secrets-engine.before-free-eval-20261109*`에 보존했다.
2. 공식 `ganler/evalplus:v0.3.1` 이미지 내부 패키지가 **0.4.0.dev2**였다.
   실제 패키지 버전과 이미지 digest `sha256:26b118098bef281fe8dfe999bf05f1d5b45374b4e6c00161ec0f30592aef4740`를 고정했다.
   컨테이너는 Python 3.11.10, 프로젝트는 기존 Python 3.12다.
3. `EVALPLUS_TIMEOUT_PER_TASK`를 지정하면 평가기에서 환경변수 문자열과 숫자를 비교하는
   TypeError가 났다. 이 옵션을 제거하고 공식 기본값을 사용했다.
4. 원본 이미지에서 HumanEval/32 정답이 실패했다. 성공 후 `continue`하기 전에
   성공 기록·진행 수를 갱신하지 않는 버그였다. 저자의
   [공식 수정 커밋](https://github.com/evalplus/evalplus/commit/6eb1e199c2e370518e7bf3e8eee6322c2b23c89c)
   을 적용했다. 원본과 **기록용 2줄만 다름을 해시로 확인**했다.
   수정 전 정답은 163/164, 수정 후 164/164였다. 문제와 허용 오차는 수정하지 않았다.
5. MBPP 전체·NoExtreme의 일괄 실행이 모두 메모리 한도에서 중단됐다.
   NoExtreme의 정답 캐시 하나도 약 0.8GB였다. 동시 평가를 1개로 줄이고
   정답 캐시를 디스크로 옮겼으며 MBPP는 50개씩 나누어 공식 평가 함수를 호출하도록 했다.
   분할 시 과제의 모든 필드·테스트 입력이 그대로 유지되는지 검사하고,
   결과를 합칠 때 378개 과제의 누락·중복을 거절한다.
   특정 50개 묶음의 정답 객체만 약 0.78GB여서 프로세스 큐의 복제도 부담이었다.
   외부 작업 배분을 ThreadPoolExecutor 1개로 바꾸어 정답 객체를 공유했다.
   공식 `untrusted_check()`의 답안별 격리 프로세스·판정 조건은 그대로 유지하며
   이 운영 방식 차이를 실행 메타데이터에 기록했다.

원본 실행 흔적:

- `20261108T232653Z-cfe50667`: 이미지 태그/패키지 버전 불일치를 감지하고 중단.
- `20261108T232751Z-8bb8840f`: 시간 제한 환경변수 타입 오류. 중단된 이번 검사 컨테이너만 정리.
- `20261108T232908Z-7127c973`: 원본 HumanEval 정답 163/164, 오답 0/164 통과. MBPP 단계에서 종료 코드 137.
- `20261108T233653Z-171186c9`: 공식 수정 후 HumanEval 164/164. NoExtreme 일괄 MBPP 단계도 종료 코드 137.
- `20261108T234334Z-d6c27fe8`: 50개 배치로 첫 100개 정답/오답 대조 완료. 큰 정답 객체를 가진 묶음의 프로세스 큐 복제에서 메모리 한도 초과.

기존 Ollama 컨테이너의 모델 목록도 확인했지만 설치된 모델이 없었다.

## 유료 단계 견적 — 실행 안 함

동일한 과제에 일반 지침 1종과 주석/구조 2×2 조합을 적용하는 계획이다.
설명은 간결하게, 출력은 전체 코드로 고정한다.
**직접 설정 모드에서 조립한 지침**이며 실제 사용자 선택을 수집한 실험은 아니다.
20개 파일럿 과제는 결과를 보지 않고 SHA-256 정렬로 정했다.

| 범위 | 호출 수 | Luna | Sol |
|---|---:|---:|---:|
| 20과제 × 5조건 | 100 | 약 $0.07~0.23 | 약 $1.48~4.55 |
| HumanEval 164과제 × 5조건 | 820 | 약 $0.62~1.88 | 약 $12.41~37.60 |
| 542과제 × 5조건 | 2,710 | 약 $1.99~6.15 | 약 $39.74~122.99 |

2026-11-09의 Standard 공식 요금과 출력 1,024~4,096토큰/호출을 가정했다.
입력은 실제 토큰 수가 아니라 UTF-8 바이트 수 × 1.1 + 128/호출의 예산 값이다.
추론 토큰은 출력 예산에 포함하며 할인·재시도·GEPA·도구·세금·환전 수수료는 제외했다.
확정 청구 상한이 아니며, 유료 실행 전 모델·범위·요금을 다시 확인해야 한다.
근거: [Luna 공식 요금](https://developers.openai.com/api/docs/models/gpt-6-luna),
[Sol 공식 요금](https://developers.openai.com/api/docs/models/gpt-6.1-sol).

## 해석과 다음 검증

이번 결과는 **예시가 의도대로 구분되고, 공개 평가기를 재현 가능하게 연결했다**는 근거다.
아직 “8~10회 선택이면 사용자 취향을 충분히 알아낸다”, “우리 지침이 실제 과제에서 더 유용하다”는 근거가 아니다.
같은 계산을 이름·상수만 바꾼 예시가 많다는 한계도 그대로다.

새 과제에서 생성한 답변의 기능 정확도와 스타일 조건을 각각 측정하고,
실제 사용자에게 결과 선호·수정 시간을 따로 측정해야 한다.
현재 PC에서는 참조 대조를 통과한 HumanEval을 먼저 사용하고,
MBPP/255의 추가 검사 실패를 해결하기 전에는 MBPP 전체 비교 결과를 개인화 성능의 근거로 쓰지 않는다.
설명 방식과 부분 수정 출력, 8/10회와 더 많은 선택 횟수의 비교는 별도 실험이 필요하다.
20과제 파일럿은 연결 확인용이며 효과 결론용 표본으로 쓰지 않는다.

## 코드 검사

`tests/test_coding_public.py`와 기존 `tests/test_coding_elicitation.py`: **36개 통과**.
해시 변조, 네트워크 차단, 불완전 코드 맥락, 제한된 해석기의 위험 연산 거절,
요청에 정답이 유출되지 않는지, 누락된 결과와 시간 초과를 성공으로 세지 않는지,
공식 수정의 범위와 NoExtreme 차이를 확인했다.

재현 명령과 자세한 범위는 `benchmarks/coding_public/README.md`를 따른다.
