# 작은 개발팀용 브랜치와 첫 사용 안내 개선

사용자 요청으로 `master`에서 `codex/summary-coding-no-aws`를 만들었다.
문서 요약·코딩과 공통 기능을 유지하며 AWS 비용 보고 UI, 조회 API,
비교 도메인 진입점과 템플릿을 제외했다. 과거 실험·검사 자료와 기존 DB는 보존한다.

제품 방향은 작은 개발팀이 AI 결과에 대한 각자의 선호를 찾고 공통 지침으로
함께 사용하는 것이다. 인수인계 전용 서비스로 범위를 한정하지 않는다.

- 팀 프롬프트 → 팀 기준 맞추기: 비교 시작 버튼과 세 단계 안내를 추가했다.
- 서비스용 프롬프트 → 업무 지침 만들기: 개발팀 업무 설명 예시와 단계 안내를 추가했다.
- 프롬프트 다듬기 → 요청문 다듬기: 개발팀의 기존 요청을 개선하는 용도로 설명했다.
- 시스템 지침 직접 편집은 접어서 제공한다. 단순한 시험 자료는 폼으로 입력하고,
  복잡하거나 잘못된 자료와 앱 연동 모드에서는 JSON 편집을 유지한다.
- 기존 다수결·동률 처리, 저장·공유 권한, 실행·평가 방식은 바꾸지 않았다.

## 확인

- React 프로덕션 빌드 통과.
- Node 단위 테스트 27개 통과. 0·false 보존, 복잡한 입력의 JSON 편집 유지,
  선택 입력 제거와 다른 자료 보존을 포함한다.
- 무과금 Python 검사: 835 passed, 5 failed, 16 deselected.
  실패 5건은 변경하지 않은 `test_coding_ai_quality_stage4.py`에서 Windows의
  `frontend/node_modules/.bin/tsc` 실행 경로를 찾지 못한 `WinError 2`다.
  AWS 제외 API 검사와 나머지 요약·코딩·팀·작업 공간 검사는 통과했다.
- 첫 실행의 로컬 HTTP 권한 제한은 권한을 허용해 재실행하여 구분했다.
- 유료 모델 호출, 배포, 원격 push와 실제 사용자의 사용성 평가는 하지 않았다.

## 후속 검토

사용자 관찰로 메뉴 의미와 첫 완주를 확인한다. 팀 코드 전달 흐름, 의견이 갈린
항목의 합의 과정, 개발팀용 완성 예제, 자료 형식 입력의 추가 단순화를 검토한다.
현재 업무 설명 예시는 전용 기능이나 결과 품질 검증을 뜻하지 않는다.
