# 11/13~11/19 계획 실행과 최종 완료 기준

확인일: 2026-11-17. 기준 계획은 주간보고서 v0.9의 10쪽이다. 이 기록은 새 개발·검증의 근거이며 지난주 보고서 PDF를 소급 변경하지 않는다.

## 최종 목표와 범위

**사용자가 명시적으로 정한 요약 조건을 재사용 가능한 지침으로 만들고, 새 원문에서 조건 준수와 내용 보존을 따로 확인하는 제품을 완성한다.** 코딩의 AI 답변 방식 설정과 React 코드 스타일 비교는 기존 확장 기능으로 유지한다.

완료는 수동 프롬프트보다 좋은 점수가 나올 때까지 실험을 반복하는 것이 아니다. 같은 조건을 정직하게 전달하고, 실패와 미검증 영역을 구분하며, 재현 가능한 결과와 사용 흐름을 제공하는 것으로 판단한다. 실제 사용자 평가를 확보하지 못한다는 전제를 유지한다.

| 필수 산출물 | 최종 통과 기준 |
|---|---|
| 요약 제품 | 입력 → 조건 확인 → 충돌의 명시적 해결 → 지침·작업 분리 → 저장·새 작업 재사용이 연결된다. 입력을 몰래 자르거나 선택하지 않은 조건을 기본값으로 확정하지 않는다. |
| 코딩 두 기능 유지 | AI 답변 방식 설정과 React 3축 비교를 구분한다. 한·영 지침의 의미가 맞고 기존 저장본·실험 기록을 바꾸지 않는다. |
| 계정·공유·만료 | 개인·공유 자료의 접근 범위를 지킨다. 비교 ID만 알아도 다른 브라우저/로그인 세션의 원문·결과를 읽거나 변경할 수 없어야 한다. 만료·로그아웃·늦은 응답을 확인한다. |
| 비교 검증 | 개선에 쓰지 않은 자료, 고정 입력·기준·첫 응답, 수동·제품 비교, 조건/내용/타입/동작의 분리 결과와 실패 원자료가 남는다. 작은 파일럿과 AI 의미 검토의 한계를 쓴다. |
| 인계 문서 | 최신 코드·실행 방법·UC 및 WBS 연결·검증 결과·남은 제약을 같은 기준으로 정리한다. PDF와 원본의 기준일을 구별한다. |
| 최종 시연·제출 | 깨끗한 환경에서 설치·실행을 확인하고, 주요 흐름과 오류 복구를 시연한다. 발표자료·시연 영상/스크린샷·최종 보고서·제출 버전/태그를 준비한다. |

사람의 만족도·수정 시간 절감·숨은 선호 추정 정확도·팀 생산성·수동 대비 우위는 이번 필수 완료 조건이 아니다. GEPA 필수화, 추가 언어/프레임워크 확대, 유료 API 실험, 공개 배포 확대도 이번 작업에 추가하지 않는다. 기존 유료 기능은 유지하지만 검증에서 실행하지 않는다.

## 이번 주 변경

### React 한·영 지침 의미 정렬

`domains/coding/v2.yaml`을 새 경로로 만들고 React API와 Streamlit의 새 코딩 비교에 연결했다. 이전 `domains/coding.yaml`, 고정 실험 입력·출력, 보관한 프롬프트 본문은 변경하지 않는다.

팀 기준과 비교할 때도 이전 기본 생성문 전체와 정확히 일치하는 저장본은 기존 선택을 인식한다. 일부 문구만으로 선택을 추측하지 않으며 직접 수정한 지침은 계속 미확인으로 둔다. 이전 버전임을 화면에 알리고, 사용자가 새 조합을 요청할 때만 현재 지침으로 미리 보기를 만든다. 원본 저장 지침은 갱신하지 않는다.

| 조건 | 한국어·영어의 공통 의미 |
|---|---|
| 한 파일 | 컴포넌트·상태·스타일을 TSX 하나에 둔다. 별도 CSS 파일을 만들지 않는다. |
| 역할별 파일 | 컴포넌트와 스타일 **또는** 상태 로직을 역할별 파일로 분리한다. 불필요한 하위 컴포넌트·타입 전용 파일을 강제하지 않는다. |
| 타입 추론 | 추론 가능한 단순 변수·반환값·기본형 상태 타입을 반복하지 않는다. 빈 배열·null·의도한 유니언·CSS 제약·공개 Props·분리된 이벤트 함수의 필요한 타입은 허용한다. |
| 명시적 타입 | Props·매개변수·반환값·상태·주요 데이터 구조를 명시한다. |
| 공통 과제 | 기능 요구가 스타일보다 우선하며, 요구한 데이터·문구·동작을 보존한다. 임의 기능·라이브러리·진입 파일을 추가하지 않는다. |

기존 영문 inferred의 ‘공개 경계에만 타입’ 문구는 필요한 상태 타입과 충돌할 수 있었다. 영어 separated가 세 역할의 파일 분리를 모두 요구하는 것처럼 읽히던 차이도 정렬했다. 스타일 지침의 정렬을 모든 생성 코드의 품질 보장으로 해석하지 않는다.

### 비교 세션 정책

| 항목 | 확정한 동작 |
|---|---|
| 로그인 비교 | 생성한 계정의 **해당 로그인 세션**에 귀속한다. 같은 계정의 다른 로그인에서도 자동 공유하지 않는다. 장기 재사용은 보관함에 명시적으로 저장한다. |
| 익명 비교 | 서버가 만든 무작위 HttpOnly·SameSite=Lax 쿠키에 귀속한다. 다른 브라우저에는 세션 ID만 전달해도 접근되지 않는다. HTTPS 환경은 기존 Secure 설정을 따른다. |
| 로그인 전환 | 같은 익명 브라우저가 로그인/가입하면 그 브라우저의 비교만 새 로그인 세션으로 이전한다. 저장 제목·선택 결과를 유지하며 자동 저장하지 않는다. 다른 계정으로 전환하면 이전 계정의 비교를 폐기한다. |
| 종료 | 로그아웃·비밀번호 변경·계정 삭제는 해당 브라우저의 비교를 정리한다. 인증 자체의 만료/철회도 매 요청에서 재확인한다. |
| 만료 | 기본 생성 후 12시간이며 `PPT_SESSION_TTL_HOURS`로 설정한다. 선택·조회로 세션 수명을 연장하지 않는다. 새 세션 생성뿐 아니라 각 읽기/변경 시점에도 만료를 확인한다. 서버 재시작 또는 보관 상한 정리로 더 일찍 사라질 수 있다. |
| 보호 경로 | 조회, 선택, 되돌리기, 팀에 선택 반영, 최적화 시작·결과 조회에 같은 정책을 적용한다. 미존재·타인·만료는 공통 404로 응답한다. |
| 늦은 처리 | 선택 계산 후 소유권·만료·현재 상태를 다시 확인한다. 로그아웃/만료 후 최적화 결과가 세션·보고서를 다시 만들지 않는다. 이미 시작된 외부 호출을 취소하거나 비용을 되돌리는 기능은 아니다. |
| 화면 | 복귀 시 서버 확인 전에는 이전 결과를 표시하지 않는다. 권한 거절·만료에는 원문·비교·결과·미리보기·임시 복귀 정보를 지운다. 일시 장애는 선택 화면을 유지한다. 창 복귀와 서버가 알려준 만료 시각에도 재확인/정리한다. |

새로운 DB migration이나 라이브러리를 추가하지 않았다. 비교 원문과 후보는 기존처럼 서버 메모리 임시 보관이며 영구 저장으로 바꾸지 않는다. 지침 보관함·팀 기준·인수인계의 기존 권한 정책을 대체하지 않는다.

## 검증과 문서 연결

이번 실행의 결과와 절차는 [기술 검증](../verification/2026-11-17/README.md), 새 출력 비교는 [독립 파일럿](../../benchmarks/weekly_validation_2026_11_17/README.md)에 기록한다. 완료 여부는 해당 결과를 기준으로 하며, 구현만으로 검증 완료를 표시하지 않는다.

새 MACSum 영어 원문 6개와 React 합성 과제 8개에서 수동·제품 첫 응답 총 28개를 보존했다. 두 독립 익명 AI 검토자는 요약 조건 각 6/6, 핵심 사실 각 17/18, 전체 보존을 요청한 사례 각 5/5로 같은 판정을 냈다. 빠진 1개는 양쪽의 같은 일부생략 허용 사례였으며 모든 내용이 보존됐다고 보고하지 않는다. React는 양쪽 모두 strict 타입 8/8, 실제 React/JSDOM 동작 40/40, 세 스타일 축 일치 8/8이었다. 수동 대비 우위는 확인하지 못했다. 설명의 일본어 혼입과 요약 해석 경계도 원자료에 남겼다.

구현 수정 후 Python 전체 회귀 1,433개, 프론트 136개, 실제 Chromium 6개 시나리오와 프로덕션 빌드가 통과했다. Windows 권한으로 심볼릭 링크를 만들 수 없어 1개 검사는 건너뛰었고, 실제 모델 API 검사 16개는 제외했다. 유료 모델 API 호출 없이 검사했으며 큰 번들 경고는 남아 있다. 이번 주 계획의 구현·독립 출력 비교·회귀·원고 갱신을 완료했으나, 아래 최종 운영/제출 단계까지 완료한 것은 아니다.

UC-02-02(비교 시작), UC-03-01~04(예시 읽기·선택·되돌리기·종료)의 공통 접근 전제에 위 정책을 적용한다. 주 구현 연결은 기존처럼 WBS 3.1(요약), 3.2(React 비교)이며 접근 정책 보완은 3.3이다. 팀에 선택을 더하는 경로 역시 세션 소유권을 먼저 확인한다. 2.1~2.3은 정책·화면·명세 문서 보완, 4.1은 새 출력 비교, 4.2는 기능·권한 검사와 연결한다.

## 이후 남겨둘 일

기존 WBS의 최종 정리 기간은 11/20~12/18이다. 수업의 실제 제출 요구사항과 최종 마감일은 팀이 확인해야 하며, 이 문서가 교수자의 평가표를 대신하지 않는다.

1. 이번 결과에서 발견된 잔여 오류가 있다면 원자료를 보존한 채 수정하고, 변경 범위만 재검증한다(WBS 4.3).
2. 최종 데모용 환경·계정·합성 자료를 정하고 새 설치에서 실행·백업/복원·주요 실패 복구를 한 번 점검한다(WBS 5.1).
3. 최종 보고서와 발표자료에 제품 목적, 구현 범위, 수동과의 비교, 동률·실패·미측정 한계를 넣고 최신 분석·설계서/WBS PDF를 발행한다(WBS 5.2).
4. 팀원과 주요 흐름을 직접 시연하고 제출 체크리스트에 맞춰 파일·저장소·실행 안내·최종 버전을 인계한다(WBS 5.3). 이 팀 내부 확인을 사용자 효과 실험으로 세지 않는다.
