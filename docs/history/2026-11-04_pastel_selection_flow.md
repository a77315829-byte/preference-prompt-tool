# 코딩 화면을 파스텔 선택 흐름으로 정리

기본값이 채워진 설정에서 바로 지침을 만들 수 있어 사용자 선택의 역할이 흐릿했던 문제를 고쳤다. 메인의 연보라·민트·살구·하늘색을 환경 선택, 예시 비교, 선택 확인, 결과와 저장 영역에 이어 쓴다.

- 새 사용자는 언어·프레임워크와 네 가지 작성 선호가 미선택이다. 프레임워크 없이 진행하는 것도 직접 누른다. 네 선호가 확인되기 전에는 생성 버튼을 활성화하지 않는다.
- 비교 조회 API의 기존 검증 형식에 필요한 기본값은 예시 조회에만 사용한다. 미선택 UI나 생성·저장 값으로 채우지 않는다. 비교를 보류한 미선택 항목은 확인 카드에서 직접 고른다.
- 예시 A/B 버튼 선택을 테두리·체크·선택 상태로 표시하고 다음 버튼을 따로 누른다. 파일을 나눈 예시는 파일 이름 버튼으로 전환한다. 취소 시 임시 비교 선택은 반영하지 않는다.
- 결과는 네 가지 선택 요약과 복사·저장 버튼을 먼저 보여 준다. Markdown 형태의 프롬프트 전문은 필요할 때 펼친다.
- 보관함에서도 저장한 네 가지 코딩 선호를 같은 파스텔 카드로 표시해 예시 선택/직접 설정의 출처를 확인한다.
- 저장한 환경·선호·비교 출처 재사용을 유지한다. 환경 변경은 선택을 초기화하고, 확인 카드에서 한 항목을 다시 고르면 그 항목만 직접 선택으로 기록한다. 기존 저장본은 갱신하지 않는다.
- 질문 전환 시 스크롤과 포커스를 이동하고 단계 표시를 유지한다. 선택된 값은 색상에 더해 체크와 텍스트로 표시한다. 언어 목록·사용자 입력·기존 React 비교·로그인·저장 실패 복구를 유지한다.

새 모듈은 `CodingEnvironmentPicker.jsx`, `CodingPreferenceChoices.jsx`, `CodingExampleCode.jsx`, `codingFlow.css`다. 엔진·백엔드 지침 형식·DB schema·의존성은 바꾸지 않았다. 화면 개편으로 개인화 효과가 개선됐다는 주장은 별도 사용자 검증이 필요하다.

검증: 실제 UI 컴포넌트 흐름 8개를 포함한 프론트 전체 68개, 관련 Python/API 72개와 프론트 빌드 통과. 미선택 생성 차단, 보류 후 명시적 선택, 이전 선택 수정, 취소, 파일 전환, 저장/재사용 원본 유지, 로그인·실패 상태 보존, 기존 React 진입을 검사했다. 브라우저에서 환경·비교·확인·완성 화면을 캡처하고 별도 미리보기 DB에 새 결과를 저장했다.
