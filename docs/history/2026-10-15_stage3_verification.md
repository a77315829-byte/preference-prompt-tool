## 실제 AI 생성 코드 재검사

- 2026-10-14 실제 API로 생성한 `cart_quantity` A/B를 재사용했다. 무료 데모 코드는 아니다.
- 원본 기록: `data/coding_ai_quality_holdout_v4_final_trial.json`.
- `domains/coding.yaml`, `service.py`, `engine/generator.py`의 현재 해시가 원본 기록과 일치함을 확인했다.
- 생성 코드를 읽은 뒤 평가기를 실행했다. A는 TSX/CSS 파일 분리, B는 한 TSX 파일이다.
- 두 코드 모두 타입 검사, 빌드, 수량·금액 관련 지정 동작 검사 4개를 통과했다. 스타일 검사에서도 문제가 보고되지 않았다.
- 재검사 결과: `data/coding_stage3_2026-10-15_evaluation.json` (data는 커밋하지 않는다).
- 이번 실행의 새 모델 API 호출은 0회다. 과거 생성 비용이 없었다는 뜻은 아니다.
- 이는 지정한 시나리오의 통과이며, 모든 입력의 기능 동일성이나 사람의 취향 만족도를 입증하지 않는다.

## 두 로그인 계정의 팀 프롬프트

`tests/test_team.py`에 독립 쿠키를 사용하는 두 계정 통합 테스트를 추가했다.
임시 SQLite DB에서만 실행하므로 실제 사용자 계정을 생성하거나 변경하지 않는다.

- 가입 → 로그아웃 → 로그인 → 각자의 코딩 A/B 선택 → 같은 팀 참여.
- 두 사람이 같은 취향을 고른 스타일 관리·타입 작성은 각각 2표로 반영된다.
- 코드 구조를 반대로 고르면 1:1 동률로 표시된다.
- 언어별 팀 프롬프트가 합산된 추정 결과로 생성되는지 대조했다.
- 요청 본문의 이름으로 다른 계정을 사칭하지 못하고, 재참여해도 표가 늘지 않는다.
- 팀 저장소를 DB에서 다시 읽어도 결과가 유지되고, 과제 원문은 팀 응답에 포함되지 않는다.

이 테스트의 선택자는 축 정보를 읽는 모의 사용자다. 실제 사람 평가나 AI 품질 평가는 아니다.

## AWS 및 남은 확인

- boto3는 설치되어 있으나 로컬에서 사용할 AWS 자격 증명이 확인되지 않아 실제 Cost Explorer는 호출하지 않았다.
- 현재 실제 조회 구현은 서비스별 비용 보고다. 유휴 리소스나 비용 누수를 확정하는 기능으로 설명하면 안 된다.
- 다음 단계는 발표 문서에 실제 AI 기록 재검사·자동 테스트·사람 평가를 구분해 반영하는 것이다.
- 실제 AWS 조회와 사람의 코딩 스타일 만족도 평가는 별도 확인이 필요하다.
- 이번 단계에서 커밋·푸시는 하지 않았다.
