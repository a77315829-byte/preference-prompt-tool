# 2026-11-04 팀 업무 정리 UI와 멘토링 PDF 갱신

## 팀 업무 정리

- 새 작업 작성과 받은 링크 열기를 파스텔 카드 두 개로 구분했다.
- 상단에 기록 → 자료와 계정 지정 → 이어받기의 세 단계를 안내한다. 개인 저장과 공유의 차이는 유지한다.
- 목록은 전체/작성/수신 분류와 개수, 작업 상태·담당자·버전을 표시하고 현재 작업을 강조한다.
- 새 작업 버튼은 작성 영역으로 이동한다. 작성 폼의 목적·현재 진행·남은 일·참고 자료·프롬프트를 별도 카드로 구분하고 필수 입력을 표시한다.
- 계정별 권한, 공유·이어받기·버전 충돌, 첨부 저장·열기·다운로드 API는 변경하지 않았다. 새 CSS는 인수인계 화면에만 적용한다.

## 소개 자료

- `output/pdf/프로젝트소개_멘토링_UI_GEPA_업데이트_2026-11-04.pdf`: 본문 20장 + 질의응답용 부록 7장.
- 기존 회색 브라우저 창 디자인과 검증한 기존 페이지를 유지하면서 코딩 개발 환경, 결과, 인수인계 시작·맥락 화면을 교체했다. 프레임워크 비교·첨부 자료 상세 화면을 추가했다.
- GEPA의 역할과 기존 요약/React 최적화 경로, 새 코딩 화면의 미연결 상태, FastAPI 평가 과제·독립 검증·개선안 별도 저장이라는 후속 계획을 2장으로 구분했다. 실제 최적화를 실행하지 않았다.
- WBS에 FastAPI 평가 기준 준비와 제한된 GEPA 시범 검토를 반영했다. R&R은 수행 실적이 아닌 기존 배정 제안임을 유지한다.
- `docs/mentor/2026-11-04/발표대본_UI_GEPA.md`는 최신 PDF 순서의 300초 대본이다. 이전 PPT·PDF·대본을 덮어쓰지 않았다.
- 최신 실제 캡처 원본은 같은 폴더의 `screens-v2/`에 보관한다. 생성/검증 작업 파일은 `data/mentor_deck_build/update_pdf_v2.py`, `check_pdf_v2.py`이다.

## 검증

- 프론트 테스트 69개 통과, Vite 빌드 통과.
- 로컬 예시 계정으로 새 인수인계 시작 화면, 저장된 작업의 맥락·자료·첨부와 최신 코딩 선택→프롬프트 결과를 직접 확인하고 캡처했다. 실제 사용자 자료나 모델 호출 결과를 사용하지 않았다.
- 최종 PDF 27페이지를 Poppler로 다시 렌더링해 전체 연락판과 변경 페이지를 육안 확인했다. 한글 폰트·줄바꿈·카드·표·캡처 배치를 확인했다.
- 페이지 크기 1440×810, 목차 27개, 본문 발표 시간 합계 300초를 검사했다.
- GEPA 개념 근거는 [공식 FAQ](https://gepa-ai.github.io/gepa/guides/faq/), 구현 상태는 `service.optimize()`와 API 서버의 `_start_optimize`를 따른다.
