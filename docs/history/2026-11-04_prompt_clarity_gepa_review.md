# 2026-11-04 코딩 프롬프트 구분과 GEPA 연결 검토

## 화면 변경

- 모호한 확인 개수를 `답변 방식 4가지 선택 완료`로 변경했다. 미완료 상태에서는 선택한 수와 남은 수를 표시한다.
- 결과에서 `내가 고른 답변 방식` 카드와 `AI에 붙여넣을 프롬프트` 전문을 나눠 바로 보여 준다. 작은 화면에서는 실제 프롬프트를 먼저 표시한다.
- 복사 → AI 대화창에 붙여넣기 → 실제 작업 요청 덧붙이기를 안내한다. 선택 입력한 작업 요청과 함께 복사할 수 있다.
- 보관함에는 기존처럼 지침과 설정만 저장한다. 이번 작업 요청은 저장 API로 보내지 않는다.

## GEPA 현황과 후속 범위

기존 `service.optimize()`와 `/api/sessions/{session_id}/optimize`는 완료한 요약·React 비교 세션의 도메인과 평가 함수를 사용한다. 새 언어·프레임워크 경로는 `coding_instructions.py`에서 선택한 문장을 조립하며 GEPA에 연결하지 않았다. 이번 변경에서도 모델 호출이나 최적화를 실행하지 않았다.

연결은 가능하다. 먼저 Python/FastAPI 한 조합에서 현재 지침을 초기 후보로 삼고, 여러 개발 과제에 대한 기능 검사와 사용자가 고른 설명·주석·구성·출력 선호 평가를 마련한다. 개선에 사용하지 않은 별도 과제 및 사용자 비교로 효과를 확인해야 한다. 기존 React 평가 함수를 네 가지 새 선호에 그대로 적용할 수는 없다.

언어·프레임워크와 명시적으로 고른 선호를 제약으로 유지하고, GEPA가 제안한 본문과 평가 결과를 원본과 비교하는 방식이 적절하다. 개선안은 원본을 덮어쓰지 않고 별도 항목으로 보관한다. 현재 보관함의 직접 설정 경로는 조립한 본문과 설정의 일치를 검사하므로, 임의로 바뀐 최적화 본문을 동일한 직접 설정 기록으로 저장하지 말고 파생 버전·최적화 출처를 별도로 설계해야 한다. 모델 호출 횟수·비용·대기 시간과 사용자 채택 여부도 검증 대상이다.

개념 확인: [GEPA 공식 FAQ](https://gepa-ai.github.io/gepa/guides/faq/), [optimize API](https://gepa-ai.github.io/gepa/api/core/optimize/). 최신 문서의 API 예제를 현재 설치 버전에 그대로 적용하지 않는다.

## 확인

- 프론트 테스트 69개 통과, Vite 빌드 통과.
- 실제 브라우저에서 완료 문구, 선택 요약과 펼치지 않은 프롬프트, 사용 안내, 작업 요청과 함께 복사를 확인했다. 클립보드가 지침과 작업 요청을 합친 값과 일치했다.
- 회귀 테스트로 작업 요청을 함께 복사해도 저장 API에는 원래 지침만 전달됨을 확인했다. 선택을 바꿔 다시 생성하면 복사 완료 상태가 초기화되며 이전 저장 항목은 유지된다.
