# 팀 생성·초대·선호 반영 흐름

`codex/summary-coding-no-aws`에서 개인용 비교를 유지하면서 팀 참여 흐름을 추가했다.

## 사용자 흐름

- 첫 화면의 팀 진입점에서 새 팀 만들기 또는 초대받아서 참여하기를 선택한다.
- 팀 이름·비교 항목을 정하면 빈 팀과 임의 코드가 생성된다. 생성만으로 모델을 호출하거나 투표하지 않는다.
- 초대 링크는 같은 서비스의 `?team=<code>`로 연결된다. 링크를 열면 팀을 확인하고 같은 항목에서 비교한다.
- 비교 중에 팀 맥락을 표시하며 요약 언어 전환으로 다른 기준에 들어가지 못하게 한다.
- 비교를 마치면 결과 맨 위에서 개인 이름·계정을 확인하고 명시적으로 선호를 합친다.
- 개인용 비교 결과에서도 새 팀을 만들거나 받은 초대를 확인한 뒤 기존 선택을 합칠 수 있다.
- 합친 뒤 성공 안내, 팀 기준, 추가 초대와 팀 안내로 돌아가는 경로를 제공한다.

## 저장·호환성

- SQLite migration 5가 `teams.name`만 추가한다. 기존 팀은 코드를 표시 이름으로 사용한다.
- 기존 코드·투표·다수결·동률 처리와 팀별 상한은 유지한다. 빈 팀도 생성 상한과 유휴 정리 대상이다.
- 로그인한 생성자는 아직 표가 없는 팀도 내 팀 목록에서 찾을 수 있다.
- 새 초대 참여는 기존 팀을 요구하며, 사라진 초대로 팀을 다시 만들지 않는다.
- 초대 링크는 기존 팀 코드와 같은 접근 수단이다. 모델 입력 원문은 팀에 공유하지 않는다.
- localhost 주소는 다른 기기의 초대에 쓸 수 없음을 복사 칸 옆에 안내한다.

## 확인

- Python: 841 passed, 21 deselected. 유료 API 16건과 이전에 확인한 Windows 코딩 평가기 실행 경로 오류 5건을 제외했다.
- Node: 31 passed. 화면 상태 전환 테스트는 실제 React 화면을 사용하고 HTTP·애니메이션만 대체한다.
  팀 생성 → 초대 복사 → 비교 → 이름 확인 → 합치기, 초대 URL 직접 진입,
  요약 항목 유지, 없는 초대의 오류 처리를 포함한다.
- 프로덕션 빌드·Python 구문·diff 공백 검사 통과.
- 기존 개발 의존성 일부가 빠져 있어 lockfile 기준 `npm ci`로 설치했다. 새 의존성은 추가하지 않았다.
- 실제 모델 호출·원격 배포·사용자 만족도 검증은 하지 않았다.
