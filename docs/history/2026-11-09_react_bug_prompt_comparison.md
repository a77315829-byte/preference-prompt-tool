# 실제 React 버그 수정: 일반 지침과 생성 지침의 독립 비교

2026-11-09. 사용자가 독립된 Codex 보조 에이전트 두 개로 비교하는 실행을 승인했다.

**이번 1건에서는 맞춤 지침의 기능 정확도·작업 시간 우위가 확인되지 않았다.** 두 수정안 모두 고정 검사 9개를 통과했고, 맞춤 조건의 에이전트 작업 구간이 약 10초 길었다. 사람의 수정 시간·선호는 측정하지 않았다.

## 실제 과제와 재현

- 기준 커밋: `3b6b550418dcaf8cb184563f699bdc727f5dd54b`.
- 실제 버그: 코딩 지침 결과/보관함에서 상위 작업 요청을 나중에 입력하거나 바꿔도 ‘실제 작업 비교’의 요청 입력란은 처음 값에 머물렀다. ‘새 작업 비교’도 이전 요청을 재사용했다.
- 원인: `CodingTrialPanel`은 `useState` 초기값에서만 `task` prop을 읽었다. 상위 입력은 이후에 계속 변하지만 비교 양식은 이를 반영하지 않았다.
- 기대 동작: 직접 편집 전에는 최신 부모 요청을 따르되, 직접 지운 입력이나 원문으로 되돌린 입력도 사용자가 편집한 값으로 보호한다. 저장한 기록은 불변으로 두고 새 비교를 확인한 시점에 최신 요청으로 다시 시작한다.
- 실제 소스는 **React 19 / JavaScript JSX**다. `frontend/src`에 `.ts`/`.tsx` 파일이 없으므로 TypeScript 컴파일 정확도나 TS 타입 안전성의 실험으로 해석하지 않는다.

수정 전에 작성한 검사에서 **5/9 통과, 4/9 실패**를 확인했다. 실패 항목은 늦은 부모 입력, 부모 변경/삭제, 제출 후 새 비교 초기화, 저장 기록에서 새 비교 초기화였다. 기대한 버그를 주입한 합성 과제가 아니라 현재 커밋의 실제 결함이다.

## 같은 조건으로 비교한 내용

| 항목 | 일반 조건 | 맞춤 조건 |
|---|---|---|
| 지침 생성 | `general_prompt(profile, [])` | `build_coding_instructions(profile)` |
| 공통 개발 환경 | JavaScript / React | JavaScript / React |
| 작성 선호 | 별도 네 항목 없음 | 핵심 설명, 필요한 주석, 간결한 구성, 변경 부분 중심 |
| 추가 선호·팀 규칙·GEPA | 없음 | 없음 |
| 코드·과제·완료 조건 | 같은 커밋·같은 문구 | 같음 |
| 에이전트 | 부모 대화 이력 없는 새 실행 | 부모 대화 이력 없는 새 실행 |
| 모델 설정 | 현재 세션 설정 상속, 별도 모델 지정 없음 | 같음 |
| 로컬 의존성 | 기존 설치 패키지 사용 | 같음 |
| 실행 횟수·상한 | 1회, 작업 8분 이내 | 같음 |

맞춤 프로필은 **실험자가 고정한 설정**이다. 사용자의 실제 선호를 찾아냈다는 결과가 아니며 8~10회 선택의 충분성도 평가하지 않는다. 두 에이전트에는 숨긴 평가 코드 대신 동일한 행동 요구사항을 주었다. 평가기는 첫 후보 생성 전에 고정했고, 두 결과를 보고 판정 기준을 바꾸지 않았다.

## 측정 결과

| 지표 | 일반 지침 | 맞춤 지침 | 관측 차이 |
|---|---:|---:|---|
| 에이전트 작업 시간 | 156.737초 (2분 36.7초) | 166.895초 (2분 46.9초) | 맞춤 +10.158초 |
| 부모의 독립 검사 시간 | 14.744초 | 14.383초 | 실질적 우열 해석 안 함 |
| 고정 기능 검사 | 9/9 통과 | 9/9 통과 | 차이 없음 |
| 기존 프로덕션 파일 변경 | 1개 | 1개 | 같음 |
| 프로덕션 변경 줄 | +14 / −2 | +14 / −2 | 같음 |
| 첫 제출 후 추가 수정 | 불필요 | 불필요 | 둘 다 첫 제출 통과 |
| 사람이 답변을 적용·수정한 시간 | 미측정 | 미측정 | 참여자가 없음 |
| 사용자가 더 선호한 답변 | 미측정 | 미측정 | 참여자가 없음 |
| 별도 모델 API 요청 | 0회 | 0회 | 현재 Codex 실행 사용 |

작업 구간은 최초 도구 호출에 저장한 UTC 시각부터 최종 도구 호출에 저장한 제출 시각까지다. 분석·파일 수정·에이전트가 선택한 자체 검사를 포함한다. 첫 도구 호출 이전의 응답 지연, 부모의 과제 선정·실험 준비·결과 정리 시간은 포함하지 않는다. 실제 수정 타이핑 시간만 잰 수치가 아니다.

- 일반 실행: `2026-11-09T07:41:27.0014288Z` → `07:44:03.7386219Z`.
- 맞춤 실행: `2026-11-09T07:41:40.6592761Z` → `07:44:27.5540182Z`.

두 후보의 접근은 거의 같았다. 일반안은 사용자의 편집 여부를 React state로, 맞춤안은 ref로 추적했다. 둘 다 편집하지 않은 초안만 동기화하고 확인한 새 비교에서 편집 표시를 초기화했다. 이 차이를 품질·성능 우열로 판단하지 않았다.

## 한계와 실행 중 이탈

1. 버그 1개, 조건당 1회다. 약 10초 차이를 프롬프트의 인과 효과나 일반적인 우열로 해석할 수 없다. 같은 호스트에서 두 실행이 겹쳤으며 도구·모델 지연과 자원 경쟁도 포함된다.
2. 9/9는 미리 정한 행동 시나리오 통과율이다. 전체 앱 기능·보안·모바일 브라우저·TypeScript 타입 정확도가 100%라는 뜻이 아니다. React를 JSDOM에 렌더링하고 HTTP를 모의 응답으로 대체했다.
3. 맞춤 실행은 읽기 전용으로 사용하도록 지정한 공용 `node_modules`에 `.ignored-output.js` 컴파일 임시 파일을 작성했다가 제거했다고 보고했다. 부모는 그 파일이 없음을 확인했고 두 후보 모두 지정한 프로덕션 파일 이외 기존 프론트 파일은 바꾸지 않았음을 대조했다. 별도 프로세스/파일시스템 샌드박스가 완전히 분리된 실험은 아니며 이 절차 위반도 결과에 기록한다.
4. 두 실행이 자체 검사에 쓴 테스트 코드와 고정 평가는 다르다. 원본 코드에 대한 고정 검사를 먼저 수행한 사실과 후보 결과를 모두 보존했다.
5. 현재 측정으로 ‘우리 방법이 실무에서 시간을 줄인다’, ‘개인 선호를 잘 추정한다’, ‘일반 프롬프트보다 정확하다’고 주장하지 않는다.

## 프로젝트 반영과 다음 확인

두 안의 고정 검사 결과가 같아 검토한 일반안의 상태 추적 버전을 현재 프로젝트에 반영했다. 맞춤안도 패치로 보관했다. 최신 요청 자동 반영·직접 입력 보호·새 비교 초기화의 9개 검사는 정규 프론트 회귀 검사에 편입했다.

반영 후 전체 프론트엔드 검사 **105/105 통과**, 프로덕션 빌드 통과. 기존 주 번들 크기 경고는 남아 있다. 이번 변경은 프론트엔드와 실험 자료에 한정했으며 백엔드 전체 검사를 반복 실행하지 않았다.

반복 검증에서는 실제 개발자가 수행하는 버그/기능 과제를 여러 개 정하고, 첫 선호 설정 시간과 반복 사용의 수정 시간을 따로 측정해야 한다. 생성 결과의 기능 통과와 직접 선호도 계속 분리한다. 현재 자료에 임의의 사용자 만족도나 수정 시간을 채우지 않는다.

## 유료 API 없이 할 수 있는 범위

**이번처럼 Codex 안에서 독립 에이전트로 후보를 만들고 로컬 검사로 비교할 수 있다.** 프로젝트의 별도 유료 모델 API를 호출하지 않았고 새 라이브러리를 설치하지 않았다. 이 방식은 서비스 자체의 자동 AI 실행 기능과는 별도다.

Codex 자체를 무조건 무료라고 뜻하지는 않는다. 공식 문서는 ChatGPT 로그인은 구독 접근, API 키 로그인은 사용량 과금으로 구분한다. 구독 한도나 구매한 크레딧이 소비될 수 있으며, 이 세션에서는 계정 잔여량·실제 청구를 조회하지 않았다. 한도를 늘리기 위한 크레딧 구매·API 전환은 실행하지 않았다. [공식 인증 안내](https://learn.chatgpt.com/docs/auth), [공식 요금 안내](https://learn.chatgpt.com/docs/pricing).
