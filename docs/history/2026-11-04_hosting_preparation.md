# Microstone 외부 접속용 배포 준비

## 현재 범위

- 목적은 대회 전용 시연이 아니라 로컬 PC를 꺼도 접속할 수 있는 개인 서비스 운영이다.
- GitHub 브랜치가 `microstone`으로 변경돼 있음을 확인하고 로컬 이름·추적 대상도 맞췄다. 이전 PR #12는 이름 변경 시 닫힌 상태이며 이력은 유지한다.
- Render 계정 연결은 확인했다. 워크스페이스 확인·비용 승인을 거쳐 서버를 생성한 상태는 아니다. 서버·도메인을 생성하거나 결제하지 않았다.
- 사용자가 비용 부담을 밝혀 유료 생성은 보류했다. 무료 VM의 자원 할당·저장 유지 조건을 먼저 확인한다.

## 준비한 변경

- `hosting_server.py`: 빌드된 React와 기존 API를 한 서버에서 제공한다. 원래 로컬 API/Vite 실행 방식은 유지한다.
- 파일 경로 탈출·숨김 파일·소스 맵을 차단한다. 공개 요청의 `X-Forwarded-Host`를 Origin 허용 근거로 신뢰하지 않는다.
- Docker는 기존 Python/Node/TypeScript 의존성만 사용한다. 로컬 `.env`·DB·캐시·보고서·임시 파일을 빌드에 포함하지 않는다.
- DB와 첨부, 응답 캐시를 `/var/data` 볼륨에 보존한다. 실제 AI·환경별 GEPA 호출은 초기 설정에서 명시적으로 끈다.
- `render.yaml`은 월 기본 $7.25(서버 $7 + 1GB 디스크 $0.25)의 유료 선택지다. 세금·초과 사용량·AI·도메인은 별도이며 생성 전 요금을 확인한다.
- 무료 가상서버에서도 같은 Docker 이미지와 볼륨 구성을 재사용할 수 있다. 실제 VM 할당과 ARM 컨테이너 빌드는 확인하지 않았다.
- GitHub Actions에는 격리된 컨테이너/볼륨의 로그인·저장·첨부·데모·재시작 보존 검사를 추가했다. 실제 클라우드 리소스 생성과 AI 호출은 없다.

## 로컬 확인

- 최초 호스팅·기존 API 검사: 37개 통과, Windows 심볼릭 링크 생성 권한에 따른 1개 건너뜀.
- 저장·인수인계·첨부를 포함한 회귀: 68개 통과, 같은 심볼릭 링크 검사 1개 건너뜀.
- 프론트 테스트 86개 통과, 배포 빌드 통과.
- 공개용 진입점을 별도 프로세스로 시작해 예시 계정·개인 지침·인수인계·첨부와 요약/코딩 데모를 확인했다. 프로세스 종료·재시작 뒤 세션·지침·작업·첨부가 유지됐다.
- Render의 현행 공개 JSON Schema로 설정 형식을 검증했다. CLI/플랫폼 자원 검증이나 실제 배포 성공을 뜻하지 않는다.
- 로컬 Docker는 설치돼 있지만 데몬 연결이 되지 않아 컨테이너 빌드를 검증하지 못했다. Linux CI에서 별도로 확인한다.

초기 검사에서는 AUTH가 참조하는 DB까지 교체하지 않은 테스트 fixture 문제를 발견했다.
fixture의 DB·AUTH를 함께 격리했고, 그 검사에서 만든 빈 합성 계정만 생성 시각·테스트 비밀번호·소유 자료 없음 확인 후 제거했다.
실제 사용자 계정과 저장 자료를 삭제하지 않았다.

## 배포할 때 남은 확인

- 선택한 제공자의 계정·무료 자원 할당 여부와 유지 조건 확인
- HTTPS 프록시·운영 백업·도메인 DNS 연결
- 실제 공개 주소의 로그인·보관함·공유·첨부 권한 검사
- 유료 AI를 켜기 전 모델 설정·독립 스위치·사용량과 제공자 예산 확인

무료 Render에 지금의 SQLite를 그대로 두면 휴면·재시작 때 자료가 사라진다. 무료 VM과 혼동하지 않는다.
운영 방법과 공식 근거는 [배포 안내](../DEPLOYMENT.md)에 정리했다.
