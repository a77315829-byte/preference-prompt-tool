# 2026-11-04 코딩 답변 확인 v2

## 요청과 적용 범위

제목에 붙은 단계 번호를 인식하고, 주석·클래스 개수만으로 선호 반영을 판정하는 문제를 고쳤다. 공통 답변 확인은 목록 14개 언어와 직접 입력 환경에 적용했다. 자동 GEPA·환경별 기능 정적 검사는 현재 Python/FastAPI와 Java/Spring Boot만 지원하며 다른 환경까지 연결했다고 표시하지 않는다.

## 구현

- `coding_answer_review.py`는 코드 블록 밖의 제목/일반 번호·단계/목록 표시를 인식한다. `### 1.`·`## 2)`·`1단계` 등은 포함하고 코드 안 번호·버전 숫자는 단계로 취급하지 않는다.
- 주석과 역할 구성은 `None`(사람 확인)이며 개수로 점수화하지 않는다. 실제 주석 일부와 선언/파일 단서, 역할 간 연결·작업 규모·변경 범위에 관한 확인 질문을 제공한다. 단서 추출은 내용의 적절함을 검증하는 의미 분석기가 아니다. 언어별 모든 주석/선언 문법을 완전히 파싱한다고 주장하지 않는다.
- FastAPI/Spring Boot 평가 버전을 각각 `*-static-v2`로 올렸다. 기능 정적 검사 65%는 유지하며 자동 형식 35%는 설명/출력 두 항목에만 배분한다. 주석/역할 구성의 수동 판단은 자동 점수와 GEPA 후보 선택에 넣지 않는다. GEPA 피드백에도 주석/클래스 수를 늘려 점수를 올리지 않도록 안내한다.
- v1 저장 기록은 재계산하지 않고 v2와 직접 비교하지 않는다. 새 숫자가 과거 74점보다 높아져도 개선 효과로 해석할 수 없다. 평가 버전이 달라도 같은 모델 요청은 기존 v1 응답 캐시를 재사용한다.
- GEPA 별도 과제의 실제 답변 아래 네 선호별 `잘 맞아요 / 보완이 필요해요 / 판단 보류` 버튼을 추가했다. 기본 선택은 없고 과제를 바꿔도 유지한다. 같은 원본 유지 답변은 중복 판단을 받지 않는다.
- 새 후보를 저장할 때만 선택한 수동 기록을 함께 `human_review`로 보관한다. 서버는 소유권·준비된 과제 ID·답변 종류·허용 항목/값을 검사한다. 점수와 원본·기존 보관함 항목은 그대로 유지하고 저장 뒤 재열람할 수 있다. 저장한 항목에 수동 기록을 덮어쓰지 않는다.
- 모든 환경에 접힌 `받은 AI 답변 직접 확인 · 모든 언어` 패널을 제공한다. 실제 답변을 붙이고 버튼을 눌러 단서를 확인한 뒤 네 선호를 직접 고른다. POST `/api/coding-instructions/review`는 검증된 개발 환경과 최대 24,000자의 답변을 받으며 로그인·모델 호출 없이 동작한다. 코드 실행·외부 AI 전송·보관함 자동 저장은 없다. 이 패널의 판단은 화면 내 임시 기록이며 답변을 바꾸면 초기화한다.
- 다른 언어에서 GEPA가 없는 이유와 현재 지원 범위를 표시한다. 후속 자동 개선은 기존 React 비교 자료를 활용할 수 있는 JavaScript/TypeScript 등부터 독립 과제와 기능 검사, 사람 판단과의 일치 여부를 준비해 연결한다.

## 검증과 한계

- Python 관련 검사 54개 통과: 제목 번호/코드 안 번호 구분, 주석·빈 클래스 추가로 점수 부풀리기 방지, 변경 부분의 미기록 구조 처리, 목록 언어와 직접 입력 환경, 문자열 속 가짜 주석 제외, 입력 제한, 수동 기록 검증·소유권·새 항목 저장·기존 보존, v1 응답 캐시 재사용, 기존 두 환경 GEPA·보관함을 검사했다.
- 프론트 전체 79개 및 Vite 빌드 통과. C++의 실제 입력 흐름, 수동 선택 초기화, GEPA 후보 전후의 직접 판단·과제 전환·저장·재열람과 v1 기록 유지도 포함한다.
- 기존 실제 Spring Boot 응답을 공통 패널에 붙여 확인했다. 과거 v1이 놓친 제목의 번호 두 곳을 인식했고 실제 주석의 오버플로 주의 설명을 단서로 표시했다. 네 항목의 직접 선택도 화면에서 확인했다. 이번 확인을 위해 새 모델을 호출하거나 생성 코드를 실행하지 않았다.
- `data/coding-answer-human-review-v2.jpg`·`data/coding-answer-steps-review-v2.jpg`는 예시 계정에서 촬영한 화면이다. 기존 보관함 15개 행의 전체 해시가 같은 것을 확인했다. 이번 v2의 실제 모델 최적화 효과를 입증한 것은 아니며, 실제 GEPA 엔진에는 테스트 모델을 연결해 회귀 검증했다.

사람 판단과 형식 검사 결과의 일치, 서로 다른 실제 업무에서의 효용, 신규 환경의 기능 정확성 검사는 후속 검증 범위다. 라이브러리·DB migration·`engine/` 변경은 없다.
