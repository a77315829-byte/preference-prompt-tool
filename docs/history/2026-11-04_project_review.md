# 2026-11-04 전체 흐름 검토와 문서 갱신

## 확인 범위와 결과

현재 작업 트리에서 유료 API를 제외한 회귀 검사, 실제 React 앱을 마운트한 상태 전환 재현,
로컬 실행 화면의 예시 선택·저장·재사용·인수인계 작성을 확인했다. 실제 모델을 호출하거나 일반적인 품질 향상을 검증한 작업은 아니다.

| 검사 | 결과 |
|---|---|
| `node --test "frontend/src/**/*.test.js"` | 86개 통과 |
| `npm run build --prefix frontend` | 통과 |
| `.venv/Scripts/python.exe -m pytest -m "not api" -q --tb=short` | 1,083개 통과·1개 실패, API 검사 16개 제외, 470.53초 |
| 실패한 검사만 UTF-8 모드로 재실행 | 1개 통과. 전체 회귀를 UTF-8 모드로 다시 실행했다고 보고하지 않음 |

초기에는 샌드박스가 로컬 HTTP 소켓을 막아 `WinError 10013`이 발생했다.
로컬 통신 권한을 확보한 뒤 전체 검사를 다시 실행한 결과가 위 표다.

## 먼저 보완할 기능

### 1. 상단 메뉴 이동 시 초안 소실

- 재현: 인수인계를 새로 작성해 목적을 입력한다. 상단 `내 선호 보관함`으로 이동했다 돌아오면 내용이 사라지며 확인창도 뜨지 않는다.
- 코딩에서도 언어·선호·프롬프트를 만들고 이번 작업을 입력한 뒤 같은 방식으로 이동하면 초기 상태로 돌아간다.
- 원인: `frontend/src/app/App.jsx`의 상단 메뉴는 곧바로 화면을 바꾼다. 각 기능 안의 `leaveOk`가 이 경로에 적용되지 않으며, 코딩 상태도 컴포넌트 내부에만 있다.
- 제안: 공통 이동 가드와 계정 범위를 고려한 초안 보존. 페이지 내부 뒤로가기만 검사해서는 이 경우를 잡을 수 없다.

### 2. GEPA 작업 복귀

- 재현: 가짜 서버 응답으로 GEPA 작업을 `running` 상태로 두고 다른 메뉴로 이동한다. 같은 환경의 프롬프트를 다시 만들면 진행 표시가 없고 시작 버튼만 나온다.
- 원인: `CodingOptimizationPanel.jsx`의 `job`은 로컬 상태다. 해제 시 폴링을 중단하며 계정별 최근 작업을 복구하지 않는다.
- 서버는 백그라운드 작업을 계속할 수 있다. 진행 중 같은 프로필을 다시 시작하면 서버가 중복 실행을 합치는 보호는 있으나, 완료한 작업 번호를 잃으면 새 화면에서 찾을 수 없다.
- 제안: 작업 번호·상태 복구와 완료 결과 재열기. 이 재현에 실제 AI는 사용하지 않았다.

### 3. 보관한 GEPA 비교 근거 표시

- `SavedCodingProfile.jsx`는 원본 지침·보충 안내·참고 점수와 저장한 직접 판단을 표시한다.
- 저장된 보고서의 전후 AI 답변·세부 검사 근거를 다시 보는 화면은 연결하지 않았다.
- 점수는 `Math.round`로 정수 표시해 작은 차이가 숨을 수 있다.
- 제안: 전후 비교 UI를 보관함에서도 재사용하고 소수점·검사 버전을 표시한다.

### 4. Windows 평가 도구의 한글 오류 읽기

- 실패: `tests/test_coding_ai_quality_stage4.py::test_faq_runtime_checks_reject_an_answer_visible_before_click`.
- `benchmarks/coding_ai_quality/evaluate_trial.py:run`이 `subprocess.run(text=True)`로 Node 오류를 기본 CP949로 읽는다.
  UTF-8 한글이 들어오면 reader thread가 실패하고 이후 `combined`에서 `None`을 문자열에 더하다 중단된다.
- 같은 검사는 아래 명령에서 통과했다. 서브프로세스 인코딩을 명시하고 오류 경로도 처리하는 수정이 필요하다.

```powershell
.\.venv\Scripts\python.exe -X utf8 -m pytest tests/test_coding_ai_quality_stage4.py::test_faq_runtime_checks_reject_an_answer_visible_before_click -q
```

이번 검토에서 위 기능 문제나 평가 도구 코드를 수정하지 않았다.

## 사용성과 제품 범위

- 결과 화면에서 복사·보관함 저장을 먼저 보여 주고 받은 답변 확인·GEPA는 추가 선택으로 묶는 편이 핵심 동선을 드러낸다.
- 새 코딩 흐름은 네 가지 답변 선호를 직접 고르는 개인용 지침이다. 기존 React의 코드 구성·스타일·타입 선호와 축이 달라 자동으로 팀 기준에 합치지 않는다.
- 팀 기준은 선호 집계이며 합의 완료나 협업 효과의 증거가 아니다.
- 사용자 관찰로 첫 사용의 성공률, 반복 설명·수정 시간, 다음 담당자의 시작 시간과 추가 질문을 확인해야 한다.
