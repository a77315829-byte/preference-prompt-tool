# 2026-11-04 Spring Boot GEPA 개선 연결

## 구현과 기존 기능 호환

- `coding_gepa.py`에 FastAPI의 기존 GEPA 실행 흐름을 공통화하고 Python/FastAPI·Java/Spring Boot를 명시적으로 구분했다. `fastapi_optimization.py`는 기존 호출부·검사와 호환하는 래퍼다. FastAPI의 평가·캐시 경로는 유지한다.
- `spring_boot_evaluation.py`는 Java 17+/Spring Boot 3의 준비 과제를 개선용 2개·후보 선택용 2개·별도 확인용 2개로 나눈다. FastAPI 과제·평가 버전·캐시와 섞지 않는다. 원래 지침과 선택은 고정하고 보충 안내만 탐색한다.
- Java 코드를 실행하지 않는다. 제한된 토큰/괄호 구조, Spring import·컨트롤러·GET 경로·필수 쿼리 매개변수, 명시적인 음수 거절 패턴과 제한된 산술식을 검사한다. 기존 컨트롤러에 적용할 return 줄/메서드와 컨트롤러·서비스 분리를 다룬다. 임의 메서드 호출·생성 코드 실행은 허용하지 않는다.
- 설명 길이·번호, 주석 수, 클래스 분리, 변경/전체 코드 형식은 선호의 대리 지표다. Java 컴파일·Spring 서버 실행·보안·일반적인 개발 품질·사용자 만족도를 검증한 점수로 표현하지 않는다.
- 후보 선택 점수가 높고 API·계산 검사 충족 수가 줄지 않은 후보만 제안한다. 별도 과제 결과는 후보 선택에 사용하지 않으며 같거나 낮을 때도 화면에 명시한다. 더 나은 후보가 없으면 원본으로 종료한다.

## 화면·API·보관

- 공통 `CodingOptimizationPanel.jsx`에서 선택 환경에 맞는 활성화 상태·이름·새 저장 제목을 사용한다. Spring Boot 지원 정보가 없는 구형 서버는 개선을 시작할 수 없다.
- 원본/후보 프롬프트와 별도 과제의 실제 답변을 비교하고 사용자가 채택한 뒤 새 이름으로 별도 저장한다. 저장 당시 선택·원본·보충 안내·평가 기록을 보관하고 개선본 그대로 새 작업에 재사용한다.
- `PPT_SPRING_BOOT_GEPA_LIVE`를 추가했다. 미지정 시 `PPT_LIVE`를 따르며 FastAPI 설정과 독립적으로 켤 수 있다. 기존 모델·성찰 모델 설정을 사용한다. 두 환경의 동시 실행·하루 한도는 공유하며 작업당 요청 32회·성찰 4회 상한과 과제/성찰 캐시를 유지한다.
- 기존 계정별 API를 재사용한다. 로그인·소유권·원본 일치·환경 활성화를 검사하고 후보 본문이나 보고서를 클라이언트에서 신뢰하지 않는다. 같은 작업을 다시 저장해도 중복 항목을 만들지 않는다. DB migration이나 새 라이브러리, `engine/` 수정은 없다.
- 기존 FastAPI 저장본과 개인 지침·팀 기준은 갱신하지 않는다. 저장된 개선본을 직접 편집하면 과거 기록과 불일치함을 안내한다.

## 자동 검증

- 관련 Python 회귀 검사 118개 통과. Spring Boot의 요청 매핑/계산/거절, 실제 GEPA 엔진에 테스트 모델을 연결한 탐색·별도 과제 분리·캐시, 새 항목 저장·재조회·위조 차단·기존 FastAPI 보존, 환경별 활성화와 소유권을 검사했다.
- 마지막 요청 매개변수의 named argument와 `this.service` 호출 처리 수정 후 Spring Boot 검사 8개 재확인했다.
- 프론트 전체 75개 및 Vite 빌드 통과. Spring Boot 활성화·전후 비교·명시적 채택·이름 입력·별도 저장·다시 열기·새 작업 재사용과 기존 FastAPI 흐름을 포함한다.

## 실제 모델 연결 확인

- 별도 예시 DB `data/task-library-preview.db`에서 Java/Spring Boot와 단계별 설명·자세한 주석·역할별 구성·변경 부분 출력 설정으로 실제 모델 연결을 1회 확인했다. 실제 사용자 자료나 생성 Java 코드 실행을 사용하지 않았다.
- AI 요청 9회(성찰 1회 포함), 후보 선택 과제 0.7375 → 0.7375, 별도 과제 0.7375 → 0.7375였다. 별도 과제의 API·계산 정적 검사 충족 수는 전후 2/2다. 더 나은 후보가 없어 원본을 유지했고 새 후보 저장은 제공하지 않았다. 이 사례를 개선 효과의 증거로 해석하지 않는다.
- 저장 전후 기존 보관함 15개 행의 전체 해시가 같고 새 항목이 추가되지 않았음을 확인했다. 새 후보의 명시적 채택·다른 이름 저장·재조회·새 작업 재사용은 자동 UI/API 검사에서 확인했다. 이번 실제 모델 실행에서 개선본 저장까지 성공했다고 주장하지 않는다.
- 실제 화면에서 Spring Boot 표시, 원본 유지 안내, 점수와 정적 평가 한계, 프롬프트 전문 및 별도 과제의 Java 답변 비교를 확인했다. Git에 넣지 않는 증거는 `data/spring-gepa-live-comparison.jpg`·`data/spring-gepa-live-check.json`·`data/spring-gepa-source-baseline.json`이다.
