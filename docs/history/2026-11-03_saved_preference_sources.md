# 저장한 작업용 지침의 항목별 선택 출처

작업용 지침을 새 항목으로 저장할 때 항목별 사용한 값과 선택 출처를 함께 남긴다.
다시 열면 내 선호·팀 기준·같은 기준의 개수와 항목별 표를 보여 준다.
미정 선택은 해당 지시 제외로, 미합의 팀 기준은 당시 합의 전으로 안내한다.

- DB 마이그레이션 7은 `personal_prompts.provenance_json` nullable 열을 추가한다.
  기존 항목의 본문·버전은 유지하며 기록이 없으면 NULL로 둔다.
- `compose_task_prompt`가 검증된 선택에서 출처를 조립한다. `save-task`는
  서버에서 다시 생성한 출처만 저장한다. 일반 생성·수정 API의 임의 출처는 무시한다.
- 출처에는 개인 지침 이름·버전, 팀 이름, 항목·라벨·선택값과 당시 개인·팀 값,
  팀 합의 여부를 저장한다. 원문·새 작업·실행 결과·팀원 기록은 넣지 않는다.
- DB에는 저장 당시 본문의 해시·종류도 함께 보관한다. 이름·설명 수정은
  출처를 유지하며, 본문·종류 수정은 출처가 현재 지침과 다를 수 있다고 표시한다.
  원본 항목 삭제와 팀 변경으로 출처가 달라지거나 사라지지 않는다.
- 이전 저장본이나 직접 추가한 지침의 출처는 본문에서 추측하지 않는다.
  기록 없음과 새로 조합·저장하면 출처도 남는다는 안내를 제공한다.
- 표는 좁은 화면에서도 항목·값·선택 출처가 함께 보이도록 줄바꿈한다.

관련 Python 검사 60개와 프론트 검사 44개, 프론트 빌드 통과.
전체 Python 검사도 868개 통과했다. 실제 유료 API 검사 16개와 기존 Windows
실행 경로 문제 5개를 제외했다(21 deselected).
실제 브라우저의 분리된 예시 DB에서 새로 조합·저장·다시 열기를 확인했다.
화면에서 파일 구성·스타일은 팀 기준, 타입 작성은 내 선호로 표시된다.
새 라이브러리·유료 모델 호출·원격 배포는 없다.
