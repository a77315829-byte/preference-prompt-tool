# microstone 개선 기록 — 2026-11-09

사용자는 기존 UI/UX 검토의 개선, 8~10회 비교와 미확정 표시, 코딩 개인화의 연구 근거 확인,
반복되는 GitHub 실패 알림 조사와 기존 Streamlit 종료를 요청했다.
8~10회 비교 방식은 사용자 선택을 확인하고 적용했다. 새 의존성과 유료 모델 호출은 추가하지 않았다.

## 반영한 내용

- 새 코딩 비교 v3: 주문·대여 예시로 기본 8회, 미확정 항목 최대 두 개를 추가 비교한다.
  각 항목은 두 번 이상 같은 응답일 때만 일관됐다고 표시한다. 2:1로 엇갈려도 미확정이며
  확인 화면에서 직접 고른다. A/B 위치는 두 번째 맥락에서 바꾼다.
  서버가 순서·예시·응답·환경을 검증하고 신호 요약을 다시 계산한다.
- 기존 4항목 직접 설정과 v1/v2 저장본은 유지한다. 기존 추정 엔진과 새 비교를 구분한다.
- 코딩 선택·프롬프트·작업 요청과 인수인계 초안을 계정별 탭 저장소에 24시간 임시 보관한다.
  저장소 사용 불가 시 메모리로 유지하고 닫기 경고를 표시한다. 로그아웃·계정 삭제 시 정리한다.
  첨부 전 파일과 진행 중 요청에는 이동 경고를 표시한다.
- 인수인계 복구는 서버 권한·버전을 재확인하며 다른 사람의 최신 변경을 초안으로 덮어쓰지 않는다.
- GEPA 작업은 계정별 SQLite에 7일간 보관한다. 메뉴 복귀·재시작 후 완료 결과를 찾을 수 있고,
  재시작으로 중단된 작업은 오류로 복구하며 유료 요청을 자동 재실행하지 않는다.
- 보관함에서 GEPA 전후 실제 답변·세부 검사·소수점 점수를 다시 볼 수 있다.
- 계정 팀은 만든 사람·참여자에게만 이름과 결과를 공개한다. 새 참여는 로그인과 열린 초대가 필요하다.
  초대는 7일 만료되며 팀장이 닫거나 같은 링크로 다시 열 수 있다.
  만든 계정 삭제 후에도 비공개 상태를 유지하고 30일 자동 정리는 익명 체험 팀에만 적용한다.
- 공급자 오류의 원문을 로그에 남기지 않는다. Windows 요청 크기 거절 시 제한된 본문만 비우고
  JSON 오류 응답을 보내 연결 리셋을 줄였다. 기존 Node 평가 도구의 출력은 UTF-8로 해석한다.

DB migration 11~13을 적용하기 전에 로컬 DB를 `tmp/microstone-before-improvements.db`에 백업했다.
사용자 DB·백업·임시 로그·기존 사용자 문서 변경은 커밋 대상에서 제외한다.

## 반복 실패의 원인과 운영 조치

[실패 실행 #179](https://github.com/a77315829-byte/preference-prompt-tool/actions/runs/42528504686)의
실제 검사 대상은 기존 `preference-prompt-tool-7c9fvm3tb5bfxv8v6648fu.streamlit.app`이었다.
로그의 실패는 180초 안에 Streamlit 위젯을 찾지 못한 것이다. 이 결과만으로 앱 내부 예외나
휴면 등 세부 원인을 확정하지 않는다. 현재 React 앱이 실패했다는 뜻도 아니다.

GitHub의 `smoke-live.yml` 워크플로를 원격에서 비활성화했고 `disabled_manually`를 확인했다.
로컬 워크플로 소스는 예약을 없애고 명시한 React 주소의 API·진입 HTML·정적 자원을 검사하는
수동 방식으로 바꿨다. 이는 브라우저 상호작용 검사를 대신하지 않는다.
Streamlit 관리 화면은 로그인 상태가 아니며 사용자가 로그인하지 못했으므로 공개 앱은 삭제하지 않았다.

## 검증

- 프런트 전체 94개 통과, 배포 빌드 통과. 최종 계정 정리 수정 후 관련 20개도 통과했다.
- Python 전체 `not api`: 1,115개 통과·5개 실패·1개 건너뜀·API 검사 16개 제외.
  실패 4개는 변경된 계정 팀 가입 정책에 맞게 수정한 기존 검사이며,
  1개는 Windows의 큰 요청 거절 때 연결이 끊기는 문제였다.
- 수정 후 관련 회귀 96개, HTTP·복구 41개, 팀 초대 7개,
  개선 작업·Windows 평가 도구 26개 통과. 이 묶음은 서로 중복되며 전체 재실행 수치가 아니다.
- 실제 로컬 브라우저에서 8회 비교 완료·프롬프트 생성, 새로고침 후 4번째 비교 복구,
  엇갈린 10회 뒤 직접 확인 전 생성 차단을 확인했다.
- GEPA 유료 실행·실제 사용자 실험은 하지 않았다. 프런트 기본 번들 500KB 초과 경고는 남아 있다.

## 연구 해석과 남은 과제

논문 원문·저자 페이지에 근거한 출처와 설계 한계는 README의
「코딩 개인화의 근거와 아직 검증하지 않은 것」에 정리했다.
맞춤 설정에 대한 사용자 수요와 프롬프트 최적화 방법의 근거는 있지만,
현재 네 항목·8~10회·13개 환경에서의 실제 유용성은 아직 입증하지 못했다.
주문·대여·인쇄는 비슷한 계산 구조라 과제 다양성도 제한된다.

다음 실험은 일반 지침·직접 설정·반복 비교·반복 비교 후 GEPA를 비교하되,
새 과제의 기능 정확도와 블라인드 선호·수정 시간·추가 질문·비용을 분리해 측정한다.
12~20명은 탐색적 파일럿 제안이며 본실험의 충분한 표본수로 주장하지 않는다.
언어별 개인 지침의 팀 연결, 구성원별 권한 회수·초대 코드 교체·팀장 승계는 후속 범위다.
