# 인수인계 참고 파일 직접 첨부

브랜치: `codex/summary-coding-no-aws`.

- 작업을 먼저 저장한 뒤 파일 선택 → 첨부 파일 저장으로 원본을 보관한다.
  파일 선택만으로 전송하지 않으며, 저장 실패 시 선택을 유지한다. 본문 수정이 있으면 먼저 저장한다.
- migration 10의 `handoff_files`에 원본 BLOB를 저장하고 버전에는 이름·ID·크기·MIME만 기록한다.
  디스크 경로를 파일 이름에서 만들지 않는다. 재시작 후에도 유지되며 작성자 계정 삭제에 연동한다.
- 파일당 5MiB, 현재 목록 10개, 과거 첨부를 포함해 작업당 20MiB다. 빈 파일·잘못된 이름·인코딩·초과 크기를 거절한다.
  JSON 크기 상향은 로그인한 첨부 경로에만 적용하고 기존 일반 요청 상한은 유지한다.
- 현재 편집 담당자만 첨부·제외할 수 있다. 첨부와 제외도 버전을 증가시키고 충돌 시 트랜잭션을 되돌린다.
  현재 목록에서 뺀 파일은 이전 기록에서 다시 받을 수 있으므로 저장 용량을 돌려주지 않는다.
- 파일 접근에는 현재 소유자/수신자 권한과 요청한 버전의 첨부 목록을 모두 확인한다.
  공유 전 뺀 개인 파일, 다른 작업의 파일, 권한을 회수한 수신자에게는 파일 ID만으로 다운로드를 허용하지 않는다.
- 원본 내려받기는 attachment 응답이다. 제한된 MIME으로 PDF·PNG/JPEG/GIF/WebP·UTF-8 텍스트 열기를 제공한다.
  HTML/SVG도 일반 텍스트로만 열고 nosniff·sandbox CSP·no-store를 적용한다. 브라우저 지원에 따라 다운로드될 수 있다.
- 기존 링크·사용한 프롬프트와 같은 화면에서 확인한다. 맥락 요청문에는 첨부 이름만 포함하며 파일 내용은 자동 AI 전송하지 않는다.

검증:

- 관련 서버 검사 68개 통과(새 첨부 검사 17개 포함). 원본 바이트, 공유 전 기록 비공개, 회수된 접근,
  다른 작업 ID, 편집 권한, 과거 첨부 보존, 본문 수정 시 목록 보존, 크기 경계와 DB 이전/계정 삭제를 확인했다.
- 프론트 전체 검사 64개 및 프로덕션 빌드 통과. 파일 선택/실패 재시도/선택 유지/수신자 링크/이전 기록을 확인했다.
- 전체 Python 회귀 검사는 948개 통과, 1개가 기존 `test_korean_pilot.py`의 Windows 파일 교체 접근 거부로 실패했다.
  해당 모듈을 별도 임시 경로에서 다시 실행해 31개 모두 통과했다. 실제 모델 호출 16개와 기존 Windows 경로 관련 5개는 제외했다.
- 별도 예시 DB에서 작성자가 직접 TXT 파일을 선택해 저장·공유하고 수신자 계정으로 열기·다운로드·이어받기를 확인했다.
  브라우저가 내려받은 파일과 원본의 SHA-256이 같음을 확인했다. 실제 사용자 자료를 업로드하지 않았다.

새 의존성·유료 모델 호출·원격 배포는 없다. 인수인계 시간·추가 질문 감소는 여전히 사용자 검증 대상이다.
