### 스타일 기준

- 코드 구조: **간결하게 작성** ↔ **역할별 파일로 분리**
- 스타일 관리: **스타일 값을 바로 작성** ↔ **나중에 전체 디자인을 쉽게 수정**
- 타입 작성: **필요한 타입만 작성** ↔ **타입을 꼼꼼하게 작성**

선호는 A/B 선택 이력에서 추정합니다. 어느 방식이 객관적으로 더 좋은 코드라는 뜻이 아닙니다. 결과 화면은 선택으로 추정된 세 축을 보여주고, 생성된 시스템 프롬프트에도 이를 반영합니다.

## 교수님께 보여드릴 데모 흐름

1. 시작 화면에서 **코딩 도움** 카드를 선택합니다. 카드의 좌우 이동과 선택은 클릭/키보드 등으로 동작합니다.
2. **무료 데모 · API 키 불필요** 상태에서 비교를 시작합니다. 입력 문장은 예시 순서에 사용되며, 데모의 준비된 코드가 입력 문장을 그대로 구현하는 것은 아닙니다.
3. 같은 기능의 A/B 코드 예시를 8회 고릅니다. 한 번의 비교에서는 코드 구조, 스타일 관리, 타입 작성 중 한 기준만 달라지도록 만든 자료입니다.
4. 마지막 화면에서 추정된 코딩 스타일 세 가지와 시스템 프롬프트를 확인·복사합니다.

## 현재 상태와 정직하게 밝혀야 할 제한

- 이 자료는 프로젝트용 **합성 파일럿 데이터셋**입니다. 72쌍은 사용자 응답 72개가 아니며, 실제 참가자 선호 정답이나 만족도 수치는 아직 없습니다.
- 코드 검사는 파싱과 일부 모의 동작 검사입니다. 모든 TypeScript 타입의 의미 검증, 실제 React 환경 전체, 접근성, 사람이 보는 가독성 검수를 대신하지 않습니다.
- 무료 데모는 API 키·외부 비용 없이 실행되지만, 사용자의 임의 요청을 완전히 새 코드로 생성하는 방식은 아닙니다. 실제 AI API 모드는 유지하되, 공급자 키/비용 승인을 받은 실호출 검증은 아직 하지 않았습니다.
- 현재 React 세션은 로컬 서버 메모리에만 저장됩니다. 브라우저 새로고침·서버 재시작 후 복구와 연구용 응답 로그 자동 저장은 없습니다.
- `submission`의 새 코딩 자료와 `ui/ux`의 최신 React 화면은 **아직 병합하지 않았습니다**. 최신 UI 작업도 별도 작업 디렉터리에 미커밋 상태입니다. 통합 후 같은 데모와 회귀 검사를 다시 수행해야 합니다.
- AWS 화면은 비용 조회/샘플 표시 수준이며 실제 유휴 자원을 확정하거나 자동 삭제하지 않습니다. 이 항목을 코딩 기능의 성과로 소개하지 않습니다.

## 2시 미팅에서 요청할 검수·다음 단계

1. 팀원이 48개 코딩 예시의 기능 동등성, 자연스러운 파일 분리·테마 사용·타입 표기를 검수합니다.
2. 통합 담당자가 `submission`과 `ui/ux`의 겹치는 서비스·테스트 변경을 검토하며 합치고 전체 회귀 검사를 다시 수행합니다.
3. 사용자 평가 시 참가자 동의를 받고, 카테고리 찾기·8회 선택 완료·결과 이해도·실제 취향과의 일치도를 기록합니다. 판단 불가/동률은 억지 A/B 선택으로 바꾸지 않습니다.
4. LLM 출력 개선 효과를 주장하려면 별도 holdout 과제에 기본/개인화 프롬프트를 같은 모델·설정으로 적용해 비교해야 합니다. 현재는 해당 효과를 입증하지 않았습니다.
