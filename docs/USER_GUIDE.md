# 사용 설명서 (React 화면)

두 결과물 중 마음에 드는 쪽을 몇 번 고르면, 그 선택에서 취향을 추정해 내 전용 프롬프트를 만들어
주는 도구입니다. 아래는 AWS를 제외한 `codex/summary-coding-no-aws` 브랜치의 React 화면 기준입니다. (공개 Streamlit 링크는 제출본으로
고정된 예전 화면이라 일부 기능이 없습니다.)

## 0. 실행하기

창 두 개가 필요합니다.

```bash
# 창 1 - API 서버 (127.0.0.1:8000)
python api_server.py

# 창 2 - 화면 (http://localhost:5173)
npm run dev --prefix frontend
```

**실행 모드** (창 1 을 켤 때 환경변수로 고릅니다)

| 모드 | 켜는 법 | 비용 | 무엇이 달라지나 |
|---|---|---|---|
| 데모 (기본) | 그대로 실행 | 0 | 후보를 규칙으로 만듭니다. 코딩은 미리 준비한 과제·코드 예시를 씁니다. AI 다듬기, 최적화, 작업 공간 AI 기능은 꺼집니다 |
| 실제 생성 | `PPT_LIVE=1` (+ `.env` 의 `OPENAI_API_KEY`) | 유료 | 후보를 모델이 만듭니다. 요약 등은 gpt-4o-mini, 코딩은 gpt-6-luna (검사에 실패하면 gpt-6.1-sol 로 다시 시도) |
| 로컬 모델 | `PPT_LIVE=1 PPT_MODEL=ollama/qwen2.5:7b` | 0 | 실제 생성과 같지만 내 컴퓨터의 Ollama 모델을 씁니다. 첫 후보는 모델을 불러오느라 20초쯤 걸립니다 |

그 밖의 설정(하루 상한, 프롬프트 언어 등)은 README 의 실행 절에 있습니다.

## 1. 비교해서 프롬프트 만들기 (주 기능)

**시작하기** → 카테고리를 고릅니다.

| 구분 | 카테고리 | 하는 일 |
|---|---|---|
| 핵심 | 문서 요약 | 글을 요약하는 방식(분량, 원문 표현을 얼마나 살릴지). 화면에서 영어/한국어를 바꿀 수 있습니다 |
| 핵심 | 코딩 도움 | TypeScript/React 코드 스타일(파일 구성, 스타일 관리, 타입 작성) |
| 실험실 | 요약 심화, 고객 리뷰, 이메일 초안, 문서 품질 평가 | 연구·시연용 추가 도메인 |

**진행 순서**

1. 다룰 글(원문)을 넣고 시작합니다. 코딩은 "만들고 싶은 기능" 설명을 넣습니다.
2. 같은 원문으로 만든 **A / B 두 결과물**이 나옵니다. 더 마음에 드는 쪽을 누릅니다.
   - **비슷해요 · 고르기 어려워요**: 둘 다 괜찮거나 판단이 어려울 때. 그 질문에서는 선호를 정하지 않습니다.
   - **← 이전 선택 수정**: 잘못 눌렀을 때 바로 앞 질문으로 돌아갑니다. 같은 질문을 다시 묻지 않는 구조라,
     잘못 누른 선택은 이 버튼으로만 고칠 수 있습니다.
3. 최대 8번까지 묻고, 더 물을 것이 없으면 일찍 끝납니다 (보통 3~5번).
4. **결과 화면**
   - **프롬프트**: `English / 한국어` 로 언어를 바꿀 수 있습니다 (기본 English). 정하지 못한 항목("비슷해요"만
     고른 것)은 프롬프트에 넣지 않습니다.
   - **프롬프트 복사**: 그대로 붙여 쓰면 됩니다.
   - **바로 쓰기**: ChatGPT·Claude·Gemini 에 붙여 넣을 문구, 또는 파일로 내려받기 - Markdown, 그리고 코딩이면
     GitHub Copilot(`.github/copilot-instructions.md`), Cursor(`.cursor/rules/...mdc`), `AGENTS.md`.
     ChatGPT 무료판 글자 수 한도(1,500자)를 넘으면 짧은 판을 같이 줍니다.
   - **← 마지막 선택 수정**: 결과를 보고 마음이 바뀌면 마지막 질문으로 돌아갑니다.
   - **선호 기준으로 최적화 (GEPA)**: 실제 생성 모드에서만. 예시 글에 프롬프트를 적용해 선호를 지키는지
     코드로 채점하고, 점수가 오를 때만 바꿉니다. 1~2분, 한 번에 약 $0.006~0.023 (성찰 모델 유료 호출).
     실험상 "추가 효과는 확인되지 않음"이라 선택 기능입니다.
   - **팀 기준 맞추기**: 아래 3절.

## 내 선호 보관함

상단 **내 선호 보관함**, 첫 화면의 **저장한 내 선호 다시 쓰기**, 내 계정에서 열 수 있습니다.
로그인한 계정에 요약용(한국어·영어)과 코딩용 지침을 저장합니다. 다른 계정이나 팀에는 자동 공유하지 않습니다.

1. **내 방식 저장**: 문서 요약·코딩 비교를 마친 뒤 결과의 **내 선호 보관함에 저장**을 누릅니다.
   기억하기 쉬운 이름을 붙이면 지금 화면에 보이는 언어의 프롬프트가 저장됩니다.
   로그인이 필요하면 결과 화면 안에서 로그인합니다. 작성한 이름·결과는 유지되며 로그인 후 저장 버튼을 다시 누릅니다.
2. **찾고 수정**: 보관함에서 요약용·코딩용으로 나누거나 이름·설명으로 찾습니다.
   **수정**에서 이름·분류·설명·지침을 고치고 **변경 내용 저장**을 누릅니다.
   다른 창에서 이미 수정한 항목은 덮어쓰지 않습니다. 내 수정 내용을 복사해 두고 **저장된 내용 다시 불러오기**로 확인합니다.
3. **새 작업에 재사용**: **새 작업에 사용**에서 새로운 원문·개발 요청을 넣습니다.
   **예시 자료 넣어보기**로 흐름을 익힐 수 있습니다. 준비된 **지침 + 새 작업 복사**를 평소 사용하는 AI에 붙여 넣습니다.
   실제 생성 모드에서는 **이 지침으로 AI 실행**도 가능합니다. 입력 자료가 모델로 전송되고 모델 사용 비용이 발생할 수 있습니다.

- 아직 저장한 항목이 없으면 **요약 취향 찾기**·**코딩 취향 찾기**로 시작합니다.
- 이미 가진 프롬프트는 **가진 프롬프트 직접 추가**로 보관할 수 있습니다.
- 보관함에는 지침·이름·설명만 저장합니다. 새 작업 입력과 실행 결과는 보관함에 자동 저장하지 않습니다.
  모델 실행 결과는 기존 생성기 정책에 따라 캐싱되며, 생성된 코드를 자동 실행하지 않습니다.
- 수정한 지침은 저장한 뒤 새 작업에 사용합니다. 입력이나 지침이 바뀌면 이전 실행 결과임을 표시합니다.
- **팀 기준과 비교하고 골라 쓰기**: 보관한 항목의 **새 작업에 사용**에서 같은 종류의 팀을 고르거나 초대 링크·코드를 붙여 넣습니다.
  **개인·팀 기준 비교하기**를 누르면 항목별 개인용·팀용 값과 같음·다름·미정, 팀 합의 필요 상태를 볼 수 있습니다.
  기본 생성문 전체가 일치할 때만 개인 선호 값을 확인합니다. 직접 수정·추가·최적화한 지침은 값을 추측하지 않고 다른 본문 문장을 보여 줍니다.
  본문 비교에서는 저장한 이름과 개인·팀 대상 안내 차이를 제외하며, 표현의 차이가 의미의 차이라는 자동 판정은 하지 않습니다.
- **개인용으로 사용 / 팀용으로 사용**을 골라 같은 새 작업을 복사하거나 실행합니다. 비교용으로 정리한 문구가 아니라 선택한 지침 원문을 사용합니다.
  선택만으로 모델을 호출하거나 내 보관함·팀 기준을 덮어쓰거나 팀에 참여하지 않습니다.
- **항목별로 골라 이번 작업용 만들기**: 비교 후 서로 다른 항목마다 **내 선호 / 팀 기준** 중 하나를 고르고 **이번 작업용 만들기**를 누릅니다.
  같은 항목은 그대로 반영합니다. 한쪽이 미정인 항목도 선택하며, **정하지 않음**을 고르면 그 항목의 지시를 제외합니다.
  팀 합의가 끝나지 않은 값은 안내를 확인한 뒤 선택하세요. 이번 선택으로 팀의 합의 상태가 바뀌지는 않습니다.
  만든 작업용 지침을 미리 보고 새 작업과 함께 복사·실행할 수 있으며, 개인용·팀용 전체로도 전환할 수 있습니다.
  항목 선택을 수정하면 작업용 지침을 다시 만들어야 합니다. 새 작업 입력은 유지하고 원본 개인 지침·팀 기준에는 저장하지 않습니다.
  직접 수정·추가·최적화해 항목을 확정할 수 없는 개인 지침은 조합을 제한하고 개인용·팀용 전체 선택을 안내합니다.
- 아직 선호를 모으지 않은 팀이나 다른 종류의 팀은 비교할 수 없습니다. 코딩·한국어 요약·영어 요약 분류를 맞춥니다.
- 팀 기준은 확인한 시점의 내용입니다. 팀원이 선호를 더하면 **팀 기준 새로 확인**을 누르세요.
  확인 후 팀 기준이 바뀌면 AI 실행은 사용량 차감 전에 멈추고 다시 확인하도록 안내합니다.
- 계정당 100개, 지침 20,000자, 새 작업 입력 12,000자까지입니다.
- 삭제는 확인 후 진행하며, 탈퇴하면 내 보관함도 삭제됩니다.

## 2. 템플릿

상단 **템플릿** 메뉴. 팀이 써 둔 프롬프트 6개(문서 요약·코딩 각각 3개)가 있습니다.

- **복사**: 그대로 씁니다.
- **내 방식으로 바꾸기**: 1절의 비교를 몇 번 하면, 템플릿의 과제·규칙은 그대로 두고 분량·표현 방식만 내
  취향으로 바꾼 버전을 만들어 줍니다. 템플릿에서 시작한 프롬프트는 언어 전환이 없습니다.

## 3. 팀 기준 맞추기

첫 화면의 **팀 만들기 · 초대로 참여** 또는 상단 **팀 기준 맞추기**에서 시작합니다.

1. **새 팀 만들기**: 팀 이름과 함께 맞출 기준(코딩·한국어 요약·영어 요약)을 고릅니다.
   팀 코드와 초대 링크는 자동으로 준비됩니다. 이 단계는 모델을 호출하거나 선호를 반영하지 않습니다.
2. **초대하기**: **초대 링크 복사**로 받은 링크를 팀원에게 전달합니다. 링크를 열면 바로 팀을 확인합니다.
   **초대받아서 참여하기**에 링크나 기존 팀 코드를 붙여 넣어도 됩니다.
3. **내 선호 고르기 시작**: 팀의 비교 항목으로 이동합니다. 사용할 내용을 확인하고 예시를 비교합니다.
   비교 중에는 팀 이름과 다음 단계가 표시되며, 팀의 요약 언어는 바꿀 수 없습니다.
4. **내 선호를 팀 기준에 합치기**: 비교를 마치면 맨 위에 마지막 단계가 나옵니다.
   익명이면 이름을 적고, 로그인했으면 내 계정으로 합칩니다. 버튼을 누르기 전에는 팀에 반영되지 않습니다.
   완료 후 참여 현황·합의할 항목·공통 지침을 볼 수 있습니다. 원문과 생성 결과는 팀에 공유하지 않습니다.
5. **다시 보기**: 상단 **팀 기준 맞추기**의 내 팀·최근 본 팀 또는 초대 링크로 엽니다.
   로그인했으면 내가 만든 빈 팀도 내 팀에 남습니다. 내 선호를 바꾸려면 다시 비교하고 합치세요.

- 개인용 비교를 먼저 마쳤어도 결과 화면에서 초대를 확인하거나 새 팀을 만든 뒤 선호를 합칠 수 있습니다.
- 링크를 가진 사람은 팀 기준을 볼 수 있습니다. localhost 링크는 다른 컴퓨터에서 접속할 수 없으므로,
  팀원에게 전달할 링크는 팀원이 접속 가능한 서비스 주소에서 복사합니다.
- 기존 팀 코드는 그대로 사용할 수 있습니다. 없는 초대 코드는 새 팀으로 자동 생성하지 않습니다.
- 선호가 없는 빈 팀은 공통 지침을 만들지 않습니다. 한 사람 이상이 선호를 합치면 지침이 생깁니다.

- 한 사람 한 표입니다. 비교를 많이 한 사람이 더 큰 영향을 갖지 않습니다.
- 아무도 정하지 않은 항목은 팀 공통 지침에서 빠집니다.
- 표가 같은 수로 갈린 항목은 "팀이 정해야 한다"고 표시됩니다. 선호가 한쪽으로 조금 더 기울었으면 그쪽이
  팀 공통 지침에 임시로 들어가고, 양쪽이 똑같으면 빠집니다.
- 로그인하면 내 아이디로 참여하고, 다른 사람이 그 이름을 쓸 수 없습니다.

## 4. 요청문 다듬기

상단 **요청문 다듬기**. 이미 가진 프롬프트를 붙여 넣습니다(4,000자 이내).

- **구조 점검**: 입력할 때마다 무료로 체크리스트를 보여 줍니다 (역할, 출력 형식 등이 있는지).
- **AI로 다듬기**: 실제 생성 모드에서만. 무엇을 고쳤는지와 다듬은 프롬프트를 보여 줍니다.

## 5. 업무 지침 만들기

상단 **업무 지침 만들기**. 반복 업무의 목적·필수 규칙·원하는 결과를 정리해 팀원과 함께 고쳐 쓸 AI 지침을 만듭니다.
앱에 연결할 때 필요한 입력·출력 형식은 **앱 연동 설정 보기**에서 편집합니다.

1. **할 일 설명**: 회의록 정리·코드 리뷰·새 팀원 안내 중 예시를 고르거나, 하고 싶은 일을 직접 적습니다. 예시 선택은 설명만 채우고 AI를 호출하지 않습니다. 데모 모드에서는 **완성된 예제로 체험 (가상 비용 보고)**으로 흐름을 확인합니다.
2. **요구사항 확인**: **내 설명으로 시작하기 (AI)** 가 필수 규칙, 선호, 입력 변수, 출력 형식, 미결 질문으로 나눠 줍니다.
   AI 가 추측한 것은 "제안", 원문에 있는 것은 "입력에서 추출"로 구분됩니다. 미결 질문은 **답 반영**으로 채웁니다.
   - 업무 담당자는 목적·필수 규칙·선호·미결 사항만 확인하면 됩니다. 출력 계약(AI가 돌려줄 답의 항목)은 목록으로만 보입니다.
   - **앱 연동 설정 보기**를 켜면 입력 변수의 타입·필수 여부와 출력 계약을 표에서 고칩니다. 타입은 글자·숫자·정수·
     예/아니오·목록·묶음으로 보이고, 목록은 안쪽 항목(한 가지 타입 또는 여러 칸 묶음)과 개수를 정합니다.
     JSON 으로 붙여 넣는 칸도 그 아래에 있습니다. 이 설정은 이 브라우저에 기억됩니다.
3. **프롬프트 편집 · 시험 · 내보내기**: 확인한 요구사항으로 프롬프트를 만들고(조립은 코드가 해서 필수 규칙
   문장이 그대로 들어갑니다), **시험할 자료**로 돌려 봅니다. 기본 입력은 항목별 폼으로 넣고, 목록·묶음 자료나 앱 연동 설정에서는 JSON을 직접 편집합니다. 검사 결과(통과/실패/미평가)가 나옵니다.
   - 시험할 자료는 실제 업무의 예시 입력입니다. 단순한 글·숫자·예/아니오는 항목별 폼으로 넣습니다.
     복잡한 목록·묶음 자료는 JSON으로 넣습니다. **빈 입력칸 만들기**로 입력 틀을 다시 만들 수 있습니다.
   - **개선 방향 추천**: 코드 점검 제안 + AI 제안. 제안마다 같은 입력으로 시험해 무엇이 고쳐지고 망가지는지
     셉니다. 필수 규칙을 바꾸는 제안은 따로 확인해야 적용됩니다.
   - **내보내기**: 프롬프트와 입출력 계약을 ZIP 으로 받습니다.
4. **저장 · 버전 · 비교** (로그인 필요): 저장할 때마다 새 버전이 쌓이고, 이전 버전과 결과를 나란히 비교하거나
   복원할 수 있습니다. 작업 중 내용은 자동 저장됩니다. **공유**로 다른 아이디를 편집자/보기 전용으로 초대합니다.
   로그인 없이도 **프로젝트 JSON 저장**으로 내려받을 수 있습니다.

## 6. 로그인과 계정

- 상단 **로그인**에서 가입합니다(아이디 3~30자, 비밀번호 8자 이상). 같은 주소에서 하루 10개까지 가입됩니다.
- 로그인하면: 작업 공간 저장·공유, 팀에 내 아이디로 참여, 사람별 하루 사용 횟수가 생깁니다.
- 내 아이디를 누르면 **비밀번호 변경**(다른 기기 로그인도 모두 끊김)과 **탈퇴**가 있습니다. 탈퇴하면 내가 만든
  프로젝트는 공유받은 사람에게서도 사라지므로, 화면이 그 수를 먼저 알려 줍니다.
- 하루 사용 횟수(실제 생성 모드): 세션 20, 최적화 5, 다듬기 20, 작업 공간 AI 30 (로그인 기준.
  로그인하지 않은 방문자는 모두 합쳐 한 몫).
