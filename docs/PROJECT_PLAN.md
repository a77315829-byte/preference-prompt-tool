# 프로젝트 계획: WBS와 R&R

이 문서는 멘토링용 계획안이다. 2026-11-04 기준이며 팀 합의와 멘토 피드백 후 확정한다.
아래 역할은 수행 실적이 아니라 배정 제안이다. 프로젝트 전체 소개와 현재 기능은 [README](../README.md)에 있다.

## WBS

| ID | 기간 | 작업 | 산출물·완료 조건 | 책임 제안 |
|---|---|---|---|---|
| 1.1 | 11.04~11.10 | 핵심 흐름·용어·초안 보존 문제 정리 | 화면 점검표, 처음 사용자 3명 관찰 목표, 상단 이동·GEPA 복귀 문제 재현과 수정안 | 팀장·김홍경 |
| 1.2 | 11.11~11.17 | 개인 지침 재사용과 환경별 평가 검토 | 공통 과제의 직접 요청/저장 지침 비교, 수정 시간·선호 기록. 연결된 GEPA의 실제 개선 여부와 비용·대기 시간 확인 | 팀장·이현우 |
| 1.3 | 11.18~11.24 | 팀 기준·인수인계 검증 | 두 계정 5개 시나리오, 권한·첨부·이어받기 확인, 새 담당자의 시작 시간·추가 질문 기록 | 조현우·팀장 |
| 1.4 | 11.25~12.01 | 피드백 반영·재검사·시연 정리 | 주요 오류 수정, 검증 보고서, 최신 캡처·발표 자료 정리 | 팀장·주성준 |

GEPA의 환경별 코드 연결과 실제 효과 검증은 구분한다. 현재 13개 조합의 연결을 구현했으므로
계획에는 다시 연결하는 작업 대신 실제 과제의 기능·선호 적합성, 비용과 대기 시간을 확인하는 일을 둔다.

## R&R

| 담당자 | 역할 제안 | 주요 산출물 | 보고 방식 |
|---|---|---|---|
| 팀장(본인) | 기획·구현·통합 총괄 | 기능 구현·수정 내역, 통합 시연·기술 문서 | 매주 진행과 위험 정리 |
| 이현우 | 기능 시나리오·선호 검증 | 재사용 비교·기능 점검표 | 사례와 결과 공유 |
| 김홍경 | 처음 사용자 흐름 관찰 | 막힌 지점·용어 개선안 | 관찰 기록 공유 |
| 조현우 | 팀 공유·인수인계 검증 | 권한·첨부·이어받기 점검표 | 오류 재현 절차 공유 |
| 주성준 | 일정·발표·결과 정리 | WBS 갱신·발표·검증 요약 | 산출물 링크 취합 |

실제 기여는 이후 커밋·점검표·관찰 기록·발표 산출물로 별도 기록한다.

## 멘토링 보고 순서

1. 누구의 어떤 문제를 해결하려는지와 이번 주 범위를 설명한다.
2. 완료한 기능을 실제 화면과 커밋으로 보여 준다.
3. 검증 결과와 아직 확인하지 못한 효과를 구분한다.
4. 발견한 문제·다음 주 계획·책임자·완료 조건을 공유한다.
5. 멘토에게 조언받을 항목을 정리한다.

기존 계획과 발표 제작 이력은 [이전 상세 안내](../README_SMALL_TEAM.md)에 보존한다.
