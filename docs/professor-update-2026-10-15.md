# 교수님 공유용 — 코딩 도움 및 UI/UX

작성일: 2026-10-15 · 담당: 차원 · 작업 브랜치: `codex/coding-ai-upgrade`

## 처음 설명드릴 때 사용할 문구

교수님, 제가 맡은 부분은 코딩 도움 기능과 React 기반 UI/UX입니다.
코딩 도움은 사용자가 원하는 코드 작성 규칙을 처음부터 설명하기 어렵다는 문제에서 출발했습니다.
사용자가 만들고 싶은 기능을 입력하면 AI가 해당 기능의 React·TypeScript 코드 A/B를 생성하고,
사용자는 더 마음에 드는 예시를 반복해서 고릅니다. 이 선택에서 코드 구조, 스타일 관리,
타입 작성 방식의 선호를 추정해 다른 코딩 도구에도 재사용할 수 있는 시스템 프롬프트로 정리합니다.

UI는 카테고리 선택부터 예시 비교, 선택 수정, 결과 확인·복사까지 한 흐름으로 연결했습니다.
기존의 핵심 카테고리와 실험실 구분은 유지했습니다.
로그인과 팀 프롬프트 등 팀에서 개발한 공통 기능도 화면에서 사용할 수 있도록 연결했습니다.

검증에서는 서로 반대 취향의 가상 사용자 2개를 설정했습니다. 실제 AI로 만든 카운터 A/B
6쌍에서 취향대로 선택하고, 결과 프롬프트로 다른 기능인 FAQ 코드를 생성했습니다.
FAQ 한 개의 반환 타입 누락을 발견해 AI 수정 호출을 별도로 실행한 뒤,
총 14개 코드 결과의 타입·빌드·정해진 동작·스타일 검사를 통과했습니다.
다만 이는 정해진 과제의 검사 결과이며, 모든 기능 입력에서 같은 품질을 보장하거나
실제 사용자의 만족도가 향상됐다는 의미는 아닙니다. 실제 사람의 사용성·선호 평가는 남아 있습니다.

## 1. 코딩 도움: 무엇을 만드는 기능인가요?

사용 흐름은 다음과 같습니다.

1. 만들 기능을 입력합니다. 예: “장바구니에서 수량을 늘리거나 줄이고 총액을 표시해주세요.”
2. 실제 AI 모드에서는 입력을 바탕으로 A/B 코드를 생성합니다.
3. 같은 기능에서 한 번에 한 가지 작성 방식만 비교하는 것을 목표로 합니다.
4. 더 마음에 드는 쪽 또는 ‘비슷해요’를 고르고, 필요하면 이전 선택을 수정합니다.
5. 선택 결과를 코드 작성 규칙으로 정리한 시스템 프롬프트를 확인하고 복사합니다.

| 비교 기준 | 화면에서 이해할 수 있는 표현 | 프롬프트에 담기는 규칙 예 |
| --- | --- | --- |
| 코드 구조 | 간결하게 작성 / 역할별 파일로 분리 | 작은 기능은 한 파일에 작성하거나 역할별로 분리 |
| 스타일 관리 | 값을 직접 작성 / 나중에 전체 디자인을 쉽게 수정 | 직접 값 지정 또는 테마·디자인 토큰 사용 |
| 타입 작성 | 필요한 곳 중심 / 타입을 꼼꼼하게 작성 | 단순 값은 추론 활용 또는 Props·함수 등에 타입 명시 |

이는 모델을 새로 학습시키는 기능이 아니라, 선택 기록으로 **재사용할 지시문을 만드는 기능**입니다.
좋은 코드의 보편적 정답을 정하거나 모든 사용자에게 더 나은 코드를 보장하는 목적은 아닙니다.
기존 `Domain`, `Estimator`, `Selector` 및 문서 요약 기능은 유지합니다.

### 실제 AI와 무료 데모의 차이

- 실제 AI 모드: 사용자가 입력한 기능으로 코드를 생성하며 API 호출 비용이 발생할 수 있습니다.
- 무료 데모: 준비된 작은 과제로 스타일을 비교합니다. 입력한 임의 기능의 구현 코드를 생성하지 않습니다.
- 키가 없거나 생성 실패·사용 한도에 도달하면 데모 전환 사유를 화면에 표시합니다.
- 서버에 연결하지 못하면 오류를 표시합니다. 연결 실패를 AI 생성 성공으로 보여주지 않습니다.

현재 코드의 기본 코딩 모델 설정은 `openai/gpt-6-luna`입니다.
정적 스타일 검사를 통과하지 못하면 같은 모델로 한 번 수정하고,
계속 실패할 때만 `openai/gpt-6.1-sol`로 한 번 재생성하는 경로입니다.
이는 저장소의 설정값 설명이며, 모델 간 성능 우위를 검증했다는 뜻은 아닙니다.
환경변수로 설정을 바꿀 수 있습니다. GEPA는 별도의 프롬프트 최적화 기능이며,
이번 코드 검사를 GEPA 성능 검증으로 계산하지 않습니다.

모델 선택 이유는 저비용 기본 생성과 검사 실패 시 제한적인 상위 모델 사용을 조합하기 위해서입니다.
기본 모델로 먼저 생성하고 검사 결과를 바탕으로 수정하므로, 모든 요청에 상위 모델을 쓰는
방식보다 비용을 제한하는 설계입니다. 실제 절감률이나 모델 간 우열은 비교 실험으로 입증하지 않았습니다.

## 2. UI/UX: 사용자가 조작하는 부분

- 가로 카드와 한 화면 내 장면 전환으로 카테고리를 선택합니다.
- 기존 핵심 카테고리 구성은 유지하며, 본 발표에서는 담당 영역인 코딩 도움을 시연합니다.
- 실험실 4개: 문서 요약 심화, 고객 리뷰 작성, 이메일 초안, 문서 품질 평가.
- 비교 화면에서 A/B, ‘비슷해요’, 이전 선택 수정, 코드 전체 보기와 결과 복사를 제공합니다.
- 로그인·로그아웃 및 팀 프롬프트 등 공통 기능을 연결했습니다.
- 긴 코드와 결과는 내부 영역에서 읽을 수 있도록 하고, 작은 화면도 점검했습니다.

실험실의 화면 흐름 확인과 각 도메인의 생성 품질 입증은 별개입니다.

### 실제 사용량과 비용

수집한 원본 5개에는 호출 시도 21회가 있으며, 사용량이 확인된 18회는 입력 23,493토큰,
출력 16,487토큰입니다. 공식 표준 단가로 계산한 확인분은 **약 $0.01442**입니다.
사용량 없는 실패 시도 3회와 미기록 과거 실행은 제외했으며, 제공업체 청구서와 대조한 실제 청구액이 아닙니다.
전체 세션의 고정 가격으로도 해석하지 않습니다. [원본별 비용 집계와 공식 단가 출처](history/2026-10-15_stage3_cost_summary.md)를 참고합니다.

## 4. 발표 때 보여드릴 순서 (약 3분)

1. 핵심 카테고리와 실험실 구분을 보여드립니다.
2. 코딩 도움에서 기능 입력과 무료 데모/실제 AI 모드의 차이를 설명합니다.
3. 비용 없는 시연은 무료 데모로 진행하고, 준비된 과제임을 먼저 밝힙니다.
4. 코드 작성 방식의 차이를 설명하며 선택하고, ‘비슷해요’와 이전 선택 수정을 보여드립니다.
5. 최종 스타일과 시스템 프롬프트를 확인하고 복사합니다.
6. 실제 AI 생성 검사는 별도 기록으로 설명하고, 방금 데모를 AI 생성 결과라고 소개하지 않습니다.

실제 AI를 실시간 시연하려면 키·접속·예산을 사전에 확인해야 합니다.
화면에서 생성 모드와 데모 전환 여부를 확인하고, 전환되면 그대로 설명합니다.

### macOS 로컬 실행

저장소 루트에서 기존 의존성 설치가 끝난 환경 기준입니다. 터미널을 두 개 사용합니다.

```sh
# 터미널 1: 무료 데모 API (키 불필요, 실제 호출 강제 옵션 해제)
PPT_LIVE=0 .venv/bin/python api_server.py
```

```sh
# 터미널 2: React 화면
npm run dev
```

API 기본 포트는 8000입니다. 화면 주소는 Vite가 출력한 주소를 사용합니다.
포트가 사용 중이면 5173 대신 다른 포트가 표시될 수 있습니다.
화면에서도 반드시 무료 데모를 선택합니다. `PPT_LIVE=0`만으로 모든 실제 AI 기능의 호출을 차단하는 것은 아닙니다.
실제 AI 실행은 [README 환경변수](../README.md#웹-ui로-사용해보기)를 참고하며 키는 공유하지 않습니다.

## 5. 인계 및 남은 작업

- 코딩 기능과 UI 연결은 구현·지정 범위 검사까지 진행했습니다. 무제한 입력의 품질 검증 완료로 표현하지 않습니다.
- 발표에 사용할 브랜치 통합 상태, 실제 실행 환경, 최종 빌드를 다시 확인해야 합니다.
- 사람에게 직접 사용하게 한 뒤 조작 난이도와 스타일 선호 적합도를 별도로 기록해야 합니다.
- 실제 AI 청구 금액은 제공업체 사용 내역에 접근할 수 있는 담당자가 대조해야 합니다.
- 이 문서 정리 단계에서는 새 유료 API 호출, 커밋·푸시를 하지 않았습니다.

팀장 전달용:

> 코딩 도움과 UI/UX 발표 설명을 최신화했습니다. 실제 AI 가상 사용자 2개 검증은 반환 타입 누락 수정 후 14개 코드 결과가 지정 검사를 통과했고, 전체 비유료 테스트는 850개 통과했습니다. 확인된 18회 호출의 토큰 기준 계산 금액은 약 $0.01442이며 실제 청구액은 아닙니다. 발표는 무료 데모로 조작 흐름을 보여주고 실제 AI 검증 기록을 별도로 설명하면 됩니다. 실제 사람 평가와 전체 입력의 품질 보장은 별개로 남아 있습니다.
