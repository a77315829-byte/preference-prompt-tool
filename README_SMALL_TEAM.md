# Preference Prompt: 개인 선호와 팀의 다음 작업을 연결하는 도구

사용자가 원하는 AI 답변 방식을 저장하고, 팀 기준과 다른 부분을 선택해 작업용 프롬프트를 만든 뒤,
작업 맥락과 자료를 다음 담당자에게 넘깁니다.

작은 개발팀을 위한 현재 제품 방향과 실행 방법을 정리한 문서입니다.
기존 선호 추정 연구와 실험 기록은 [기술 문서](README_DETAILS.md)에서 별도로 확인합니다.

## 만드는 이유와 필요한 사용자

AI에 매번 같은 선호를 설명하고, 팀원마다 다른 형식의 결과를 다시 고치며, 담당자가 바뀔 때 목적·진행·자료를
재설명하는 수고를 줄이려 합니다. 다음 사용자를 우선 대상으로 잡았습니다.

- 개인: 요약 길이, 코드 설명·주석·구성 방식을 정해 다음 작업에도 쓰고 싶은 사람
- 작은 개발팀: 학생 프로젝트, 사이드 프로젝트처럼 개인 취향과 공동 기준을 함께 다뤄야 하는 팀
- 다음 담당자: 이전 작업의 목적·현재 상태·남은 일·자료·사용 지침을 확인하고 일을 이어갈 사람

필요성과 시간 절감 효과는 제품 가설입니다. 구현 여부와 실제 사용자 효과를 구분해 검증합니다.

## 현재 구현된 기능

| 흐름 | 사용자가 할 수 있는 일 | 확인할 범위 |
|---|---|---|
| 문서 요약 | 한국어·영어 예시 비교로 길이·표현 선호를 고르고 지침 생성 | 무료 데모는 규칙 기반 예시. 실제 생성 모드와 구분 |
| 코딩 지침 | 언어·프레임워크 선택 또는 직접 입력, 설명·주석·구성·출력 선호 설정 | 설정 문장 조립. 모든 언어의 코드 실행·품질 검증 기능은 아님 |
| React 비교 | 기존 TypeScript/React 예시를 비교해 작성 선호 추정 | 무료 데모는 준비된 과제의 스타일 비교 |
| 내 선호 보관함 | 요약·코딩 지침 저장·수정·검색·새 작업 재사용 | 보관함에 작업 원문·실행 결과 자동 저장하지 않음 |
| 팀 만들기·참여 | 기준 분류를 골라 팀 생성, 초대 링크로 참여, 마지막에 선호 합치기 | 선호 집계이며 전원 합의 완료를 의미하지 않음 |
| 개인·팀 비교와 조합 | 같은 분류의 팀과 차이 확인, 개인용·팀용 또는 항목별 조합 선택 | 개인 원본과 팀 기준을 유지 |
| 조합의 기록 | 출처, 전후 비교, 일부 항목 복원, 다른 이름으로 저장, 이전 작업용 연결 | 기록하지 않은 과거 출처는 추측하지 않음 |
| 인수인계 | 목적·진행·남은 일·링크·사용 프롬프트를 저장하고 받을 계정 지정 | 팀 초대와 작업 열람 권한은 별도 |
| 참고 파일 첨부 | 파일 원본 저장·열기·다운로드, 이전 기록의 첨부본 확인 | 파일당 5MiB, 현재 10개, 과거 첨부 포함 작업당 20MiB |
| 템플릿과 요청문 점검 | 24개 업무 초안 검색·복사, 요청문의 역할·형식·조건 점검 | 6개만 예시 비교 지원. AI 수정안은 실제 생성 모드 필요 |
| 업무 지침 만들기 | 반복 업무의 입력·규칙·출력 형식 확인, 프로젝트 저장·공유·편집 | 실시간 공동 편집·자동 합의로 설명하지 않음 |

임의 언어를 직접 설정한 코딩 지침은 개인용으로 보관·재사용합니다. React 팀 기준과의 자동 비교·조합은 제공하지 않습니다.
현재 서비스에서는 AWS 화면·조회 API·관련 템플릿을 제외했으며, 과거 실험 자료는 기록으로 보존합니다.

## 처음 사용할 때

1. **시작하기**에서 문서 요약, 코딩 도움, 팀 업무 정리 중 작업을 고릅니다.
2. 개인 지침을 만들고 **내 선호 보관함**에 저장합니다. 저장에는 로그인이 필요합니다.
3. **팀 기준 맞추기**에서 팀을 만들거나 초대를 열고, 비교 후 선호 합치기를 직접 누릅니다.
4. 보관함의 **새 작업에 사용**에서 개인용·팀용을 고르거나 항목별 작업용을 조합합니다.
5. 조합을 다른 이름으로 저장하면 기존 항목과 팀 기준은 유지됩니다.

자세한 화면별 안내는 [사용자 가이드](docs/USER_GUIDE.md)에 있습니다.

## 작업을 다음 사람에게 넘길 때

1. **시작하기 > 팀 업무 정리 > 작업 인수인계 시작하기**를 엽니다.
2. 이름·목적·진행·남은 일·참고 링크·사용한 프롬프트를 적고 **내 작업으로 저장**합니다.
3. **참고 파일 첨부 > 파일 선택 > 첨부 파일 저장**으로 원본을 추가합니다.
4. 같은 서비스에 가입한 팀원 아이디를 지정해 공유하고 링크를 전달합니다.
5. 수신자는 로그인 후 내용을 확인하고 **이어서 맡기**를 누른 뒤 진행을 갱신합니다.
6. **이전 기록 확인**에서 공유 당시 내용과 당시 첨부본을 열 수 있습니다.

파일을 현재 첨부에서 빼도 이전 버전은 남기므로 저장 용량이 반환되지는 않습니다.
공유 전 개인 기록에서 뺀 파일은 수신자에게 공개하지 않습니다. 링크나 파일 주소를 아는 것만으로 권한이 생기지 않습니다.
첨부 내용은 AI 요청문에 자동 포함하지 않으며, 필요한 파일은 사용자가 내려받아 따로 전달합니다.
작성자 계정을 삭제하면 작업·버전·첨부도 함께 삭제됩니다.

`localhost` 링크는 다른 컴퓨터에서 접속할 수 없습니다. 서로 다른 기기에서 협업하려면 같은 서비스 주소에 접속해야 합니다.
공유 알림이나 메시지는 자동 발송하지 않습니다.

## 로컬 실행

Python 3.12와 Node.js가 필요합니다. 기존 프로젝트 의존성을 설치한 환경을 사용합니다.

API 서버를 실행합니다(PowerShell).

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
$env:PPT_LIVE="0"
.\.venv\Scripts\python.exe api_server.py
```

다른 터미널에서 화면을 실행합니다.

```powershell
npm ci --prefix frontend
npm run dev --prefix frontend
```

`http://127.0.0.1:5173/`에서 접속합니다. `PPT_LIVE=0`은 유료 모델을 호출하지 않는 데모입니다.
AI 수정안·실제 생성·모델 시험의 환경변수는 [기술 실행 안내](README_DETAILS.md)를 따릅니다. API 키를 저장소에 넣지 않습니다.
사용자·보관함·인수인계·파일은 기본적으로 `data/app.db`에 저장하며 이 데이터는 Git에 포함하지 않습니다.

## 앞으로 검증할 부분

- 개인: 직접 쓴 요청문보다 저장한 지침을 다시 쓰는 데 드는 시간과 수정량이 줄어드는가?
- 팀: 항목별로 어느 기준을 따랐는지 팀원이 설명하고 선택할 수 있는가?
- 인수인계: 새 담당자가 기록과 파일만 보고 다음 행동을 시작할 수 있는가? 추가 질문은 무엇인가?
- 처음 사용: 지침·팀 기준·작업용의 차이를 안내 없이 이해하는가?

작은 팀 2~3곳의 파일럿을 제안하지만 모집은 확정되지 않았습니다. 단순히 기능 테스트가 통과했다는 이유로 만족도나 생산성 향상을 주장하지 않습니다.
