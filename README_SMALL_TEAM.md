# 기능별 상세 안내와 이전 계획 기록

프로젝트 전체 소개·현재 화면·검증 요약은 [README](README.md)를 먼저 읽어 주세요.
갱신하는 WBS와 R&R은 [프로젝트 계획](docs/PROJECT_PLAN.md)에서 관리합니다.
이 문서는 기존 기능별 안내와 멘토링 계획의 제작 이력을 보존합니다.

사용자가 원하는 AI 답변 방식을 저장하고, 팀 기준과 다른 부분을 선택해 작업용 프롬프트를 만든 뒤,
작업 맥락과 자료를 다음 담당자에게 넘깁니다.

작은 개발팀을 위한 현재 제품 방향과 실행 방법을 정리한 문서입니다.
기존 선호 추정 연구와 실험 기록은 [기술 문서](README_DETAILS.md)에서 별도로 확인합니다.

## 만드는 이유와 필요한 사용자

AI에 매번 같은 선호를 설명하고, 팀원마다 다른 형식의 결과를 다시 고치며, 담당자가 바뀔 때 목적·진행·자료를
재설명하는 수고를 줄이려 합니다. 다음 사용자를 우선 대상으로 잡았습니다.

- 개인: 요약 길이, 코드 설명·주석·구성 방식을 정해 다음 작업에도 쓰고 싶은 사람
- 작은 개발팀: 학생 프로젝트, 사이드 프로젝트처럼 개인 취향과 공동 기준을 함께 다뤄야 하는 팀
- 다음 담당자: 이전 작업의 목적·현재 상태·남은 일·자료·사용 지침을 확인하고 일을 이어갈 사람

필요성과 시간 절감 효과는 제품 가설입니다. 구현 여부와 실제 사용자 효과를 구분해 검증합니다.

| React 비교 | 기존 TypeScript/React 예시를 비교해 작성 선호 추정 | 무료 데모는 준비된 과제의 스타일 비교 |
| 내 선호 보관함 | 요약·코딩 지침 저장·수정·검색·새 작업 재사용 | 보관함에 작업 원문·실행 결과 자동 저장하지 않음 |
| 팀 만들기·참여 | 기준 분류를 골라 팀 생성, 초대 링크로 참여, 마지막에 선호 합치기 | 선호 집계이며 전원 합의 완료를 의미하지 않음 |
| 개인·팀 비교와 조합 | 같은 분류의 팀과 차이 확인, 개인용·팀용 또는 항목별 조합 선택 | 개인 원본과 팀 기준을 유지 |

| 인수인계 | 넘길 일·받은 링크를 파스텔 카드로 구분. 목적·현재 진행·다음 행동을 저장하고 자료 첨부·받을 계정 지정 | 상태·담당자·버전으로 다시 찾기. 팀 초대와 작업 열람 권한은 별도 |
| 참고 파일 첨부 | 파일 원본 저장·열기·다운로드, 이전 기록의 첨부본 확인 | 파일당 5MiB, 현재 10개, 과거 첨부 포함 작업당 20MiB |
| 템플릿과 요청문 점검 | 24개 업무 초안 검색·복사, 요청문의 역할·형식·조건 점검 | 6개만 예시 비교 지원. AI 수정안은 실제 생성 모드 필요 |
| 업무 지침 만들기 | 반복 업무의 입력·규칙·출력 형식 확인, 프로젝트 저장·공유·편집 | 실시간 공동 편집·자동 합의로 설명하지 않음 |

임의 언어를 직접 설정한 코딩 지침은 개인용으로 보관·재사용합니다. React 팀 기준과의 자동 비교·조합은 제공하지 않습니다.
언어별 예시 비교의 선택과 판단 보류도 지침과 함께 보관합니다. 보류한 항목은 당시 직접 설정을 유지하며, 저장본에서 항목별 선택 출처를 확인할 수 있습니다. 이는 네 항목의 예시에서 직접 고른 결과이며 기존 React 선택 이력의 선호 추정·최적화 결과와 구분합니다. 목록에 없는 언어는 직접 설정으로 지침을 만듭니다.
프레임워크 비교 저장본에는 예시 이름과 ID도 남습니다. 이전 기본 문법 비교 저장본은 같은 프레임워크가 설정되어 있어도 프레임워크 예시를 봤다고 바꾸지 않습니다. FastAPI 예시는 Python 3.10+와 설치된 FastAPI, Spring Boot 예시는 Java 17+와 Spring Web이 있는 기존 프로젝트를 전제로 합니다.
코딩의 예시 선택은 고른 값을 확인한 뒤 다음 버튼으로 진행합니다. 새 사용자가 비교를 보류하면 해당 항목을 확인 카드에서 직접 골라야 합니다. 기존에 저장해 직접 재사용한 설정은 유지합니다. 환경을 바꾸면 네 가지 선택을 다시 시작하고, 한 항목만 다시 고를 때는 그 항목의 출처만 직접 설정으로 바뀝니다.

선호 선택 화면 상단에서 **코드 예시로 고르기**(추천)와 **설정만 빠르게 고르기**를 전환합니다. 확인 화면의 **코드 예시를 보며 다시 고르기**로도 비교를 열 수 있습니다. 네 항목의 비교를 마쳐야 새 선택을 반영하며, 취소하면 진입 화면의 기존 선택과 생성한 프롬프트를 유지합니다. 프레임워크 전용 예시인지 언어 기본 문법 예시인지는 코드 위에 항상 표시합니다. FastAPI·Spring Boot 외 새 비교 화면은 현재 선택한 언어의 기본 문법 예시이며 GEPA의 환경별 평가 과제와 구분합니다.
현재 서비스에서는 AWS 화면·조회 API·관련 템플릿을 제외했으며, 과거 실험 자료는 기록으로 보존합니다.

## 처음 사용할 때

1. **시작하기**에서 문서 요약, 코딩 도움, 팀 업무 정리 중 작업을 고릅니다.
2. 개인 지침을 만들고 **내 선호 보관함**에 저장합니다. 저장에는 로그인이 필요합니다.
3. **팀 기준 맞추기**에서 팀을 만들거나 초대를 열고, 비교 후 선호 합치기를 직접 누릅니다.
4. 보관함의 **새 작업에 사용**에서 개인용·팀용을 고르거나 항목별 작업용을 조합합니다.
5. 조합을 다른 이름으로 저장하면 기존 항목과 팀 기준은 유지됩니다.

자세한 화면별 안내는 [사용자 가이드](docs/USER_GUIDE.md)에 있습니다.

## 코딩 프롬프트를 GEPA로 다듬을 때

Python의 FastAPI·Flask·Django, Java/Spring Boot와 JavaScript·TypeScript의 React·Express·Vue·Next.js와 TypeScript/NestJS에서 같은 흐름으로 사용할 수 있습니다.

1. **코딩 도움**에서 위 지원 언어·프레임워크를 고르고 네 가지 답변 방식으로 프롬프트를 만듭니다. JavaScript·TypeScript의 Express·Vue·Next.js도 선택 카드에서 고를 수 있습니다. 보관한 설정도 재사용할 수 있습니다.
2. 로그인한 뒤 결과 아래 **실제 AI로 GEPA 개선 시작**을 누릅니다. ‘이번 작업’ 입력은 보내지 않으며, 준비된 평가 과제와 선택한 지침으로 실제 모델을 호출합니다.
3. **개선 전 / 개선 후** 지침과 AI 답변을 비교합니다. 먼저 기능 정적 검사와 네 가지 답변 방식의 전후 확인 수를 봅니다. **답변 방식의 검사 기준과 과제별 근거**를 펼치면 고른 선호의 기준·설명 글자 수·주석/함수/클래스 수 등을 확인합니다. 별도 확인 과제를 기본으로 보며 후보 선택 과제로 전환할 수 있습니다.
4. **개선 후보를 새로 보관할게요**를 선택하고 새 이름을 입력해 저장합니다. 원본 지침·선택 설정·팀 기준과 기존 보관함 항목은 그대로 둡니다.
5. 보관한 개선본은 **새 작업에 사용**에서 그대로 재사용합니다. 저장 당시 원본·보충 안내·평가 기록도 다시 확인할 수 있습니다.

GEPA는 원본 문장을 지우거나 고른 선호를 바꾸지 않고 뒤에 붙일 보충 안내를 탐색합니다. 더 나은 후보를 찾지 못하면 원본을 유지하고 개선본 저장은 제공하지 않습니다. 작업 결과는 서버 재시작 또는 약 2시간 뒤 사라질 수 있으므로 재사용할 후보는 보관함에 저장하세요.

숫자는 **참고 점수 · 계산 근거 보기** 안에 둡니다. 현재 v2는 기능 검사 65%·자동 형식 검사 35%(설명/출력 2항목)의 과제 평균이며, 주석과 역할 구성은 점수에서 제외합니다. 코드 기본 구조를 확인하지 못한 과제는 0점입니다. 비중이 사용자 만족도를 예측한다고 검증하지 않았습니다. 점수가 같거나 별도 과제에서 낮으면 추가 개선이 확인되지 않았다고 표시합니다. 원본 유지 뒤 같은 점수는 탈락 후보를 재평가한 점수가 아닙니다. 과거 v1의 73.75점(반올림 74점)은 당시 네 형식 지표의 결과로 보존하며 v2와 직접 비교해 향상으로 해석하지 않습니다.

v2는 `### 1.`·`## 2)`·`1단계` 등의 제목 번호도 인식합니다. 주석 예시와 선언·파일 단서를 보여 주되 적절함은 실제 답변을 읽고 **잘 맞아요 / 보완이 필요해요 / 판단 보류**로 직접 고릅니다. GEPA 별도 과제의 내 판단은 후보를 새 항목으로 저장할 때 함께 보관하며 자동 점수나 원본 지침을 바꾸지 않습니다. 기존 기록에 상세 측정값이 없으면 추측하지 않습니다. GEPA는 선택 기능이며, 선호 지침 생성·저장·재사용에는 점수나 GEPA 실행이 필요하지 않습니다.

다른 언어도 생성 결과 아래 **받은 AI 답변 직접 확인 · 모든 언어**를 열어 실제 답변을 붙여 넣고 확인할 수 있습니다. 이 기능은 코드의 동작을 검사하거나 프롬프트를 자동 개선하지 않습니다. 환경별 GEPA·기능 정적 검사는 현재 위의 열세 조합을 제공합니다. React/Express/Vue/Next.js와 TypeScript/NestJS는 Node.js와 기존 프론트 의존성(`npm ci --prefix frontend`)이 필요하며 도구가 없으면 시작 전에 비활성화합니다.

Flask는 `app.get/app.route`·`request.args`·`jsonify`를, Django는 `path`·`require_GET` 함수형 뷰·`request.GET`·`JsonResponse`를 사용하는 과제를 제공합니다. 누락·비정수·음수의 JSON 400 응답과 정상 계산식을 제한된 Python AST로 확인합니다. URL/뷰 분리와 계산 함수, 기존 맥락의 부분 수정을 다루며 평가 서버에 Flask/Django를 설치하거나 답변을 실행하지 않습니다. 실제 모듈 경로·Django 설정·미들웨어·DB·서버 동작은 검증하지 않습니다. Django REST Framework·클래스 기반 뷰의 별도 평가는 아직 없습니다.

새 React 과제는 숫자 props·오류 표시·계산값, Express 과제는 GET 경로·필수 숫자 쿼리·400 오류 응답·반환 계산식을 검사합니다. TypeScript 파서로 소스 구문을 읽고 제한된 AST만 해석하며 생성 코드를 실행하지 않습니다. React 화면 렌더링·Express 서버 실행·TypeScript 타입 검사는 제공하지 않습니다. 표현이 지원 문법을 벗어나면 올바른 코드도 확인하지 못할 수 있습니다.

Vue는 Vue 3의 `<script setup>`과 숫자 `defineProps`, `computed`, `v-if/v-else`, 보간을 사용하는 `.vue` 과제입니다. 누락·비숫자·무한대·음수 입력의 오류 표시와 정상 계산값을 제한된 소스/템플릿 구조로 확인합니다. 변경 과제는 script setup 또는 template 블록을 기존 맥락에 적용하며 필요한 import·계산 함수를 함께 제시할 수 있습니다. Vue 컴파일·실제 렌더링·반응성·타입 검사는 제공하지 않습니다. Options API·외부 컴포넌트·이벤트·기타 미지원 문법은 올바르더라도 자동 확인하지 못할 수 있습니다.

Next.js는 App Router GET API를 평가합니다. 코드 바로 위에 제시한 `app/.../route.ts/js`(또는 `src/app/...`) 경로와 `export GET`, URL/nextUrl 쿼리, NextResponse 또는 Response의 JSON 400 응답과 계산값을 확인합니다. 변경 부분은 export 없는 GET 함수 전체 또는 마지막 return을 기존 맥락에 적용하며 필요한 import·계산 함수도 함께 제시할 수 있습니다. 실제 Next.js 빌드·서버·화면·캐싱·타입·보안과 Pages Router·동적 경로·Server Actions는 별도 검증하지 않습니다.

NestJS는 TypeScript의 GET 컨트롤러·원시 Query 입력·Module 등록을 평가합니다. 서비스를 나눈 답변은 Injectable·providers·생성자 주입·실제 계산 메서드 연결까지 제한된 AST로 확인합니다. 누락·빈 값·공백·비숫자·무한대·음수는 BadRequestException으로 거절해야 합니다. 변경된 quote 메서드나 return만 제시한 답변은 준비된 원래 컨트롤러 맥락에 적용합니다. 실제 Nest 빌드·DI 컨테이너·HTTP·ValidationPipe·DB·보안 검증은 아니며, JavaScript NestJS·커스텀 provider/pipe/guard·상속·비동기 IO는 별도 지원하지 않습니다.

환경별 평가 과제는 개선용 2개, 후보 선택용 2개, 후보 선택이 끝난 뒤 확인하는 별도 과제 2개입니다. FastAPI는 Python AST로 문법·API 선언·일부 계산식을, Spring Boot는 Java 코드 구조·Spring 요청 매핑·음수 입력 거절 패턴·제한된 계산식을 확인합니다. 설명 길이·번호와 변경/전체 출력 형식만 자동 선호 지표로 사용하고, 주석·역할 구성은 사람이 확인합니다. 생성 코드는 실행하거나 컴파일하지 않습니다. 점수는 성공률이나 만족도가 아니며 실제 HTTP 동작·보안·복잡한 개발 업무 품질을 보증하지 않습니다.

공유 알림이나 메시지는 자동 발송하지 않습니다.

## 로컬 실행

Python 3.12와 Node.js가 필요합니다. 기존 프로젝트 의존성을 설치한 환경을 사용합니다.

API 서버를 실행합니다(PowerShell).

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
$env:PPT_LIVE="0"
.\.venv\Scripts\python.exe api_server.py
```

다른 터미널에서 화면을 실행합니다.

```powershell
npm ci --prefix frontend
npm run dev --prefix frontend
```

`http://127.0.0.1:5173/`에서 접속합니다. 기본 `PPT_LIVE=0`은 모델을 호출하지 않는 데모입니다.
GEPA만 실제 호출로 사용하려면 기존 모델 키 설정을 준비한 후 서버 실행 전에 FastAPI는 `$env:PPT_FASTAPI_GEPA_LIVE="1"`, Flask·Django는 `$env:PPT_PYTHON_WEB_GEPA_LIVE="1"`, Spring Boot는 `$env:PPT_SPRING_BOOT_GEPA_LIVE="1"`, JS/TS의 React·Express·Vue·Next.js와 TypeScript/NestJS는 `$env:PPT_WEB_GEPA_LIVE="1"`을 추가합니다. 미지정 시 `PPT_LIVE`를 따릅니다. 기존 `PPT_CODING_MODEL`과 `PPT_REFLECTION_MODEL`을 사용하며, 시작 버튼을 누르면 비용이 발생합니다. 작업당 AI 요청 최대 32회(성찰 최대 4회), 모든 환경을 합쳐 서버 동시 2개·계정 1개와 기존 최적화 하루 한도를 적용합니다. 과제와 성찰 호출 모두 환경별 파일 캐시를 사용합니다. 요청 횟수에는 캐시 조회도 포함될 수 있어 청구 횟수와 같지는 않으며 금액 상한을 뜻하지 않습니다.
AI 수정안·실제 생성·모델 시험의 환경변수는 [기술 실행 안내](README_DETAILS.md)를 따릅니다. API 키를 저장소에 넣지 않습니다.
사용자·보관함·인수인계·파일은 기본적으로 `data/app.db`에 저장하며 이 데이터는 Git에 포함하지 않습니다.
