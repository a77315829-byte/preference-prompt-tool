# 배포되는 앱(app.py)이 실제로 쓰는 것만. Streamlit Community Cloud가
# 이 파일을 읽으므로 여기에 불필요한 걸 넣으면 빌드가 느려지거나 터진다.
# 실험·검증 스크립트를 돌리려면 requirements-dev.txt 를 쓸 것.
#
# 버전을 정확히 고정한 이유: 심사 기간(2주) 동안 앱이 재시작되면 환경이
# 다시 만들어지는데, 버전이 열려 있으면 그 사이 올라온 새 릴리스를 당겨온다.
# gepa는 아직 0.x라 마이너 올림에도 API가 깨질 수 있고, 배포 링크가 죽으면
# 실격이다. 아래 버전은 전부 로컬에서 테스트가 통과한 조합이고, PyPI에
# 존재하며 yanked 아님을 확인했다 (2026-09-15 기준).
#
# 심사가 끝나면 상한을 풀어도 된다. 올릴 때는 requirements-dev.txt로
# 전체 테스트를 돌린 뒤 한 번에 올릴 것.
#
# 배포 동작 메모: 코드만 바꿔 푸시하면 Streamlit Cloud 로그에
# "Updated app!" 만 찍히고 메인 스크립트만 다시 실행된다. 이때 이미
# import 된 모듈(engine/, demos/)은 옛 객체가 메모리에 남을 수 있어서,
# app.py 는 새 코드인데 engine/ 은 옛 코드인 상태가 실제로 발생했다
# (engine/demo_generator.py 가 지워진 ValueError 를 계속 던졌다).
# 이 파일이 바뀌면 "Processing dependencies" 를 거쳐 프로세스가 완전히
# 재시작된다. engine/ 이나 demos/ 를 고친 뒤 배포가 옛 동작을 보이면
# Streamlit Cloud 콘솔에서 Reboot app 을 누르는 것이 정석이다.
